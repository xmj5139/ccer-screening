# CCER 公开信息平台

> **当前版本：v2.3 公开信息平台**（2026-10-14 CEA 阶段B 尾项整改，八模块）。
> 平台只整合**公开资料**，采集与核验**完全自动化**：不含机构内部项目档案、项目录入、尽调与投资审批，
> 也不含任何人工复核 / 人工确认 / 专家签字 / 审核待办 / 审批门禁。
>
> - 启动：`npm start`（默认启动**新版公开平台** `data/ccer_v2.db`，根路径自动跳到 `/v2`）
> - 搜索使用**博查 Web Search**，抓取使用 **Firecrawl v2 MCP**（后台「采集连接」一键填入默认配置）
> - 实施记录：`docs/32-CEA开发实施记录.md`（CEA 本轮）、`docs/24-DSH二轮整改实施记录.md`（二轮）、
>   `docs/20-DSH升级实施记录.md`（首轮）
> - 本文件后半部分描述的是 **v1 投资筛选应用**（`data/ccer.db`）的历史设计，
>   其中「项目档案 / 分级授权 / 人工审核留痕」等要求**已被 v2 取代**，仅作历史参考。

面向投资机构与研究团队的**公开信息整合平台**，覆盖：

- **总览** —— 最新政策、方法学分布、公开项目阶段/地域、交易量价趋势、最新研报与动态
- **政策和方法学** —— 全国 CCER 规则、配套技术文件、部委政策；方法学原文、适用条件、参数与版本变化
- **公开项目** —— 注册登记系统公开项目/减排量公示与登记阶段，原始文件与阶段日期
- **交易信息** —— 官方市场量价、区间汇总、趋势图与 CSV/XLSX 下载，自动标注数据异常
- **减排粗估** —— 低于 8% 煤矿瓦斯简表（年混合气量 + 甲烷浓度两项），确定性程序计算
- **研报与行业动态** —— 公开研报、行业动态、机构观点、企业公告；四态自动核验
- **后台管理** —— 采集连接（搜索 API / 抓取 MCP）、模型配置与真实连接测试、自动核验策略、任务与快照

> **使用边界**：平台输出「公开信息、证据缺口、自动核验状态与规模粗估」，供分析师复核。
> 不替代项目业主、审定与核查机构、注册登记机构的工作；不把公示预计量、核查量、登记量、
> 签发量或可交易量混为一谈；粗估结果不是「预计可签发量」。

## 快速开始

```bash
cd "D:\AI workspace\ccer-screening"

npm start          # 启动新版公开信息平台 → http://127.0.0.1:8787/v2
```

浏览器打开 **http://127.0.0.1:8787**（会自动跳转到 `/v2`）。首次启动会自动初始化
`data/ccer_v2.db`（公开政策/方法学/公开项目/交易日历，**不含内部项目与人工审批记录**）。

**无需 `npm install`** —— 本应用零第三方依赖，只使用 Node 内置模块。

### 环境要求

- Node.js **≥ 22.5.0**（依赖内置 `node:sqlite`；实测 24.14.1）
- 浏览器：Chromium 内核或 Firefox 最新版

```bash
node -v             # 应 ≥ v22.5.0
npm test            # v1 历史测试（政策/规则/计算/权限）
npm run v2:test     # v2 隔离测试（每个文件一个临时库）
```

## 核心设计原则如何落地

| 原则 | 实现 |
|---|---|
| 官方原文优先 | 方法学目录只从发布通知核实编号；来源库每条记录保存 URL、文号、发布/生效日与解析质量 |
| 原始文件可回看 | 证据表保存文件名、页码与原文片段；每条规则结果都能追到证据定位 |
| 规则和公式版本可追溯 | 计算运行绑定「分析基准日 + 方法学版本 + 因子快照」；历史报告不被库更新改写 |
| 证据不足时输出「待核实」 | 三态规则引擎；严格证据字段在来源仅为业主自述时**不会**返回「通过」 |
| 规则负责判断，程序负责数值 | 规则以 JSON 表达式树确定性执行（无 `eval`，不由大模型生成结论）；数值由按编号+版本注册的插件计算 |
| 关键结果由人审核 | 计算运行 / 条件检查 / 报告三类的审核流，全部写入审计日志 |

## ⚠️ 使用前必读：默认不出数

**新装一套系统，任何方法学都无法产出业务测算数字。这是设计如此，不是故障。**

首轮检查（见 [`docs/14-首轮检查整改对照.md`](docs/14-首轮检查整改对照.md)）指出：
原实现「通过测试不能证明与官方方法学一致」，且未完成校验时默认允许出数。
整改后，业务测算必须同时满足四个条件：

1. 该方法的**计算插件已通过领域专家审批**（`calculator_status = 'approved'`）；
2. 插件**不含任何未确认的占位系数**；
3. 所有公式**已回填方法学原文条款页码**；
4. **绑定了同一项目、同一方法学版本、同一分析基准日的条件检查快照**，且该快照无硬障碍。

当前状态：

| 方法学 | 阻断原因 |
|---|---|
| CCER-10-001 | 原文未定义参数 `CEF_CH4`，另有 `TDL_y`、`η_ELEC` 无缺省值 |
| CCER-10-002 / -003 / -004 | 公式链尚未对照官方原文，条款页码未回填 |

**要出数，必须走完这条链路**：
研究员核对编号 → 领域专家回填条款页码 → 领域专家逐项确认参数 →
在管理后台完成审批（仍有占位系数时系统会拒绝批准）→ 业务测算放行。

在此之前，**演示通道**可用于流程演示：由管理员显式开启，运行记录标记为 `demo`、
带水印，**不进入投资筛选报告、不可导出**。

另需注意：**8 项方法学的编号尚待核实**，其 `code_display` 置空、`is_candidate_eligible = 0`，
只可检索不可作候选。系统**不推测编号**——本项目曾因按新闻稿顺序推断，把
`CCER-14-001`/`CCER-14-002` 的对应关系写反，现已更正并加来源驱动测试防止复发。

## CCER 公开信息平台 v2.3（2026-10-14 CEA 阶段B 尾项整改）

> 本节为当前版本。在 v2.2 基础上新增**全国碳排放配额（CEA）独立模块**（八模块），
> 并完成 `docs/35-CEA独立验收尾项.md` 的尾项与「17:00 之后的独立故障注入」整改。
> 实施记录见 `docs/32-CEA开发实施记录.md`；独立验收与云端发布见 `docs/33`、`docs/35`。

### 八个主模块

总览 ｜ 政策和方法学 ｜ 公开项目 ｜ 交易信息 ｜ **CEA市场** ｜ 减排粗估 ｜ 研报与行业动态 ｜ 后台管理

- **CEA市场（新增）**：行情、政策配额、履约日历、企业名录、交易意向、成本情景、研报动态、来源与缺口八个页签。
  - **行情口径分层**：官方综合收盘价（指定权重指数 `close`）与「总成交额 ÷ 总成交量」程序计算均价**分列、互不替代**；
    精确量额只来自 `querySubStat` 的 COMCEA 三行按挂牌(10)/大宗(20)/单向竞价(21)聚合，
    各年度标的行（CEA21…CEA25）**不参与相加**；`dailyov` 的「万吨/亿元」只是舍入展示层，
    单独成块并做跨层核对（差异与容差中文呈现），**不覆盖**精确值。
  - **缺项即未知（本轮故障注入整改）**：三方式缺一、重复行、串日，或某个累计/总量字段未由三方式全部披露时，
    该字段合计保持 `null` 并登记可追溯缺口，绝不用「已见方式之和」或 0 冒充完整总量；
    `queryMarketByDate` 响应没有 COMCEA 综合行时**判失败**，年度标的行情不得冒充全国综合行情。
  - **日历三层证据 + 来源修订**：正式全年休市公告（`official_notice`）> 实际成交 > 查询页机器辅助列表（`holidays_json`）。
    成功且完整的来源快照会同步**当前有效集合**：来源删除的旧日期标为 `superseded`，
    原文、快照与告警留痕保留可追溯，但不再作为当前事实或告警依据；失败 / 不完整结果**绝不清空**原集合，
    只由旧机器列表产生的永久告警自动结清（真实用例：`holidays.json` 101 项 → 100 项，删除 2026-10-14）。
  - **展示纪律**：概览层原始 JSON 只放在可折叠详情里，默认展示中文核对结论；
    不是时间的 UUID / 哈希字段（错位留痕）不当作成交或抓取时间显示；图表、统计与来源钻取分层保留。
  - **成本情景**：P1 取 CEA 行情，P2 只能取 CCER 独立交易行情或手动输入；无可靠 CCER 报价时明确说明缺失，
    **绝不用 CEA 价格顶替**。
- **可复现回归**：官方公开响应的逐字夹具随代码包提供（`test/fixtures/cea/`，无账号与 API 凭据），
  CEA 回归（`test/30`—`test/37`）不再依赖 `data/backups/` 运行期目录；`npm run cea:test` 一次跑完，
  独立故障注入脚本（串日 / 缺方式 / 重复行 / 字段未披露 / 无 COMCEA）在验收证据目录
  `data/backups/cea-20261014/independent-fault-check.mjs`，6 项全部通过。

### CEA 采集与调度

- **采集配置**（后台「CEA 配额市场 → 采集配置」）：`enabled`、`auto_verify`、`after_close_enabled`、
  `after_close_time`（默认 16:30 北京时间）、批次预算、每日抓取上限、每轮条数、搜索服务与抓取连接的**指定**服务
  （指定服务不存在/未启用时明确失败，不静默切换）。
- **收盘后轻量增量**：与既有 06:30 全平台更新**分开排程**，只做当日行情 + 交易意向等轻量增量，
  共享批次 deadline；后台改开关/时间后立即重排并显示下一次运行时间。
- **开关**：`CCER_DAILY_SYNC=0` 一并停用（本地开发默认不误触发）；`CCER_CEA_AFTER_CLOSE=0` 单独停用 CEA 收盘后增量，
  06:30 全平台更新不受影响。

## CCER 公开信息平台 v2.2（2026-09-29 二轮整改）

> 本节为当前版本。产品已按 `docs/19-公开信息整合平台升级任务.md` 重构为**公开信息整合平台**：
> 只整合公开资料，**不再包含机构内部项目档案**，**不再包含任何人工复核 / 人工确认 / 专家签字 /
> 审核待办 / 审批门禁**。采集与核验完全自动化。
> 首轮实施记录 `docs/20-DSH升级实施记录.md`；二轮整改（Codex 验收 17 项 + 博查/Firecrawl 接入）
> 见 `docs/24-DSH二轮整改实施记录.md`。

### 七个主模块

总览 ｜ 政策和方法学 ｜ 公开项目 ｜ 交易信息 ｜ 减排粗估 ｜ 研报与行业动态 ｜ 后台管理

- **总览**：最新政策、方法学状态分布、公开项目阶段/类型/地域分布、交易量价趋势、最新研报与动态、
  数据更新时间。**演示条目与来源归档一律从业务统计排除**（如 294 条公开项目中 3 条为演示，
  业务口径为 291）；公示量不当登记量；阶段不重复相加成项目总数。
- **政策和方法学**：正式 / 征求意见 / 修订 / 废止分开；方法学含原文、适用范围、关键条件、参数、
  自动解读与版本变化；AI 解读标「自动生成」；缺正文时不声称已读原文。
- **公开项目**：主来源 [注册登记系统项目公示栏目](https://ccer.cets.org.cn/projectPublicity/projectPublicityList)；
  覆盖公示、登记等可查阶段；保留业主、方法学、地域、原始文件、阶段日期与历史变化；
  附件不能下载时显示真实状态与官方链接；演示条目默认隐藏（可显式 `include_demo=true` 查看留痕）。
- **交易信息**：官方市场量价、区间汇总、趋势图、CSV/XLSX 下载；量价/累计差分由系统**自动核对并标注**，
  不产生人工核对任务；无项目级对应证据时不编造项目成交量。
- **减排粗估**：**低于 8% 煤矿瓦斯简表置顶**，年混合气量（可选 m³/年 或 万 m³/年，服务端严格 ×10000）、
  平均甲烷浓度两项为主，处理比例与销毁效率为可选高级参数。**无需项目档案、无需签字审批**；
  结果为规模粗估，不是可签发量；数值由确定性程序按方法学因子计算，**不由大模型生成公式**。
- **研报与行业动态**：公开研报、行业动态、机构观点、企业公告；可按时间、类型、机构、方法学/行业、
  关键词过滤；显示**发布日期（来源未声明时显示「未披露」，绝不用采集时间代替）**、采集时间、
  来源摘要与自动摘要（分开存放）、来源 URL、核验状态；观点、预测与已发生事实分开。
- **后台管理**：采集连接（搜索 API / 抓取 MCP）、模型配置与**真实连接测试**、自动核验策略、
  每日任务/重试/错误日志、用户管理与操作日志。**没有**审核任务、复核角色或专家审批。

### 搜索与抓取连接（用户指定：博查 + Firecrawl）

| 用途 | 默认预设 | 参数 | 凭据（只存服务端） |
|---|---|---|---|
| 内容发现 | **博查 Web Search** | `POST https://api.bocha.cn/v1/web-search`，白名单 `api.bocha.cn`；`query/summary/count/freshness` | 环境变量 `BOCHA_API_KEY`（或后台加密保存） |
| 正文抓取 | **Firecrawl v2 MCP** | `https://mcp.firecrawl.dev/v2/mcp`，只读工具 `firecrawl_scrape`，读取 `tools/list` 的 inputSchema 映射 `url/formats` | 环境变量 `FIRECRAWL_API_KEY` |

- 后台「采集连接」提供 **「填入博查默认配置」「填入 Firecrawl MCP 默认配置」** 按钮：
  只填入公开参数（地址/路径/工具/白名单/凭据引用名），**不读取任何 DSH 凭据库，也不填任何密钥**。
- 博查：`HTTP 200 但 code≠200` 也算失败（鉴权/余额不足/限流/空结果/超时分别显示），
  错误信息保留可公开的 `log_id`；返回的 `summary/snippet` **只是摘要，不是全文**；
  `dateLastCrawled`（抓取时间）**不会**被当作发布日期。
- Firecrawl MCP：测试先做真实 `initialize + tools/list` 并确认所选工具存在，再区分
  **「连接及工具可用」** 与 **「抓取授权/实际调用成功」**；官方固定地址允许显式 keyless 限额试用，
  一旦被官方拒绝（`Anonymous keyless access is unavailable`）即如实显示需要 API Key，**不反复无密钥重试、不伪造成功**。
  其它远端 MCP 未配置凭据一律拒绝调用；不在只读白名单内的工具一律拒绝。
- 未配置凭据时如实显示「未配置/不可调用」，公开原始信息仍可正常浏览。

### 自动采集与核验

链路：来源发现 → 抓取正文/文件 → 去重与版本保存 → 结构化抽取 → 规则一致性检查 →
模型证据核验 → 自动发布与状态标记 → 每日更新。

- **来源首页/栏目页只作来源发现与快照归档**（`record_kind=source_homepage/source_index`），
  不再被写成「今天发布的研报」；正文条目只取来源页面声明的发布日期。
- 核验结果只有四种：**自动核验通过 / 证据不足 / 来源冲突 / 暂未自动核验**；
  政策、方法学、公开项目与研报动态**共用同一套四态与同一缓存键**。
- 核验缓存键包含「输入 + 策略 + 模型 + 证据版本」；**`unavailable` 永不缓存**，
  因此配置好模型后同一内容会自动重试，不会永远命中「未配置模型」的旧结论。
- 模型引文必须能在实际证据中定位；无法定位的引文会被过滤并把结论降级，
  **不给不存在的原文片段盖「已核验」标记**。
- 模型不可用时公开原始记录照常展示，不阻断全站，也不需要人工补位。

### 启动与运维

```powershell
npm start                              # 新版公开平台（默认 data/ccer_v2.db）
npm start -- --port=8899               # 指定端口
npm run v2:seed                        # 初始化/补齐种子数据（幂等）
npm run v2:daily                       # 每日更新：官方数据 + 研报动态 + 统一自动核验
npm run v2:calibrate                   # 立即复查差异并执行大模型证据核对
npm run v2:real-collect                # 真实联网采集验证（--no-write 为只读探测）
npm run v2:real-collect -- --no-write  # 只读：不写业务数据、不建连接、不写游标
npm run v2:ingest-docs21               # docs/21 真实文章入库与日期来源验证
npm run v2:db-verify                   # 用现有 v2 库验收接口口径（只读；加 --run-verify 可跑统一核验）
npm run v2:test                        # v2 隔离测试（每个文件一个临时库）
npm run cea:test                       # CEA 专项回归（test/30—test/37，夹具随代码包）
npm run cea:status                     # CEA 采集与数据状态（只读）
npm run cea:collect                    # CEA 公开 JSON 采集（--target=json 只跑 JSON 通道）
npm run cea:independent                # 独立核对链（解析/JSON/情景 + 串日、缺方式、重复行、无 COMCEA 故障注入）
npm run backup                         # 数据库备份
```

- v2 一律使用**独立数据库** `data/ccer_v2.db`；`CCER_DB_PATH` 指向在用库 `data/ccer.db` 时
  写操作会被拒绝（409），v2 迁移也不会执行（需显式 `CCER_ENABLE_V2=1`）。
- **每日任务**由 `npm run v2:daily` 或系统计划任务触发；每个数据集都会写
  「最近成功时间」与「失败原因」（后台「任务与快照」页签可见，含「从未成功」占位）。
- **差异每日校准**：每日任务在采集与确定性规则复查之后，对未结清差异调用后台配置的模型；
  结论和可定位的来源引文写入 `reconciliation_ai_review`。缺少官方正文、模型失败或引文无法定位
  时保持「证据不足/模型不可用」，不凭模型推断覆盖官方数值。规则不再检出的旧差异自动归档并留痕。
  服务内置北京时间 06:30 的每日调度（`CCER_DAILY_SYNC=1`）；本地如另有采集实例，
  可用 `CCER_DAILY_CALIBRATE_ONLY=1` 让第二实例只做规则与模型校准，时间由
  `CCER_DAILY_SYNC_HOUR` / `CCER_DAILY_SYNC_MINUTE` 指定。
- **进程守护 / 备份**：`scripts/backup.mjs` 提供库备份；云端部署请用 systemd / PM2 / 任务计划程序
  守护 `v2:start`，并为 `v2:daily` 配置定时执行与失败告警。详细的备份与恢复演练步骤见
  `docs/13-部署与运维说明.md`。
- **凭据**：只存服务端。优先用环境变量（后台填「凭据引用名」，如 `BOCHA_API_KEY`、
  `FIRECRAWL_API_KEY`、`DEEPSEEK_API_KEY`）；或在后台「模型配置 → 初始化本机主密钥」后
  由页面提交（AES-256-GCM 加密入库）。
  - 主密钥文件位于**当前数据库目录**下（`<数据库目录>/keys/master.key`，测试用临时库因此
    不会污染真实密钥），也可用 `CCER_KEY_DIR` 覆盖；
  - POSIX 权限 0600 并校验；Windows 用 `icacls` 关闭继承、只授予当前用户并**回读 ACL 校验**；
    无法设置或校验时**拒绝初始化并删除刚生成的文件**（不留权限过宽的私钥），
    此时请改用环境变量 `CCER_SECRET_KEY`；
  - 未初始化主密钥时提交明文密钥会被**拒绝**并给出可操作提示；
  - **任何接口、页面、日志与导出都不会出现凭据明文**，只返回「是否已配置」与来源。
- **模型细节**：对 `api.deepseek.com` 会在核验与连接测试中显式设置
  `thinking:{type:'disabled'}`（DeepSeek 默认开启 thinking，短请求可能只返回 reasoning），
  该参数**不会**被强加给其它供应商。
- **联网抓取限制**：出站地址受域名白名单约束，回环与内网地址默认拒绝
  （`CCER_ALLOW_LOOPBACK_OUTBOUND=1` 仅用于本地联调与自动化测试）。
  直连 HTTP 抓取不执行 JS，动态渲染页面取不到正文时会如实返回失败；
  抓到的正文过短（<60 字符，疑似跳转/错误页）不计入文章统计。

### 关于旧版功能

- `npm start` 默认进入新版公开平台；根路径 `/` 在 v2 启用时 **302 跳转 `/v2`**，
  旧版静态工作台不再对外提供。
- 旧版私有 / 审批 API（`/api/projects*`、`/api/reviews*`、`/api/calculations*`、`/api/reports*`、
  `/api/dashboard`、旧导入与管理入口）在 v2 启用时一律返回 **410**，并给出替代接口，不是 404 或 500。
- v2 侧旧业务入口（内部项目、项目人工确认、政策确认、行情人工核对、审核任务、旧测算链路、
  旧 AI 复核）同样返回 410；`/api/v2/measure/readiness`、`/api/v2/measure/targets`
  等依赖内部档案与领域签字的入口也已停用。
- 旧数据表（`review_task`、`policy_change`、`internal_project*` 等）**保留为历史备份，未删除、
  未清空**，只是不再写入；历史记录中遗留的人工流程措辞在**展示层**改写为自动运行口径
  （数据库原文不改写）。
- `docs/01`—`docs/14` 等早期文档描述的是**旧版内部项目与人工门禁需求**，与现行版本冲突处以
  `docs/19`（授权需求）、`docs/22`（二轮整改项）、`docs/23`（博查/Firecrawl 要求）与
  `docs/24`（二轮实施记录）为准。
