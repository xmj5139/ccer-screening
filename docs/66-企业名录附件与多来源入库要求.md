## 附件格式

- 官方北京、内蒙古、新疆名单实际是 DOCX。为企业采集路径增加有边界的 DOCX 解包提取，可沿用已存在的 spawnSync：Python 标准库 zipfile + ElementTree，仅读取 word/document.xml，将段落/表格转为转义 HTML 供 parseEntityRows。限制原件大小、XML 解压大小、输出长度及运行时间，拒绝缺失部件/无效ZIP/解压炸弹，禁止宏或执行附件代码。不添加 npm 依赖，不改全局 PDF/OCR 服务。
- 山西官方 PDF 链接返回 multipart/form-data 外壳而非裸 PDF。真实样本 `data/backups/cea-directory-20261020/raw/shanxi_a1.html`（原始HTTP字节）和 `shanxi_a1.pdf`（独立提取后的有效PDF）。仅支持有明确边界的单个完整PDF附件；异常、多附件、超限要失败。原始 HTTP content hash 不变，解析使用解码后的 payload，原件与载荷哈希不要混淆。
- 在源元数据 kind 或 URL 明确 DOCX 时支持识别；不要拿任意ZIP当文档。Python 本机 python，Linux python3，沿用现有探测方式。每批4个和deadline继续生效。

## 同一企业多个行业与来源

真实名单中1481行按信用代码+2026年度去重成1451主体；30主体同时出现在不同产业名单。现有 upsertCeaEntity 会覆盖前一次行业和来源，必须修复。

- 用增量建表保存 entity_id + source_code + sector 的成员关系/出处，保留 source_url、source_hash、snapshot_id、note、更新时间。已有记录按原字段回填，不能丢福建84条。
- upsertCeaEntity 对有 source_code 的有效输入保留本来源行业记录，其他来源不删除；聚合主体 sector 按明确分隔符合并标签。没有来源的既有编辑路径仍兼容。历史变化可追溯，同源重采幂等，不以一次获取失败删除企业或标退出。
- listCeaEntities 行业筛选应命中成员关系，不只 sector 完全相等；返回 source_memberships 让调用方能看到所有出处。原 source_url 保持兼容。企业数量仍按信用代码+年度去重；禁止按行业关系行数计算企业数。
- unchanged hash 缓存计数要按本来源成员关系去重企业，不能只看主体行最后一个 source_code，否则同主体多来源会导致缓存永远失效。
- CSV 至少 notes 包含多出处链接；前端无需改版，只在已有企业名录出处处允许展开/显示多个链接，避免明明多出处却只显示最后来源。不要引入与本任务无关页面重构。
- 本批加福建后1535主体，既有 exportCeaDataset('entities') 只取limit1000会静默丢后535家。企业导出需按既有分页遍历完整筛选结果（JSON与CSV统一），不要取消分页API上限；测试用>1000行临时数据证明导出完整。
