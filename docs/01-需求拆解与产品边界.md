# 需求拆解与产品边界

> 本文档把《CCER 投资筛选 AI 应用：产品与技术设计 v1.0》拆解为可开发、可验收的需求条目，
> 并逐条标注实现位置与验收方式。「产品边界」部分是**不可协商的约束**，任何功能扩展都不得突破。

---

## 一、产品定位

本应用是**投资筛选与研究辅助工具**，输出「候选方法学、条件判断、证据缺口、初算结果、投资关注点」，供分析师复核。

**不做的事（刚性边界）**：

| 编号 | 边界 | 实现措施 |
|---|---|---|
| B-01 | 不替代项目业主、审定与核查机构、注册登记机构的工作 | 全站免责声明（`web/index.html` 顶栏 + 每份报告 `disclaimer` 字段） |
| B-02 | 不把预计减排量、核查量、登记量、签发量、可交易量混为一谈 | 三个数值分列存储（`project.owner_announced_estimate` / `verified_amount` / `registered_amount`）；六个注册登记状态各占独立布尔列；报告按状态分述 |
| B-03 | 不把「已公示」「已登记」「已核查」「减排量登记」合并成一个状态 | `registry_project_public` / `registry_validated` / `registry_project_registered` / `registry_reduction_public` / `registry_verified` / `registry_reduction_registered` 六个独立列；`registryStageLabel()` 逐个展示 |
| B-04 | 不得把网页搜索摘要当作规则源 | 方法学目录与规则卡的唯一权威来源是 `src/data/catalog.mjs` 中标注了官方 URL 的发布通知；未核实编号的条目 `is_candidate_eligible = 0` |
| B-05 | 不得用 AI 自行生成未经核实的系数或公式 | 全部系数写入 `factor_version` 表并带 `value_status`（`verified`/`placeholder`）与 `source_ref`；占位系数在 UI、报告、计算输出中逐项列出 |
| B-06 | 任何方法学尚未完成公式校验时，界面必须提示「暂不支持自动测算」 | `methodology_version.calculator_status`；严格模式下含占位系数即拒绝出数（`calc-svc.mjs` `gateCheck`） |
| B-07 | 不把情景估算称为「预计可签发量」 | 计算输出 `disclaimer` 与 `unit_note`；自动化测试 `04-catalog-and-governance` 检查禁用措辞只以否定形式出现 |
| B-08 | 碳价只是情景参数，不能把估算量乘现价当作确定现金流 | 碳收益单列于 `estimate.carbon_revenue`，并带 `note: 不与估算量相乘当作确定现金流` |
| B-09 | 首期只覆盖全国 CCER | 目录只收录全国 CCER 方法学；全国碳排放权配额、地方碳普惠、国际自愿减排机制不进入匹配与测算规则（冲突标记规则 X-01~X-03 仅作提示） |

## 二、核心原则的落地映射

设计文档第 1 节列出六条核心原则，逐条对应到实现：

| 原则 | 实现位置 | 验证 | 测试用例 |
|---|---|---|---|
| 官方原文优先 | `source_document` 表保存 URL / 发布机关 / 文号 / 发布日 / 生效日 / 抓取时间 / 解析质量；`methodology_version.official_url` 与 `source_id` | 每条来源字段完整性检查 | `04-catalog-and-governance`「来源库每条记录都有…」 |
| 原始文件可回看 | `project_evidence` 保存文件名 / 页码 / 原文片段；规则结果携带 `evidence` 对象 | 报告的「证据定位」列 | 验收用例 6 |
| 规则和公式版本可追溯 | `rule.methodology_version_id` + `rule_version`；`calculation_run.factor_snapshot_json`；`calculation_run.analysis_base_date` | `compareRuns` 差异对比 | 验收用例 4 |
| 证据不足时输出「待核实」 | `FactStore.usable()` + `evidence_policy = 'strict'` | 三态判断 | 验收用例 2；`01-rule-engine` |
| AI 负责抽取检索解释，确定性规则负责判断，已校验程序负责数值 | 规则引擎执行 JSON 表达式树（无 `eval`）；计算由按「方法学编号+版本」注册的插件执行 | 规则引擎 11 项单元测试 + 计算独立复算 | `01-rule-engine`、`03-calculation` |
| 关键结果由人审核 | `review_decision` 表 + `calculation_run.review_status` / `eligibility_run.review_status` / `report.status` | 审核流与审计日志 | 验收用例 6 |

## 三、功能需求拆解

### 3.1 信息雷达（FR-01）

| 需求 | 实现 | 状态 |
|---|---|---|
| 监测生态环境部、全国 CCER 注册登记系统及信息平台等官方来源 | `radar-svc.syncSources()` 对 `source_document` 中每条 URL 发起受控抓取（15 s 超时，走机构受控出口） | ✅ |
| 按领域、地区、项目类型订阅 | `subscription` 表 + `alertsForSubscriptions()` 过滤 | ✅ |
| 提供新增、修订、废止、征求意见提醒 | `alert.kind` ∈ {new, revised, repealed, draft_consultation, fetch_failed, structure_changed, withdrawn, catalog_gap} | ✅ |
| 显示来源链接、发布机关、发布日期、生效日期、抓取时间、文件状态、变更摘要 | `source_document` + `source_change.diff_summary` | ✅ |
| 抓取后去重与差异比对 | SHA-256 内容哈希比对；同时扫描方法学编号新模式 | ✅ |
| 抓取失败、来源结构变化、公告撤回告警 | `source_change.change_kind` + `alert` | ✅ |
| 研究员确认后才发布到判断引擎 | 抓取只写 `source_change` 与 `alert`，**不触碰** `methodology_version` | ✅（测试「抓取结果不会自动修改方法学状态」） |

### 3.2 方法学库（FR-02）

| 需求 | 实现 | 状态 |
|---|---|---|
| 按名称、编号、领域、版本、状态检索 | `GET /api/methodologies?keyword=&domain=&status=` | ✅ |
| 查看适用条件、排除条件、基准线、额外性、监测参数、公式及附件 | 规则卡（`rule` 表）+ `formula` 表 + `factor_version` 表 + 方法学详情页 | ✅ |
| 正式发布与征求意见分栏 | `GET /api/methodologies` 返回 `formal[]` 与 `draft[]` 两组 | ✅ |
| 原文页码 / 条款 | `rule.clause_ref`（当前为占位，见 EXP-101 系列） | ⚠️ 待专家回填 |
| 版本差异 | `methodology_version.supersedes_id` + `change_log` | ✅（结构就绪，内容待专家填写） |
| 同一方法学保留所有版本 | 表结构天然支持；`UNIQUE(methodology_id, version)` | ✅ |

### 3.4 方法学匹配（FR-04）

| 需求 | 实现 | 状态 |
|---|---|---|
| 候选清单、匹配/排除理由、需补充字段 | `runMatch()` 返回 `candidates` / `observations` / `excluded` / `gap_list` / `unknown_fields` | ✅ |
| 只能把正式有效版本列为可申报候选 | 三重过滤：`document_status === 'formal'` && `is_candidate_eligible` && `rulecard_status === 'approved'` | ✅ |

### 3.5 条件检查（FR-05）

| 需求 | 实现 | 状态 |
|---|---|---|
| 通用门槛 + 方法学专属条件 + 资料完备性 | 三层规则：`layer` = common / specific / conflict | ✅ |
| 结果为通过 / 不通过 / 待核实 / 不适用 | 三态引擎 + 四态结论；「不适用」通过规则的 `applies_to` 字段作用域体现 | ✅ |
| 每项规则、证据、判断时间和复核人 | 规则结果携带 `rule_id` / `condition_text` / `expression_text` / `evidence` / `clause_ref` / `judged_at` / `rule_version`；复核人来自 `review_decision` | ✅ |
| 筛选结论为四态枚举，不输出笼统的「符合申报」 | `conclude()` 只返回四个枚举值；测试断言不出现「符合申报」 | ✅ |

### 3.6 减排量初算（FR-06）

| 需求 | 实现 | 状态 |
|---|---|---|
| 由按方法学编号与版本注册的插件计算，不允许通用大模型直接生成最终数字 | `src/methodologies/*.mjs` 的 `plugin.compute()`；通用链只用于组织计算顺序 | ✅ |
| 生成年度、分期情景；支持保守 / 基准 / 乐观三情景 | `plugin.scenarios` + `allScenarios: true` | ✅ |
| 方法学版本、公式、参数单位、数据期间、因子来源、计算日志、敏感性 | `result_json.steps[]`（含 `formula` / `substitution` / `unit` / `factor_refs` / `clause_ref`）+ `factor_snapshot_json` + `sensitivity[]` | ✅ |
| 缺失关键监测数据禁止猜值 | `validate()` 返回 `errors` → 拒绝出数（HTTP 422） | ✅（验收用例 5） |
| 允许明确标注为「假设」的情景输入，输出只称「情景估算」 | `resolveInputs()` 中用户覆盖一律标注 `模型假设`；输出 `disclaimer` | ✅ |

## 四、非功能需求

| 编号 | 需求 | 实现 |
|---|---|---|
| NFR-01 | 部署在机构内网或私有服务器 | `HOST` 默认 `127.0.0.1`；非回环来源返回 403，除非显式设置 `CCER_ALLOW_REMOTE=1` |
| NFR-02 | 外部模型调用和官方站点采集须走受控出口，并由机构确认数据可否离开内网 | `syncSources()` 统一出口并记录 `source_change`；系统**不调用任何外部大模型 API**（全部判断与计算在本地确定性执行） |
| NFR-03 | 项目资料按机构、团队、项目分级授权 | `project.team_id` + `project.confidentiality` + `canViewProject()` |
| NFR-04 | 敏感附件加密 | ⚠️ 未实现：当前仅做访问控制与审计，未做静态加密。见「未完成项」 |
| NFR-05 | 保留访问与导出记录 | `audit_log` 覆盖 `report.export` / `report.export_denied` / `evidence.create` / `fact.create|update` |
| NFR-06 | API 异步处理大文件、支持批量项目导入与重跑 | 请求体上限 32 MB；批量导入与重跑为**接口层已预留、未实现命令**。见「未完成项」 |
| NFR-07 | 零第三方依赖、便于内网离线部署 | `package.json` 的 `dependencies` 与 `devDependencies` 均为空；仅使用 Node 内置模块 |
| NFR-08 | 具体技术栈由制作方根据既有环境确定 | 选型 Node.js ≥ 22.5（使用内置 `node:sqlite`）+ SQLite + 原生前端；无构建步骤 |

## 五、验收标准对照

设计文档第 10 节的 A/B/C/D 四阶段验收标准，逐条对应：

| 阶段 | 验收标准 | 实现证据 |
|---|---|---|
| A 基础库 | 官方目录可核对 | `docs/05-方法学清单.md`（从数据生成）+ `GET /api/methodologies` |
| A | 新增/修订/草案不混淆 | `document_status` 分列；`01`/`04` 测试断言草案与正式版并存 |
| A | 每条记录可打开原件 | `source_document.url` + `methodology_version.official_url` |
| B 项目初筛 | 每项判断可追到原文条款和项目证据 | 规则结果携带 `clause_ref` + `evidence`；验收用例 6 |
| B | 缺数据返回待核实 | 三态引擎；验收用例 2 |
| B | 已排除项说明原因 | `excluded[].reason_code` + `reason`；验收用例 1 |
| C 计算 | 每个上线插件通过独立手算/表格样例校验 | `plugin.selfCheckSamples` 6 个样例 + `03-calculation` 中独立算术复算 |
| C | 单位与边界校验通过 | `validateNumeric()` + `detectPeriodOverlap()`；验收用例 5 |
| C | 错误输入拒绝给数 | HTTP 422 + `persistRejected()`；验收用例 5 |
| D 投资工作台 | 可从一份项目资料生成可编辑报告 | `POST /api/projects/{id}/report` → Markdown / HTML / Word(.doc) / Excel(.xls) / CSV 五种导出 |
| D | 分析师修改后保留审计轨迹 | 报告按 `revision` 并存 + `audit_log` |

关键验收用例 1–7 的函数级自动化测试见 `test/02-acceptance.test.mjs`（9 项测试全部通过）。
