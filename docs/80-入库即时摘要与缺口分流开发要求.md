# 入库即时摘要与缺口分流开发要求

2026-10-21，用户要求按现状先本地修改。由 DSH 开发、Codex 独立验收；不部署云端、不推送 GitHub、不修改既有数据/账号/密钥。沿用专业清爽绿色前端。

## 已核实背景与边界

- 当前文章通过 content-svc.upsertContent 入库；每日链路末尾 runDailyGovernance 在七类型之间有界轮转，并非新文章入库即生成摘要。
- 云端审计的合格文章 311 条，其中 22 条无 entity_summary；已存摘要可能过期，不把 status=ok 等同当前有效。阶段表仅已初始化部分对象，不能当全库统计。
- 既有工具：博查、Firecrawl、DeepSeek、百度 OCR，云端 pdftoppm 已安装；本轮不新增付费账号，不安装大模型/重型解析器，不读取密钥。
- 错误候选 https://overview.cneeex.com/c/2025-02-19/488525.shtml 实际是交易所“基本信息”页，不是 CEA 日报；另一条 parse failure 不能因同为失败就批量结清。
- 用户已指定异常信用代码可留空、保留企业名称；应显示字段级非阻塞提示，不将其变成整条名录缺失。原始异常值保留历史，不能猜测补齐。

## A. 新文章入库触发异步摘要（必须真实接通）

1. 持久 SQLite 队列，以实体类型/ID + 实际输入签名、提示词与模型键去重。upsertContent 新增或实质更新后立即入队，不在同步写路径等待外部模型。不为演示、转载副本、source_archive、failed_fetch、只有标题的记录生成伪全文摘要。其他入口：搜索采集、种子来源、历史补采、正文修复均经该写入口覆盖。
2. 独立轻量 worker 服务启动自动恢复并周期排空队列；进程内单并发，跨进程需有 SQLite 租约/领取机制。支持显式环境禁用，独立于每日06:30调度。setTimeout/unref，防重入、关停清理，无 GET 调模型。
3. 新内容优先，同时保证旧待办不会永久饥饿。默认短周期（例如10~15秒），单批最多3条/45秒，配置有硬上限。复用 runSummaryBatchExclusive 及既有模型，不与每日/手动摘要并发。共享 collection 或独立租约要说明锁顺序，不能死锁；忙时延后，不消耗真实失败次数。
4. 失败指数退避、尝试上限、每日兜底补入漏队项；无配置明确 blocked，不能假成功。运行中输入变化时，旧结果不得把新签名任务标完成。任务中断后可回收过期运行态，重启续跑。相同正文重复抓取不重复付费。
5. 生成文本写既有 entity_summary，仍用实际输入哈希判断有效。完整/部分正文范围如实展示；只有来源摘要可作“摘要的概括”，不可称阅读全文；只有标题不调用。优先取得正文，摘要成功不表示核验成功。
6. 内容列表/详情仍只读缓存。后台增加队列开关、状态/统计、失败原因与有界重试/补入按钮（管理员鉴权）；普通用户只能看到公开摘要/生成中/缺少正文等真实空态。

## B. 缺口分类与受控动作

1. 将既有 data_gap + processing_stage 按下载/访问失败、动态页/正文不全、PDF已下载未解析、OCR失败、摘要待办/失败、核验需第二来源、原始事实冲突、来源未公开、非目标页、可选字段异常分类。输出类别、依据、自动动作、可重试性/是否阻塞，不凭模型猜关闭。
2. 原有 content.repairIncompleteContent、policy/methodology/CEA/archive/pdf/OCR 等适配器和 governance.retryStage 尽量复用；只对当前明确支持的单条能力提供可执行动作，缺失能力明确 unsupported，不把“重试”按钮做成空动作。每次处理有条数/时间/次数约束、SSRF/域名/角色限制不放宽。解析失败不能用抓取成功结清，摘要失败不能靠关闭缺口处理。
3. CEA 日报在解析行情前先判断正文的文章标题/主内容是否明确属于企业基本信息、招聘、导航等非目标页；不要因页脚或导航出现“基本信息”而误伤真正日报。明确非目标页记录带来源/快照/规则的排除记录，不建行情行；既有同URL parse缺口可留痕标明非目标并停止同任务反复重试。未知/空/访问失败仍保留缺口，不能统统视为非目标。
4. 缺口台账说明自动维护：已成功修复的对象以同一来源/日期/实体的证据结清，旧说明可更新但保留审计。交易日期真的缺失/累计差异继续保留。信用代码异常字段非阻塞展示，企业名称仍计入名录；不改原始值、不捏造正式代码。
5. 后台治理页/维护页增加分类与动作说明，展示实际执行结果和失败原因。没有人工审批门槛，不重做整个 UI。
