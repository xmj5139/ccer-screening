日期：2026-10-29。依据：`docs/86-公开信息智能化三阶段开发设计.md` 第三阶段；承接 `docs/87`、`docs/88`。本文只记录**本轮实际写入的代码、实际跑过的隔离测试与仍然存在的限制**。本轮未部署、未推 Git、未读取 `data` 下数据库、未读取密钥/环境变量值、未调用真实付费 API；真实模型与云端验收由主 Codex 独立执行。

## 1. 交付结论

1. **索引新鲜度与分批修正**：新增 `search_index_dirty` 队列与源表触发器（覆盖 `admin_revision`）。查询只做有界消费（默认最多 25 条），仍有剩余 dirty 时回退既有检索并返回 `mode=legacy_fallback / fallback_reason=index_dirty`，不把旧 payload 当最新文本。每日批次使用每类型旋转游标；末批清理按整个合法来源 ID 集合，不再用本批 `seen` 删除前批索引。
2. **语义扩展 + FTS 混合检索**：新增显式 `POST /api/v2/search/semantic`。单次模型调用、严格 JSON、最多 4 个扩展词；原查询始终保留，类型/地区/年度/来源/日期筛选原样传递；精确 CCER/方法学/登记编号不调用模型、不消耗模型配额，直接关键词检索。模型不可用/超时/输出非法返回原检索，标记 `fallback`；正常扩展标记 `semantic_expansion`；精确编号标记 `keyword`。限频、限长、每日配额与留痕均落库。
3. **CEA 企业档案**：新增 `GET /api/v2/cea/entities/:id`，返回规范标识、名称/别名、跨年度名录行、按年度/来源的行业成员关系、公开来源、历史修订与正文提及。无信用代码时只按“名称 + 省份 + 城市”聚合，同名跨地区不合并；异常信用代码标准字段留空、原始值保留、企业名称照常入名录；多行业、多年度逐条保留；不提供/不推算企业实际排放量。
4. **第三方行情候选**：新增独立候选表与后台导入/差异/导出。严格来源、日期、单位、finite/positive、字节/行数/字段上限；保留 `stale` 第三方标志；逐行输出 `missing/conflict/match/unsupported`。CEA 候选核对 `cea_trade_daily`，CCER 候选核对 `trade_daily` 并按日汇总不同交易方式；未来交易日、晚于来源 as-of、非 CEA/CCER 标的为 `unsupported`。候选与差异报告绝不改写两张官方行情表；CSV 导出复用公式注入前缀防护；viewer 无诊断/导入权限。
5. **UI 入口**：统一检索页新增“智能扩展检索”显式按钮与模式/扩展词提示；CEA 名录企业名可进入档案，地图省详情列出已收录企业并可进入档案，管理员可在档案页补充带来源别名；后台「CEA 配额市场」新增候选导入、差异表与导出；「我的关注」地区改为平台省份下拉，不再手工拼写省名。

## 3. Schema 与迁移

`db.mjs` 在第二阶段 schema 之后执行 `schema-intelligence3.sql`，重复执行安全：

- `search_index_dirty(type, entity_id, reason, queued_at)`：源表 insert/update/delete 与 `admin_revision` insert/update/delete 均入队；
- 迁移时给既有公开记录补一次 dirty（`search_dirty_seeded_v3` 标记），之后完全由触发器维护；
- `cea_entity_alias`：企业别名/曾用名，带来源代码、链接、证据说明与操作者；
- `search_expansion_quota` / `search_expansion_log`：按 CST 分钟/日窗口限额，留痕查询词、扩展词、模式、模型与延迟，不保存密钥；
- `market_candidate_import` / `market_candidate_row`：第三方候选批次与逐行差异，含 `stale`、原始行 `raw_json`、来源 as-of 与 `diff_status`；
- 不修改、不删除既有表/列/数据，不写官方行情表。

## 4. 索引 dirty 队列、旋转游标与清理

入口：`search-index-svc.mjs`、`unified-search-svc.mjs`。

- **查询前有界刷新**：`searchUnified()` 仅在索引 ready 时调用 `consumeSearchDirty({maxDocs:25})`。每次查询最多刷新 25 个实体；仍有 dirty 时返回 legacy 结果并注明“本次已刷新 N 条、剩余 M 条”，不返回旧 payload 当最新。
- **单条刷新**：`refreshSearchEntity()` 成功后立即删除该实体 dirty；源记录被排除/删除时删除索引行并清 dirty。
- **末批清理**：`buildSearchIndex()` 在类型完整时调用 `sourceIds(type)` 获取整个合法来源 ID 集合，再删除缺失行；不再使用本批 `seen`。项目类型按登记号聚合后的项目 ID 计算。
- **旋转游标**：每日批次 `buildSearchIndex({rotate:true})` 读取 `cursor:<type>`，完整处理后回到 0；后台显式 `offset` 仍可指定单批。游标越过当前总数时自动回到 0。
- **管理员覆盖层**：`admin_revision` 触发器入 dirty；查询消费后用同一覆盖合并逻辑重算 payload/hash，标题等公开字段立即参与检索与展示。
- **非 content 类型**：政策/方法学/项目/CEA 文件/因子/企业名录的更新不再等“下一次手动全量重建”，由 dirty 队列或每日旋转批次刷新。
- **legacy 回退也遵守覆盖层**：`searchLegacy` 的安全 SQL 用 `CASE EXISTS` 取公开字段有效值（显式 NULL 也按覆盖处理），日期/来源/地区筛选与 COUNT 都走同一有效值；取回后在 JS 合并覆盖层，索引未建/损坏时也不会显示覆盖前的旧标题，`manual_revision/manual_fields` 仍返回。

## 5. 语义扩展检索

入口：`semantic-search-svc.mjs`；路由：`POST /api/v2/search/semantic`。

- 只有显式 POST 才调用模型；GET 列表不触发。
- 单次结构化调用：`callStructuredModel(..., maxRetries:0)`；严格 JSON `{"terms":[...]}`；服务端再次去重、截断到 4 词、单词 40 字符、查询 100 字符。
- 精确编号短路：`CCER-10-001-V01`、`CCER—10—001—V01` 等直接 `keyword`，不调用模型、不消耗模型配额，`exact_reference=true`。
- 原查询始终保留：FTS MATCH 为 `(原查询) OR (扩展词1) OR ...`；类型/地区/年度/来源/日期筛选沿用原参数，扩展词不修改筛选。
- 模型失败/超时/无 provider/限流：返回 `searchUnified({...原参数})`，`mode=fallback`、`expansion_terms=[]`、`expansion_fallback_reason` 如实说明；不伪造扩展结果。
- 正常扩展：`mode=semantic_expansion`，`index_mode` 保留底层 fts5/legacy，`expansion_terms` 与 `semantic_message` 返回给页面。
- 配额：每用户每分钟 4 次、每日 40 次、平台每日 400 次；分钟/日窗口落库；超限回退普通检索而非报错丢结果。
- 库内标题提示仅用于提示模型短词，不把标题当事实，不调用外部服务；未引入哈希向量或静态同义词冒充 embedding。

## 6. CEA 企业档案

入口：`GET /api/v2/cea/entities/:id`；服务：`getCeaEntityProfile()`。

- 规范标识：有信用代码时跨年度按信用代码聚合（`credit:...`）；无代码时只按“名称 + 省份 + 城市”聚合（`name:...|省|市`），同名跨地区不合并。
- 主体键：`upsertCeaEntity()` 无代码时把省市纳入 `entity_key`；同源重采的兜底查询也校验省市。
- 异常代码：非 18 位/校验不通过的标准 `credit_code` 留空，原始值写 `raw_credit_code`，`credit_code_valid=0`；企业名称照常入名录。
- 多行业/多年度：`cea_entity_membership` 逐来源保留行业；档案返回 `industry_relations`（年度 → 行业集合 + 来源明细），不覆盖。
- 别名：`cea_entity_alias` 显式别名 + 历年名称/修订记录中的历史名称；管理员可 POST 带来源别名，写审计。
- 来源：主体来源 + 成员关系来源去重合并；正文/标题提及单独列 `mentions`，明确“非官方关系”。
- 排放：`emissions: null`，文案明确不提供/不推算企业实际排放，不用国际估算或名录数量替代。
- UI：名录企业名、地图省详情企业列表均链接 `#/cea?tab=entities&entity=<id>`；档案页返回名录入口。

## 7. 第三方行情候选与差异

入口：`market-candidate-svc.mjs`；后台路由：

| 方法 | 路径 | 作用 |
|---|---|---|
| POST | `/api/v2/admin/market-candidates/import` | 导入 CSV/JSON 候选并生成差异 |
| GET | `/api/v2/admin/market-candidates` | 批次、逐行差异、限额 |
| GET | `/api/v2/admin/market-candidates/export` | CSV/JSON/XLSX 差异导出 |

- 独立表：`market_candidate_import` / `market_candidate_row`；官方 `cea_trade_daily`、`trade_daily` 只读。
- 上限：2 MB、5000 行、单行 4000 字符；数值上限按成交量/成交额/均价/累计分别限制。
- 校验：来源名称或 http(s) 链接必填；日期必须真实存在；单位必须支持（tCO2e/吨/元/万元/元每吨）；`NaN/Infinity/非数字/负数/零` 拒绝；金额单位换算到元后比较。
- 官方侧：`CEA` 查 `cea_trade_daily`；`CCER` 查 `trade_daily` 并按 `market='CCER'`、日期汇总不同交易方式，缺字段保持 NULL 不当 0。其它标的、未来交易日、交易日晚于来源 as-of → `unsupported`。
- 差异：逐字段记录候选/官方/差值/是否一致；严格绝对容差（浮点余量），1 吨差异不会被 0.5% 相对容差吞掉；`missing/conflict/match/unsupported` 逐行保留。
- `stale`：批次显式 stale 或来源 as-of 超过 30 天即保留 stale=1；stale 不阻止差异展示。
- 导出：复用 `export-svc` 的 CSV 公式前缀防护；viewer 访问后台路由 403，匿名 401。

## 9. 已知限制

1. 本进程未执行真实付费模型、真实浏览器、云端迁移/部署/Git 推送；由主 Codex 独立验收。真实语义回执已存在，但需要主 Codex 在发布前复核模型/凭据配置。
2. 索引查询每次最多消费 25 条 dirty；批量源数据变更后，检索可能先回退 legacy 数轮，直到 dirty 被每日/后台批次清空。这是“不把旧 payload 当最新”的代价，不是失败。
3. 索引完整批次的清理需要读取该类型全部合法 ID；类型数据量很大时末批更重，但不在每次查询执行。
4. 中文切分仍是双字/单字，不是词典分词；语义扩展只把模型词合并到 FTS/legacy 候选，不保证扩展词相关，结果必须回原文核对。
5. 企业档案的“关联资料”只做标题/正文提及，不是官方隶属/政策关系；别名必须有来源，未做跨地区名称相似度合并；不提供企业实际排放量。
6. 候选单位只支持本轮列出的有限集合；未做任意单位库/换算表；CCER 累计口径在 `trade_daily` 未提供时，累计字段标不可比而不是补 0。
7. 120 的两个山西样本用例因仓库缺少既有样本文件失败；未删除或改写测试，待样本恢复后重跑。
8. 未跑全套旧网络每日任务/长期 server；遵循主 Codex 回执，仅跑新增与受影响定向测试，不能声称全量回归通过。
