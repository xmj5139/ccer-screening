# 首轮检查整改对照

**整改日期**：2026-09-24
**整改依据**：《CCER 应用首轮检查与整改清单》（检查日期 2026-09-24）
**整改范围**：P0 全部 4 项 + P1 第 5、7 项 + 第 6 项的能力诚实降级；复核说明中的测试数量问题

---

## 一、总体结论

首轮检查的核心判断是：**「通过测试不能证明与官方方法学一致」**。这个判断成立，
本轮整改的第一件事就是去读官方原文，结果证明**原实现确有实质性错误**。

最严重的一处是：原 `CCER-10-001` 规则卡允许露天煤矿、瓦斯提纯、民用/工业燃气、
火炬基准线与「部分利用」情景，而官方 PDF §2 明确只适用**井工煤矿 + 无焰氧化 + 发电/供热/热电联产**，
§6.1 明确基准线只有一种（**瓦斯全部排空**）。这不是页码缺失，是模型错了。

整改后，系统默认**不再产出任何业务测算数字**。这不是能力退化，而是把「未确认」如实表达出来。

### 2.3 原实现中被删除的「无来源臆造」内容

以下内容在任何官方文件中都找不到依据，属于制作方自行设定，本轮**全部移除**：

- 基准线「部分利用」情景的 50% / 50% 拆分比例
- 泄漏率 1% 及 `LE = M_CH4 × λ × GWP` 公式
- 基准线火炬燃烧效率 98%
- 自制的 `PE_slip`（未销毁逃逸）与 `PE_comb`（销毁过程 CO₂）组合
- 瓦斯发电替代电网电力的自定义扣减方式
- 露天煤矿适用性

### 2.4 **本轮发现并修复的一个 100 倍错误**

重写过程中，第二套独立实现与原插件在样例上出现 **100 倍差异**。

- 官方公式(3) 的印刷式为 `MM′_y = Σ ( F_NPT,h × PC_CH4,h × ρ_CH4 × 10⁻³ )`，
  「式中」说明 `PC_CH4,h` 的单位是「百分比（%）」。
- 若直接把百分数（1.2）代入，量纲为 `m³/h × 1 h × 1.2 × kg/m³ × 10⁻³`，
  结果比正确值**大 100 倍**；正确做法是先换算为体积分数（0.012）。
- 修复后两套实现在全部样例上一致（差异 < 0.02 tCO₂e）。

该口径差异已作为 **EXP-117** 记入 `docs/12`，请领域专家确认我们的理解正确。

### 2.5 独立复算验证

新增两套彼此独立的实现并交叉比对：

| 实现 | 位置 | 说明 |
|---|---|---|
| A | `src/methodologies/ccer-10-001.mjs` 的 `plugin.compute()` | 生产实现 |
| B | `test/official-10-001.mjs` | 按原文公式**重新写一遍**，不 import 任何生产代码 |

比对脚本 `scripts/verify-10001.mjs`，覆盖 4 个正结果样例（仅发电 / 仅供热 / 热电联产 /
实测气量远大于推算值时取推算值的 `min()` 分支）与 3 个应拒绝样例（浓度 9% /
§6.7a) 合规性不满足 / 计入期 12 年）。

**结果：差异项数 0。**

## 三、P0-2 审批状态与门禁不再默认放行

| 原问题 | 整改 |
|---|---|
| 种子数据「只要代码里有模块就写 `approved`，并以『系统基线』填审核人」 | ✅ 改为一律写入 **`pending_review`**，审批人与审批时间**留空**。新增 `approveMethodology()` 审批流，批准时才写入真实审批人 |
| 默认门禁为 `demo` | ✅ 默认改为 **`strict`** |
| 仅在 strict 模式下拦截占位系数 | ✅ 业务测算改为**四道独立关卡**：① 计算插件审批状态须为 `approved`；② 不得含任何 `placeholder` 因子；③ 不得有缺条款页码的公式；④ 必须绑定通过的条件检查快照 |
| 演示出数与业务库混在一起 | ✅ 新增**隔离的演示通道**：默认关闭；须管理员显式开启；运行记录 `status='demo'`；返回 `demo:true` / `usable_for_report:false` / `watermark`；**报告生成与导出都不接受 demo 数据** |

审批流还带一个防呆：**当插件仍有占位系数或缺条款页码时，`approveMethodology` 直接返回 409**，
并在 `detail` 中列出具体缺哪几项。也就是说，无法靠「点一下批准」绕过未确认的系数。

## 五、P0-4 计算必须绑定条件检查快照

新增 `assertCalculationPreconditions()`，业务测算必须满足：

1. 绑定的条件检查快照属于**同一项目**；
2. 使用**同一方法学版本**；
3. 使用**同一分析基准日**；
4. 该快照的 `blocking_failures === 0`；
5. 快照由 `opts.eligibilityRunId` 显式传入，或由 `latestEligibilityFor()` 找到。

任一不满足 → **HTTP 409**，`kind='precondition'`，并说明具体是哪一项。
`report-svc.generateReport()` 也改为把刚生成的条件检查运行 ID 传入计算，保证报告中的数字与
报告中的判断**必然同源**。

实测：`CCER-DEMO-004`（站场设计总规模 35000 m³/天，超出 CCER-10-004 的 3 万上限）
条件检查结论为「存在明确障碍」，其测算被拒绝，提示「存在 1 项硬障碍…禁止形成可用于筛选报告的减排量数字」。

|---|---|

## 七、P1-7 报告的证据等级错误

| 原问题 | 整改 |
|---|---|
| `project-svc` 允许任一可管理项目的角色直接修改登记状态与三类减排量，未强制官方链接或证据 | 状态暂仍由人工维护，但**报告侧的证据等级已改正**（见下） |
| `report-svc` 把人工录入的注册登记状态输出为「**官方已确认**」 | ✅ 新增 `registryStatementLabel()`：有公示链接时标「**项目资料记载**」，无链接时标「**待核实**」；**永不**标「官方已确认」 |

报告中的表述现在是：

```
【项目资料记载】注册登记链条状态（人工录入）：项目公示
   （注：本字段由项目档案人工维护，系统未与全国温室气体自愿减排注册登记系统自动核对，

【待核实】业主公示预计减排量：320000 tCO₂e
   （注：仅代表业主公示口径，不等于核查量或登记量，且未经系统与公示页面核对。）
```

后续动作（见 `docs/01` G-09）：接入注册登记系统的采集任务，为状态绑定 `source_id` 与采集时间后，

## 八、P1-6 政策跟踪与「AI」能力的诚实降级

检查指出：当前产品实质是**人工录入 + 确定性规则原型**，而 `radar-svc` 只做预置 URL 的哈希比对，
动态渲染的注册登记目录无法保证完整发现新增方法学；PDF 归档、页码提取、资料上传/OCR、自动字段抽取均未实现。

**本轮处理：不做能力包装，改为如实标注。**

- `docs/09-官方来源采集方案.md` 第五节逐条列出 8 项未实现的采集能力（C-01 ~ C-08），
  并说明每一项的生产化建议。
- `docs/01` 的未完成项清单把 OCR、文件归档、批量导入等标为未实现。
- 报告与工作台的免责声明明确：系统**不调用任何外部大模型 API**，
  字段抽取与变更摘要由人工完成，以换取完全离线可运行与数据不外流；
  接入 LLM 只需替换四个入口，判断与计算链路不受影响。
- `docs/12` 第二部分把「全局常数引用版本」等条目按官方原文逐条结清，
  未结清的（`CEF_CH4`、`TDL_y`、`η_ELEC` 等）保留为待确认，不假装已解决。

**PDF 原件归档**：本轮把 CCER-10-001 的方法学 PDF 完整解析并保存，
解析结果位于 `.dsh-mineru/artifacts/ccer10001-*/full.md`；
`source_document.original_file_hash` 列已就绪，正式的 PDF 归档仍需接入机构对象存储。

## 十、整改后的默认行为（重要）

**新装一套系统，任何方法学都无法产出业务测算数字。** 这是**预期行为**，原因是：

| 方法学 | 业务测算被阻止的原因 |
|---|---|
| CCER-10-001 | 含 1 项原文未定义的参数 `CEF_CH4`（另有 `TDL_y`、`η_ELEC` 无默认值），且插件审批状态为 `pending_review` |
| CCER-10-002 | 公式链尚未对照官方原文，全部公式缺条款页码，审批状态 `pending_review` |
| CCER-10-003 | 同上 |
| CCER-10-004 | 同上 |

要产出数字，必须走完这条链路：

```text
① 研究员在注册登记系统核对方法学编号与名称
② 领域专家对照官方 PDF 逐条回填公式条款页码
③ 领域专家逐项确认参数（含原文未定义项的处置方式）
④ 在管理后台完成审批（系统会拒绝在仍有占位系数时批准）
⑤ 业务测算放行，且必须绑定通过的条件检查快照
```

在上述链路走完之前，**演示通道**可用于流程演示：它由管理员显式开启，
运行记录标记为 `demo`，带水印，**不进入投资筛选报告、不可导出**。
