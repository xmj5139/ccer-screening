# 计算插件接口规范

> 设计文档第 7 节要求：**计算执行采用独立的、按方法学编号与版本注册的插件，不允许通用大模型直接生成最终数字。**
> 本文档定义插件的接口契约、注册方式、执行流程、校验规则与验收要求。

---

## 一、核心纪律

| 编号 | 纪律 | 实现机制 |
|---|---|---|
| D-01 | 通用计算链**不是**任何方法学的官方公式，只用于组织计算顺序 | `calc-kit.mjs` 只提供与具体方法学无关的**数值与校验工具**，不提供任何公式 |
| D-02 | 实际公式、基准线、扣减、排放因子、GWP、舍入规则必须逐项取自所选方法学及其指定引用文件 | 每个插件在自己的文件内声明 `formula_refs` / `factors` / `parameters` / `scenarios` / `compute` |
| D-03 | 每个插件提供输入模板、数据校验、逐式计算明细和可复算导出 | `parameters[]`（模板）、`validate()`（校验）、`compute()` 返回 `steps[]`（逐式明细）、`selfCheckSamples[]`（复算样例） |
| D-04 | 对缺失的关键监测数据禁止用 AI 猜值 | `validate()` 返回 `errors` → `runCalculation` 返回 HTTP 422 且**不产生任何数值** |
| D-05 | 允许使用明确标注为「假设」的情景输入，但输出只称「情景估算」 | `resolveInputs()` 对用户覆盖一律标注 `模型假设`；输出 `disclaimer` 固定表述 |
| D-06 | 不得称「预计可签发量」 | `result_json.disclaimer` 与 `unit_note`；测试断言禁用措辞只以否定形式出现 |
| D-07 | 未完成公式校验的方法学必须提示「暂不支持自动测算」 | `calculator_status !== 'approved'` → 拒绝；严格模式下含占位系数 → 拒绝 |

### 通用计算链与各方法学实际公式的区别（重要）

设计文档给出的通用链是：

```text
原始活动数据 → 时间/边界/单位校验 → 方法学参数计算
→ 基准线排放或清除量 → 项目排放 → 泄漏/扣减/不确定性处理
→ 方法学规定的可计减排量 → 分期汇总 → 情景与敏感性
```

四个已实现插件**在结构上遵循该顺序，但公式各不相同**：

| 环节 | CCER-10-001（瓦斯销毁） | CCER-10-002/003/004（油气回收制产品） |
|---|---|---|
| 基准线 | 瓦斯排空 或 瓦斯火炬燃烧（含火炬不完全燃烧的 CH₄ 与 CO₂ 两部分） | 伴生气/放喷气排空 或 火炬燃烧 |
| 项目排放 | **未销毁甲烷逃逸** + **销毁过程 CO₂**（与基准线火炬的 CO₂ 项对称计入） | **处理自耗气燃烧** + **外购电力** （产品最终燃烧不计入，因产品替代了化石天然气） |
| 泄漏 | `M_CH4 × λ × GWP` | `M_CH4 × λ × GWP` |
| 闭式等价形式 | 排空基准线下：`ER = M_CH4·η_d·(GWP − EF_CO2) − LE` | 无简单闭式 |

> CCER-10-001 的闭式等价形式在 `selfCheckSamples` 中作为**交叉校核**使用，
> 也是领域人员手算复核的最便捷路径。

## 二、插件接口契约

每个方法学模块导出三个对象：

```js
export const meta   = { methodology_id, version, display_name, project_type };
export const rulecard = [ /* 规则对象数组，见 docs/07 */ ];
export const plugin = { /* 计算插件，见下 */ };
```

### 2.1 `plugin` 对象结构

| 键 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `plugin_key` | string | ✅ | 命名规范 `calc-ccer-<域>-<序号>`，如 `calc-ccer-10-001` |
| `plugin_version` | string | ✅ | 语义化版本，如 `1.0.0`；插件变更必须升版本 |
| `methodology_id` | string | ✅ | 如 `CCER-10-001` |
| `methodology_version` | string | ✅ | 如 `V01`；**计算运行必须显式绑定版本** |
| `title` | string | ✅ | 中文标题 |
| `status_note` | string | ✅ | 关于占位系数与待确认项的说明，显示在界面顶部 |
| `formula_refs[]` | array | ✅ | 公式声明（≥ 5 条） |
| `parameters[]` | array | ✅ | 输入参数绑定声明（≥ 5 项） |
| `scenarios` | object | ✅ | 必须恰好含 `conservative` / `base` / `optimistic` 三个键 |
| `factors[]` | array | ✅ | 因子声明（≥ 5 项，含全局常数） |
| `validate(inputs, ctx)` | function | ✅ | 返回 `{ errors[], warnings[] }` |
| `compute(inputs, ctx)` | function | ✅ | 返回计算结果对象 |
| `selfCheckSamples[]` | array | ✅ | 独立复算样例（≥ 1 个） |

### 2.2 `formula_refs[]`

```js
{ formula_id: 'F2', title: '回收甲烷质量', expression: 'M_CH4 = V_CH4 × ρ_CH4 / 1000',
  unit: 'tCH₄/年', clause_ref: '<方法学条款与页码>' }
```

规范：`formula_id` 在插件内唯一；`expression` 用符号式而非数值；`unit` 必填；`clause_ref` 必填
（专家回填前写 `【占位】`）。测试 `03-calculation` 断言每条都含 `expression` / `unit` / `clause_ref`。

### 2.3 `parameters[]`

```js
{
  key: 'recovery_volume_nm3',        // 输入键，compute 通过它取值
  label: '年回收瓦斯量（标态）',       // 界面标签
  unit: 'Nm³/年',
  source: 'fact' | 'input',          // 取值来源
  fact_key: 'gas.recovery_volume_nm3',   // source='fact' 时绑定的事实字段
  factor_fallback: '<factor_key>',   // 事实缺失时的因子缺省值
  type: 'number' | 'enum' | 'date' | 'list',
  required: true | false,
  min: 1, max: 5e9,                  // 数值合理范围（校验依据）
  default: 0.98,                     // 插件级缺省值
}
```

**取值优先级与来源标注**（`calc-svc.resolveInputs` 实现）：

```text
1. 用户在情景输入中的覆盖        → origin.kind = 'assumption'，标签「模型假设」
                                    若覆盖了项目事实，note 中记录原始值与原始来源
2. 项目事实（source = 'fact'）    → origin.kind = 事实的 source_kind
                                    （official / project_doc / analyst / owner_claim）
3. 方法学缺省因子（factor_fallback）→ origin.kind = 'factor_default'，标签「方法学缺省值（占位待确认）」
4. 插件缺省值（default）          → origin.kind = 'plugin_default'，标签「插件缺省值」
```

> **关键设计**：用户覆盖**永远**被标注为「模型假设」，绝不冒充官方或项目资料证据。
> 该标注会一路进入报告的事实表与情景估算段落。

### 2.4 `scenarios`

```js
scenarios: {
  conservative: {
    label: '保守情景',
    multipliers: { efficiency: 0.9, concentration: 0.95, availability: 0.85 },
    note: '销毁效率取下限、甲烷浓度保守下调 5%、可用小时数下调 15%，得到偏小的减排量。',
  },
  base:        { label: '基准情景', multipliers: { /* 全 1 */ }, note: '按实测记录与缺省值取中。' },
  optimistic:  { label: '乐观情景', multipliers: { /* ... */ },   note: '设备满负荷、效率达设计值。' },
}
```

约束：
- 乘数由各插件在 `compute()` 中显式应用到对应输入，**不是**引擎自动施加。
- **必须满足方向性**：`保守 ≤ 基准 ≤ 乐观`。由测试「保守情景结果不大于基准情景，基准情景不大于乐观情景」断言。
- 情景使用的乘数会写入 `result_json.scenario_multipliers`，并作为「模型假设」列入 `assumptions[]`。

### 2.5 `factors[]`

```js
{
  factor_key: 'c10-001.destruction.efficiency.default',
  name: '瓦斯甲烷销毁/氧化效率缺省值',
  value: 0.9,
  unit: '无量纲(0-1)',
  scope: 'methodology' | 'global',
  methodology_version_id: 'CCER-10-001::V01',   // 全局因子留空字符串 ''
  source_ref: '【占位】待填入方法学正文规定的缺省值及适用条件',
  source_year: null,
  gwp_assessment_report: 'IPCC AR5',             // 仅 GWP 因子需要
  value_status: 'verified' | 'placeholder' | 'deprecated',
  verification_note: 'EXP-003：缺省值与实测要求须由领域专家依据方法学原文确认。',
  reasonable_min: 0.5, reasonable_max: 1.0,      // 数值合理范围，用于交叉校核
}
```

**`value_status` 的语义与门禁**：

| 状态 | 含义 | 门禁影响 |
|---|---|---|
| `verified` | 数值与出处已核实（数值可由公开定义复算） | 无 |
| `placeholder` | 缺省值 / 效率值，**必须**由领域专家确认 | 严格模式下阻止出数；演示模式下所有输出逐项标注 |
| `deprecated` | 已弃用，不得使用 | — |

测试 `03-calculation` 断言：每个占位因子必须写明 `verification_note`。

### 2.6 `validate(inputs, ctx)`

```js
validate(inputs, ctx) {
  const errors = [];    // 有任一 error → 拒绝出数（HTTP 422），不产生任何数值
  const warnings = [];  // 仅提示，不阻断
  // 使用 calc-kit 提供的 validateNumeric(label, value, { min, max, unit, field })
  return { errors, warnings };
}
```

必须校验的项：

| 项 | 工具 | 错误类型 |
|---|---|---|
| 关键计量值缺失 | `validateNumeric(..., { allowNull: false })` | `missing` |
| 非数值（单位写进数值字段） | `validateNumeric` | `not_numeric` |
| 超出合理范围 | `validateNumeric` + `checkRange` | `out_of_range` |
| 超出方法学适用范围（浓度上限、规模上限） | 插件内显式判断 | `scope_violation` |
| 关键日期缺失（计入期起始） | 插件内显式判断 | `missing` |
| 期间重叠 / 起止倒置 | `detectPeriodOverlap`（由 `runCalculation` 在 `extraPeriods` 上调用） | `period_overlap` / `period_reversed` |

### 2.7 `compute(inputs, ctx)`

`ctx` 由 `calc-svc.runCalculation` 构造：

```js
{
  factors: FactorRegistry,          // 只读因子快照，get(key) / value(key)
  scenario: 'conservative'|'base'|'optimistic',
  scenarioLabel: '基准情景',
  scenarioMultipliers: { ... },     // 当前情景的乘数
  baseDate: '2026-09-24',           // 分析基准日
  project: { ... },                 // 项目行（只读）
}
```

返回值：

| 键 | 类型 | 说明 |
|---|---|---|
| `steps[]` | array | **逐式计算明细**，每步含 `step_no` / `title` / `formula` / `symbolic` / `substitution` / `result` / `unit` / `factor_refs` / `clause_ref` / `note` / `factor_status` |
| `annual[]` | array | 年度序列（由 `buildAnnualSeries` 生成；无数据年份 `reduction: null` 且 `data_status` 说明「不外推」） |
| `crediting` | object | 计入期汇总（由 `aggregateCrediting` 生成） |
| `assumptions[]` | array | 模型假设清单（含情景乘数与全部占位系数） |
| `missing[]` | array | 缺失数据清单（**未猜值**的项目） |
| `sensitivity[]` | array | 敏感性分析（由 `sensitivity()` 生成，按 `swing` 降序） |
| `er_annual` | number | 年度可计减排量（tCO₂e/年）；**允许为负**，负值须同时给出 warning |
| `warnings[]` | array | 计算过程中发现的业务警示（可选） |

### 2.8 `selfCheckSamples[]`

```js
{
  name: '样例 A：风排瓦斯发电，浓度 0.8%，年回收量 1.2 亿 Nm³，基准线瓦斯排空',
  inputs: { /* 完整输入 */ },
  expect: { v_ch4_nm3: 960000, m_ch4_t: 687.36, be_tco2e: 19246.08, er_annual_tco2e: 15432.0018432 },
  tolerance: 0.01,
  expectRejection: 'scope_violation',   // 或：声明该样例应被拒绝
}
```

要求：
- 每个样例必须写明**手算过程**（写在 `expect` 上方的注释中）。
- 期望值必须由领域人员独立算出，**不得由插件输出反填**。
- 至少包含一个正结果样例；建议包含一个负结果或拒绝样例。

## 三、执行流程

```text
runCalculation(user, projectId, opts)
│
├─ 1. 定位方法学版本
│     opts.methodologyVersionId → opts.methodologyId → 匹配分最高的候选
│
├─ 2. 版本合法性检查
│     document_status !== 'formal'  → 409「计算必须绑定现行正式版本」
│     无插件模块                     → 409「暂不支持自动测算」
│     calculator_status !== approved → 409
│
├─ 3. 门禁检查 gateCheck(plugin)
│     gate_mode === 'strict' 且存在 placeholder 因子 → 拒绝出数
│
├─ 4. 输入解析 resolveInputs(plugin, facts, overrides)
│     按优先级取值，并记录每一项的来源标注
│
├─ 5. 期间重叠校验（opts.extraPeriods）
│     有重叠/倒置 → persistRejected
│
├─ 6. validate(inputs, ctx)
│     有 errors → persistRejected（写入 calculation_run，status='rejected'）
│     ★ 此路径不产生任何减排量数值 ★
│
├─ 7. 对每个情景执行 compute(inputs, ctx)
│     注入该情景的 multipliers
│
├─ 8. 落库 calculation_run
│     inputs_json / result_json / factor_snapshot_json / analysis_base_date
│     audit: calculation.run
│
└─ 9. 返回 runs[]（含逐式明细、假设、缺失、敏感性、占位系数清单）
```

## 四、注册与版本管理

注册表位于 `src/methodologies/index.mjs`，键为 `${methodology_id}::${version}`：

```js
const MODULES = [m10001, m10002, m10003, m10004];
const registry = new Map();
for (const mod of MODULES) {
  registry.set(`${mod.meta.methodology_id}::${mod.meta.version}`, mod);
}
```

**多版本并存**：同一方法学的不同版本可同时注册（例如 `CCER-10-001::V01` 与 `CCER-10-001::V02`）。
计算运行通过 `calculation_run.methodology_version_id` 显式绑定版本，
`compareRuns()` 可对比两个版本的结果差异并说明原因。

**新增方法学插件的步骤**：

1. 在 `src/data/catalog.mjs` 的 `METHODOLOGY_CATALOG` 中登记方法学条目（必须附官方发布通知 URL）。
2. 新建 `src/methodologies/ccer-XX-YYY.mjs`，导出 `meta` / `rulecard` / `plugin`。
3. 在 `src/methodologies/index.mjs` 的 `MODULES` 中 import 并加入数组。
4. 在 `src/data/fact-fields.mjs` 中登记该方法学需要的新字段。
5. 运行 `npm run seed -- --reset` 重建数据库。
6. 运行 `npm test`，确认全部测试通过。
7. 运行 `node scripts/gen-docs.mjs` 更新方法学清单。
8. 将方法学专属占位系数登记到 `docs/12-领域专家确认清单.md`。
9. 由领域专家确认系数后，更新 `factor_version.value_status` 与验证信息。

## 五、单位与数值约定

| 量 | 单位 | 说明 |
|---|---|---|
| 气体体积 | `Nm³`（标态，0 ℃、101.325 kPa） | 全部体积输入必须为标态；非标态须先折算 |
| 甲烷质量 | `tCH₄` | 由 `Nm³ 甲烷 × ρ_CH4 ÷ 1000` 得到 |
| 排放量与减排量 | `tCO₂e` | 全部输出统一为 tCO₂e |
| 甲烷体积浓度 | `%`（0–100） | 仅 CCER-10-001 使用 |
| 甲烷体积分数 | 无量纲（0–1） | 仅 CCER-10-002/003/004 使用；界面提示「90% 应填 0.9」 |
| 效率 | 无量纲（0–1） | 销毁/氧化效率、火炬燃烧效率、自耗气比例、泄漏率 |
| 电力 | `MWh` | — |
| 电力排放因子 | `tCO₂/MWh` | — |
| 站场规模 | `m³/天` | 设计规模，非实际处理量 |

**舍入**：内部计算保留全部精度，仅在 `step()` 输出时四舍五入到 10 位有效小数；
`conservativeRound()` 提供向「减排量较小」方向取整的工具（供方法学要求保守取整时使用）。
方法学规定的最终舍入规则须由领域专家确认后写入 `formula.rounding`。

## 六、验收要求

设计文档第 10 节 C 阶段验收标准对应到本原型的实现：

| 验收标准 | 实现 | 测试 |
|---|---|---|
| 每个上线插件通过领域人员独立手算/表格样例校验 | `plugin.selfCheckSamples` 共 6 个样例 | `03-calculation` 用**独立算术**重新计算每个样例的期望值并比对引擎输出 |
| 单位与边界校验通过 | `validateNumeric` + `detectPeriodOverlap` + `checkRange` | 验收用例 5 |
| 错误输入拒绝给数 | HTTP 422 + `persistRejected`，`er_annual` 为 null | 验收用例 5 断言被拒绝的运行不产生任何数值 |
| 保守情景 ≤ 基准 ≤ 乐观 | 各插件 `compute` 中的乘数应用 | 「保守情景结果不大于基准情景…」 |
| 未完成校验时提示「暂不支持自动测算」 | `calculator_status` + `gateCheck` | 「严格模式下含占位系数的插件被阻止出数」 |
| 无可用监测数据的年份不外推 | `buildAnnualSeries` | 「无可用监测数据的年份不外推填补」 |
| 因子数值可由公开定义复算 | `global-factors.mjs` 的 `source_ref` | 「已核实因子的数值可由公开定义复算」 |

## 七、复核清单（领域人员使用）

对每个新上线插件，请逐项确认：

- [ ] `formula_refs` 的每条公式是否与方法学正文一致（符号、下标、单位、适用期间）
- [ ] `clause_ref` 是否已回填为真实条款号与页码
- [ ] `parameters` 的每个 `fact_key` 是否指向正确的事实字段
- [ ] `factors` 中每个 `placeholder` 因子是否已替换为方法学规定值，并改为 `verified`
- [ ] `scenarios` 的乘数与方向性是否符合方法学的保守性原则
- [ ] `validate` 的合理范围（`min` / `max`）是否能拦住明显的单位错误
- [ ] `selfCheckSamples` 的期望值是否由本人独立手算得出（而非取自插件输出）
- [ ] 基准线情景的判定逻辑是否与方法学一致（特别是「部分利用」这类中间情景）
- [ ] 项目排放的扣减项是否完整（自耗气 / 电力 / 泄漏 / 未销毁逃逸 / 销毁过程 CO₂）
- [ ] 是否存在方法学要求而插件未实现的扣减项或不确定性处理
