# 独立复核发现（2026-10-16）

DSH 完成本轮基础实现后，应逐项处理。本文件基于真实迁移库及实际代码，不是可选功能建议。

1. `retrieval-svc` 的 public_project 使用不存在的 `registry_no`，真实字段是 `registry_project_no`；emission_factor 使用不存在的 `unit`/`note`，真实为 original_unit/standard_unit/applicability 等。当前 catch 把 schema 错误吞成空命中，导致库内优先失效。`summary-svc` 同样引用错误项目字段、因子字段，accounting_standard 还有不存在的 source_url。请对所有白名单 SELECT 用实际 schema prepare 验证。独立测试 test/90-v2-platform-independent.test.mjs 已固定这些验收，不能删或放松。
2. 项目原文链接实际存在 `official_url`（及 design_doc_url），检索/摘要不要强制设 NULL；标准的 source_locator 是原文定位说明，不一定 URL，链接应取 actual original_url 或 announcement_url。
3. 摘要缓存必须随完整正文（包括6000字以后修改）、来源/元数据、模型配置变化失效。当前 inputHash 只有截断片段；rowToSummary/fresh 判定未比较当前 provider/model，批量 getSummaries 不检查输入变化。这会展示过期内容。请加完整输入哈希，并对列表缓存查实际 freshness；stale 摘要不能当成当前正文摘要显示。
4. 摘要候选目前只扫描每类头40条，补完头40条后老内容永远轮不到；total limit也不是全局硬限制。需要持久游标/可靠分页，失败项不可无限阻塞后续；排除演示项目、失败抓取、重复/归档内容、不生效的旧因子，保留总量/成功/失败的真实覆盖统计。日更新持续补齐所有符合范围条目。支持后台按类型/选定ID补齐以便初始回填与实际排错。
5. 检索指定日期仅判断年份不够：同年不同日、今天/最新也要校验；不能用2026-01旧行情回答2026-10-16。SQL无order LIMIT40会把最新记录漏掉；须对行情明确日期/市场分类匹配与截至日排序。自然中文提问的关键词不能只截取句首长滑窗，把位于句尾的核心词截掉。
6. 问答 quotes 必须对应本段 source_ids，不能引用A却用B引句通过。出现伪造引用/无法定位引句不应悄悄算通过。明显新增且证据没有的数字/日期应拒绝（禁止无程序支持的模型推算数值）。不能只验证引句存在却放过相矛盾的数值答复。`quoteInEvidence`目前把小数点/负号删掉、只要长句60%片段相同就通过，会放过0.5306变成05306或9.9999的篡改；独立测试91已证实失败。需严格保留数值符号，只允许不改变语义的空白/全半角排版归一化。
