# 接口清单

本文档列出 CCER 投资筛选 AI 应用当前实际实现并已注册在 `src/server.mjs` 路由表中的全部 HTTP 接口（共 46 条）。服务仅使用 Node.js 内置模块 `node:http`，**零第三方依赖**；默认绑定回环地址 `127.0.0.1`，端口取环境变量 `PORT`（默认 `8787`），监听地址取环境变量 `HOST`（默认 `127.0.0.1`），数据库路径由 `CCER_DB_PATH` 决定。路由采用「方法 + 按 `/` 切分的等长路径段」匹配，路径段以 `:` 开头的部分作为路径参数传入处理函数（服务端会对参数做 `decodeURIComponent` 解码）。全部接口统一以 `/api/` 为前缀，非 `/api/` 前缀的路径一律走静态资源分支。

本文所有内容均取自源码：路由注册见 `src/server.mjs`，业务语义见 `src/services/` 下各服务模块。未在路由表中注册的接口一律视为不存在。

## 通用约定

### 身份识别与会话（安全基线）

身份**只**来自服务端会话，客户端不能自报身份。认证模式由系统元数据 `auth_mode` 决定，环境变量 `CCER_AUTH_MODE` 可显式覆盖：

| 模式 | 身份来源 | 说明 |
| --- | --- | --- |
| `session`（**默认**，生产） | 服务端会话令牌 | 请求头 `x-user-id` 与查询参数 `?user=` **一律忽略**（不报错、也不记录）。除白名单外的 `/api/*` 无有效会话时返回 **401 `{ "error": "未认证" }`** |
| `dev`（必须显式开启，仅本地演示） | 会话令牌 **或** 旧的 `x-user-id` / `?user=` | 服务启动时打印多行警告横幅，说明认证已关闭、不得暴露到回环之外。与 `CCER_ALLOW_REMOTE=1` 同时出现时**拒绝启动** |

令牌传输（**不支持**查询参数传令牌）：

- 优先 `Authorization: Bearer <token>`；
- 其次 Cookie `ccer_session`（`HttpOnly` + `SameSite=Strict` + `Path=/`，登录时下发、注销时以 `Max-Age=0` 清除）。

令牌由 `crypto.randomBytes(32).toString('base64url')` 生成，数据库 `user_session.token_hash` 只保存其 **SHA-256 摘要**，明文令牌只在登录响应中出现一次。会话过期（`expires_at`）、已注销（`revoked_at` 非空）与账号停用（`app_user.active = 0`）一律视为无效。

**免登录白名单**（仅三条）：`GET /api/health`、`POST /api/auth/login`、`POST /api/auth/register`（公开注册：只创建 `viewer` 账号、不签发会话）。此外 `GET /` 与 `web/` 下的静态资源无需会话（它们不含任何数据）。

内置可用身份（`src/services/seed.mjs` 种入 `app_user`，演示口令定义在 `src/data/users.mjs`）：

| 身份 ID | 角色 | 角色名称 | 所属团队 |
| --- | --- | --- | --- |
| `user-admin` | `admin` | 系统管理员 | `team-carbon` |
| `user-researcher` | `researcher` | 政策研究员 | `team-carbon` |
| `user-analyst` | `analyst` | 投资分析师 | `team-invest` |
| `user-reviewer` | `reviewer` | 领域复核人 | `team-carbon` |
| `user-other` | `viewer` | 只读用户 | `team-other` |

> ⚠️ 口令是**占位演示口令**（明文定义于 `src/data/users.mjs`），仅供原型与本地演示。正式部署必须替换为机构统一身份认证（SSO / OIDC / LDAP），由身份提供方完成口令与多因素校验，本系统只接收身份断言并建立服务端会话。

先登录再调用其他接口（所有示例中的 `-H 'x-user-id: …'` 在 `session` 模式下已不再产生任何效果）：

```bash
TOKEN=$(curl -s -X POST http://127.0.0.1:8787/api/auth/login \
  -H 'content-type: application/json' \
  -d '{"user_id":"user-analyst","password":"analyst-demo-2026"}' | sed -n 's/.*"token": *"\([^"]*\)".*/\1/p')
AUTH="authorization: Bearer $TOKEN"
```

角色枚举全集为 `admin / researcher / analyst / reviewer / viewer`（`projects.ROLES`）。身份决定四类行为：**角色白名单**（如新增来源、确认来源变更、审核、查看审计日志与待审列表、切换门禁模式、会话管理）、**项目级授权**（项目按团队与保密等级过滤，只读角色不能产生新数据）、**数据可见范围**（证据按 `confidentiality` 过滤）、以及**审计日志署名**。三层校验的完整规则与各角色权限范围见下文「授权模型」。


### 请求体

- 仅 `POST` / `PATCH` / `PUT` 读取请求体；`GET` 请求体一律忽略。
- 大小上限 **32 MB**，超限抛出「请求体过大（超过 32 MB）」。
- 依据 `Content-Type` 解析：`application/x-www-form-urlencoded` 解析为表单对象；其余（约定为 `application/json`）按 JSON 解析，解析失败抛出「请求体不是合法 JSON」。
- 空请求体返回 `{}`。
- 请求体解析在业务 `try` 块**之外**单独执行：超限或非法 JSON 时直接返回 **400**，响应体为 `{ "error": "请求体解析失败", "message": "<具体原因，如「请求体过大（超过 32 MB）」或「请求体不是合法 JSON」>" }`，请求不进入业务处理，也不会表现为 500。

### 回环限制

服务在进入任何路由之前先做来源地址校验：

- 允许的地址为 `127.0.0.1`、`::1`、`::ffff:127.0.0.1`；
- 非回环来源默认直接返回 **403**，响应体为 `{ "error": "本服务默认仅允许回环访问，如需内网开放请设置 CCER_ALLOW_REMOTE=1" }`；
- 设置环境变量 `CCER_ALLOW_REMOTE=1` 后才允许内网 / 远程访问。

该限制对静态资源与 API 一视同仁。

### 响应规约

处理函数返回的对象按以下 **6 条分支**依次判定，命中即返回（`src/server.mjs` 主处理函数中的「统一响应规约」）：

| 顺序 | 返回值形状 | 实际行为 | 使用场景 |
| --- | --- | --- | --- |
| 1 | `{ raw: { mime, body, headers } }` | 以 `200` 输出原始内容，`content-type` 取 `raw.mime`，并附加 `raw.headers`（如 `content-disposition`） | 文件下载（`GET /api/reports/:id/export`） |
| 2 | `{ status, body }`（`body !== undefined` 且 `status` 为数字） | 显式信封：以 `status` 作为 HTTP 状态码，仅输出 `body` | 显式指定状态码的成功 / 失败响应 |
| 3 | `{ error, ... }`（`error` 为真值） | 业务错误：以 `out.status \|\| 400` 作为状态码，**整个对象**（含 `error`、可能含 `status`）作为响应体 | 权限不足、资源不存在、参数非法等 |
| 4 | `{ rejected: true, ... }` | **HTTP 422**，剥离 `status` 字段后返回其余字段 | 计算输入校验未通过、系统拒绝出数（属正常业务结果，不是异常） |
| 5 | `{ status: 200 \| 201, ...其余字段 }` | `201` → 201；其他数字状态一律按 `200` 返回；响应体**剥掉数字型 `status` 标记** | 成功响应 |
| 6 | 其他对象 / 数组 | `200` 直接返回（数组原样返回） | 大多数查询接口 |

统一说明：

- 除分支 1 外，响应均为 JSON，使用 `JSON.stringify(payload, null, 2)` 两空格缩进，`content-type: application/json; charset=utf-8`，并设置 `cache-control: no-store`。
- 分支 3 的 `status` 字段会随对象一起返回；分支 5 的 `status` 字段被剥离，不会出现在响应体中。
- 未匹配到任何路由时返回 `404`，响应体为 `{ "error": "未找到接口：<METHOD> <path>", "hint": "GET /api/health" }`。
- **身份校验在路由匹配之后、请求体解析之前执行**：除白名单（`GET /api/health`、`POST /api/auth/login`、`POST /api/auth/register`）外的 `/api/*` 若没有有效会话，一律返回 **401** `{ "error": "未认证", "message": "请先登录（POST /api/auth/login）并携带会话令牌（Authorization: Bearer 或 Cookie ccer_session）。", "auth_mode": "…", "login_endpoint": "/api/auth/login" }`；未匹配到路由的请求仍先返回 404，避免用 401/404 的差异探测接口是否存在。

### 静态资源

非 `/api/` 前缀的路径由 `web/` 目录提供（`serveStatic`）：

- `/` 与空路径映射到 `/index.html`；
- 扩展名映射表覆盖 `.html` `.js` `.mjs` `.css` `.json` `.svg` `.ico` `.md` `.csv`，未命中时使用 `application/octet-stream`；
- 路径经 `normalize` 处理并剥离前导 `..` 段；拼接后若不在 `web/` 目录内返回 `403 禁止访问`（纯文本）；
- 文件不存在返回 `404 未找到静态资源：<路径>`（纯文本）；
- 命中时以 `cache-control: no-cache` 输出。

### 示例中的变量

下文 `curl` 示例统一使用 `http://127.0.0.1:8787`，并统一使用上文登录得到的 `$AUTH`（`authorization: Bearer $TOKEN`）作为身份凭据。**注意**：`session` 模式下示例中遗留的 `-H 'x-user-id: …'` 已不再产生任何效果（服务端一律忽略该请求头），仅 `dev` 演示模式下有效。示例中出现的 `$PRJ` / `$MV` / `$CAL` / `$RPT` / `$EVD` 可按下列方式获取，保证示例可直接执行：

```bash
BASE=http://127.0.0.1:8787
UA="$AUTH"   # 见上文「身份识别与会话」的登录示例

# 项目 ID
PRJ=$(curl -s "$BASE/api/projects" -H "$UA" | sed -n 's/^ *"id": "\(PRJ-[^"]*\)".*/\1/p' | head -1)
# 方法学版本 ID
MV=$(curl -s "$BASE/api/methodologies" -H "$UA" | sed -n 's/^ *"id": "\(MV-[^"]*\)".*/\1/p' | head -1)
# 计算运行 ID / 报告 ID / 证据 ID（需先产生相应数据）
CAL=$(curl -s "$BASE/api/projects/$PRJ/calculations" -H "$UA" | sed -n 's/^ *"id": "\(CAL-[^"]*\)".*/\1/p' | head -1)
RPT=$(curl -s "$BASE/api/projects/$PRJ/reports" -H "$UA" | sed -n 's/^ *"id": "\(RPT-[^"]*\)".*/\1/p' | head -1)
```

## 授权模型

服务按**三层**顺序执行授权校验，任何一层拒绝都不会进入下一层：

| 层 | 校验内容 | 实现位置 | 失败响应 |
| --- | --- | --- | --- |
| 第一层：回环限制 | 请求来源必须是 `127.0.0.1` / `::1` / `::ffff:127.0.0.1`，否则需显式设置 `CCER_ALLOW_REMOTE=1` | `server.mjs` 主处理函数，路由匹配之前 | 403 `{ "error": "本服务默认仅允许回环访问，如需内网开放请设置 CCER_ALLOW_REMOTE=1" }` |
| 第二层：角色白名单 | 当前身份的角色必须落在该接口声明的白名单内（`projects.requireRole(user, roles, action)`，返回 `null` 表示通过） | 路由处理函数（新增来源 / 变更告警 / 创建订阅 / 创建项目 / 待审列表 / 门禁模式），以及服务层的来源变更确认、审计日志、审核结论 | 403，错误文案含当前角色中文名与所需角色中文名，例如 `当前角色「只读用户」无权限创建项目（需要：系统管理员 / 政策研究员 / 投资分析师）` |
| 第三层：项目级授权 | `projects.requireProjectAccess(user, projectId, { needManage })`（返回 `{ ok: true, project }` 表示通过） | 路由处理函数（运行历史 / 条件检查历史 / 计算历史与对比）与服务层（`project-svc.updateProjectRegistry`、`project-svc.addEvidence`、`project-svc.upsertFact`、`engine.runMatch`、`engine.runEligibility`、`calc.runCalculation`、`reports.generateReport`；以上七个服务函数均以 `needManage: true` 调用） | 项目不存在 → **404** `{ "error": "项目不存在" }`；非 admin 且非同团队且项目非 `public` → **403** `{ "error": "无权访问该项目（团队或保密等级限制）" }`；`needManage: true` 且角色为 `viewer` → **403** `{ "error": "只读角色不能修改项目数据" }` |

项目级授权在**路由层与服务层双重生效**：即使绕过 HTTP 路由直接调用服务函数（内部调用、测试或后续新增接口），`requireProjectAccess` 依然会执行，两层返回的是同一套 `{ error, status }`。两类失败状态码含义严格区分：

- **404** 只表示「对象不存在」：项目 ID 不存在时返回 `{ "error": "项目不存在" }`；计算运行 ID 不存在时返回 `{ "error": "计算运行不存在" }`（`GET /api/calculations/:id` 与 `GET /api/calculations?a=&b=` 中的 `a`、`b` 任一不存在都是这一条）。
- **403** 只表示「对象存在但无权访问或无权操作」：跨团队 / 非 `public` 项目返回 `{ "error": "无权访问该项目（团队或保密等级限制）" }`；只读角色尝试写操作或触发运行时返回 `{ "error": "只读角色不能修改项目数据" }`。

角色权限范围一览（`needManage: true` 已在全部项目写操作与运行触发中启用，因此只读角色在可见项目内也是**完全只读**）：

| 角色 | 中文名 | 可做什么 | 明确不可做 |
| --- | --- | --- | --- |
| `admin` | 系统管理员 | 全量读取；项目数据不受团队与保密等级限制；新增来源、触发来源同步、确认来源变更、变更告警状态、创建订阅、创建项目、查看审计日志、查看待审列表、切换计算门禁模式、提交审核结论 | — |
| `researcher` | 政策研究员 | 与 admin 相同的业务动作（新增来源、来源同步、确认来源变更、变更告警状态、创建订阅、创建项目、查看审计日志、查看待审列表、提交审核结论）；可查看受限级证据 | 不能切换计算门禁模式（`POST /api/admin/gate-mode` 仅 `admin`） |
| `analyst` | 投资分析师（默认身份） | 创建项目、创建订阅；在项目授权范围内写事实与证据、触发匹配 / 条件检查 / 计算、生成报告；读取项目与运行历史 | 不能新增来源、不能触发来源同步、不能确认来源变更、不能变更告警状态、不能查看审计日志、不能查看待审列表、不能提交审核结论 |
| `reviewer` | 领域复核人 | 查看审计日志、查看待审列表、提交审核结论、变更告警状态、创建订阅；可查看受限级证据 | 不能创建项目、不能新增来源、不能触发来源同步、不能确认来源变更、不能切换计算门禁模式 |
| `viewer` | 只读用户 | 读取本团队或 `public` 项目的项目列表与详情、事实与证据（受限级证据不可见）、条件检查历史、计算历史、报告清单，并可导出报告 | 不能创建项目 / 订阅；不能执行任何项目写操作或运行触发——`PATCH /api/projects/{id}/registry`、`POST /api/projects/{id}/facts`、`POST /api/projects/{id}/evidence`、`POST /api/projects/{id}/match`、`POST /api/projects/{id}/eligibility`、`POST /api/projects/{id}/calculate`、`POST /api/projects/{id}/report` 这七项一律 403「只读角色不能修改项目数据」；不能新增来源与触发来源同步、不能确认来源变更、不能变更告警状态、不能查看审计日志与待审列表、不能提交审核结论、不能切换门禁模式 |

**唯一有意的例外**：`GET /api/admin/plugins` 允许任意身份（含 `viewer`）读取。前端顶栏的门禁模式徽标在任何角色登录时都需要展示当前 `gate_mode`，因此该只读接口刻意不做角色校验；其对应的写接口 `POST /api/admin/gate-mode` 则严格仅限 `admin`。

## 接口总表

共 **45** 个接口（其中 6 个为身份认证与会话接口）。表中「处理函数」指路由处理函数实际调用的服务函数（内联处理即写在 `server.mjs` 中的处理逻辑）；「所需角色」列出角色白名单与项目级授权要求，标「任意」表示该接口不做角色与项目级校验（仍受**回环限制 + 会话校验**约束：除白名单外均需有效会话）。授权规则详见上一节「授权模型」。

| 方法 | 路径 | 处理函数 | 说明 | 所需角色 |
| --- | --- | --- | --- | --- |
| POST | `/api/auth/login` | `auth.loginWithPassphrase` | 登录：以演示口令换取服务端会话令牌（响应体返回 `token` + `expires_at` + `user`，并下发 `ccer_session` Cookie） | **免登录白名单** |

| GET | `/api/auth/me` | 内联处理（`ctx.user` / `ctx.session`） | 当前会话身份与认证模式（`auth_mode` / `dev_mode`） | 任意有效会话 |

### 认证与会话

#### POST /api/auth/login

- **是否免登录**：是（白名单）。
- **请求体字段**：`user_id`（必填，`app_user` 中的用户 ID）、`password`（演示口令，见 `src/data/users.mjs`）。
- **响应字段**：`token`（明文会话令牌，**仅此一次返回**，库中只保存 SHA-256 摘要）、`expires_at`、`user`（`id` / `name` / `role` / `team_id`）、`auth_mode`。响应头附带 `Set-Cookie: ccer_session=…; Path=/; HttpOnly; SameSite=Strict; Max-Age=43200`。
- **错误码**：**401** `{ "error": "用户 ID 或口令不正确" }`（未知用户与错误口令返回同一文案，避免枚举账号）；403（非回环且设置了 `CCER_ALLOW_REMOTE` 时来源不合法）；500。
- **绝不返回**：口令字段（`demo_passphrase`）、令牌摘要。

```bash
curl -s -X POST http://127.0.0.1:8787/api/auth/login \
  -H 'content-type: application/json' \
  -d '{"user_id":"user-analyst","password":"analyst-demo-2026"}'
```

#### POST /api/auth/register

- **是否免登录**：是（白名单）。公开自助注册，只创建**只读账号**，不签发会话；注册成功后由用户自行回登录页登录。
- **服务端固定**：`role = viewer`（`src/services/registration-svc.mjs` 的 `REGISTER_ROLE`）、`team_id` 为普通团队（默认 `team-other`「综合管理组（只读查看）」，不可用时回落 `team-default`）、`active = 1`、`must_change_password = 0`。
- **请求体字段**（严格白名单，仅这 5 个别名）：
  - `username`（必填，或使用别名 `user_id`；两者同时提供时必须一致）：去空白并**统一小写**后校验，规则为「字母开头 + 小写字母/数字/下划线/连字符，3–32 位」，如 `zhang-san`、`analyst_2026`；`admin` / `root` / `system` 等保留名不允许注册。
  - `password`（必填）：复用 `src/core/password.mjs` 的强度校验（长度 ≥ 12、含大写字母、含小写字母、含数字、不能是单一重复字符），长度上限 200；以 **scrypt + 随机盐**哈希入库（`password_hash`，格式 `scrypt$N$r$p$saltB64$hashB64`）。
  - `display_name`（可选，或使用别名 `name`）：1–40 字符，不允许控制字符与 `<` `>`；空白视为未提供，此时 `name` 回落为用户名。
- **响应字段**（201）：`ok`、`user`（`id` / `name` / `display_name` / `role` / `team_id` / `active`）、`message`（提示回登录页登录）、`login_endpoint`（`/api/auth/login`）。**不返回**会话令牌、口令、口令哈希，也不下发 `Set-Cookie`。
- **提权拦截**：请求体出现 `role`、`roles`、`team`、`team_id`、`active`、`enabled`、`is_admin`、`admin`、`permissions`、`grants`、`must_change_password`、`password_hash` 等账号属性时**一律 400 拒绝**（不是静默忽略），错误为 `注册不接受客户端指定账号属性：<字段列表>`。
- **错误码**：**400**（缺少/非法用户名、弱口令、非法显示名、提权字段、未知字段，字段级原因见 `error` / `message` / `issues`）；**409** `{ "error": "该用户名已被占用" }`（唯一性大小写不敏感，既有账号 ID 同样不可占用）；**409**（`CCER_DB_PATH` 指向在用生产库 `data/ccer.db` 时拒绝写入，沿用 v2 写入约束）；**503**（v2 未启用或账号口令字段未迁移）；403（非回环来源）；500。
- **审计**：成功写入一条 `user.register` 审计（`detail` 只含角色、团队与是否设置显示名，不含口令与哈希）。

```bash
curl -s -X POST http://127.0.0.1:8787/api/auth/register \
  -H 'content-type: application/json' \
  -d '{"username":"zhang-san","password":"RegPass2026xyz","display_name":"张三"}'
```

- **路径参数**：`id` = 项目 ID。
- **请求体字段**：`methodologyVersionId`（显式指定方法学版本）、`methodologyId`（按方法学编号取现行正式版本）、`scenario`（默认 `base`，可取 `conservative` / `base` / `optimistic`）、`allScenarios`（真值则依次计算三种情景）、`analysisBaseDate`、`overrides`（情景输入参数，键为插件参数键）、`extraPeriods`（附加计入期数组，用于期间重叠校验）。
- **响应字段（成功，200）**：`project_id`、`methodology_version_id`、`analysis_base_date`、`plugin`（`plugin_key`、`plugin_version`、`title`、`status_note`、`formula_refs`）、`inputs`、`input_origins`（逐输入项来源标注：`kind` 为 `official` / `project_doc` / `owner_claim` / `analyst` / `assumption` / `factor_default` / `plugin_default`）、`factor_snapshot`、`warnings`、`runs`（每项含 `calculation_run_id`、`scenario`、`scenario_label`、`status`、`er_annual`、`crediting`、`steps`、`assumptions`、`missing`、`sensitivity`、`warnings`、`placeholder_factors`、`result`）。数字型 `status` 被剥离。
- **响应字段（拒绝出数，422）**：`project_id`、`methodology_version_id`、`rejected: true`、`calculation_run_id`、`errors`（`field` / `kind` / `message`）、`warnings`、`gate`、`message`。此时**不返回任何减排量数值**，但该次运行仍以 `status = 'rejected'` 落库。
- **错误码**：
  - **404** 项目不存在（来自服务层 `requireProjectAccess`）；
  - **403** 项目级授权不通过：跨团队 / 非 `public` 项目（`{ error: '无权访问该项目（团队或保密等级限制）' }`），或只读角色（`{ error: '只读角色不能修改项目数据' }`）；
  - **404** 找不到可用方法学版本（`未找到可用于本项目的方法学版本…`）；
  - **409** 所选版本非现行正式版本（草案 / 修订征求意见稿）；
  - **409** 该方法学未注册计算插件；
  - **409** 计算插件未通过领域专家校验（`calculator_status !== 'approved'`）；
  - **422** 输入校验未通过 / 严格模式下占位系数阻断 / 计入期重叠（业务结果，非异常）；
  - 403（非回环）；500。
- **说明**：情景输入一律标注为「模型假设」；缺失关键监测数据不猜值；输出绑定分析基准日 + 方法学版本 + 因子快照。服务层 `calc.runCalculation` 自身以 `needManage: true` 执行项目级授权，只读角色被拒。

```bash
curl -s -X POST "http://127.0.0.1:8787/api/projects/$PRJ/calculate" \
  -H 'x-user-id: user-analyst' -H 'content-type: application/json' \
  -d '{"allScenarios":true,"analysisBaseDate":"2025-01-31","overrides":{"ch4_concentration_pct":45}}'
```


## 与设计文档 §8 建议接口的对应关系

设计文档 §8 给出的建议接口为一组不带前缀的概念性路径；实现层统一加 `/api/` 前缀，并按「读取历史」与「触发运行」拆分为独立方法。对应关系如下：

| 设计文档 §8 建议接口 | 实现路径 | 差异说明 |
| --- | --- | --- |
| `/sources/sync` | `POST /api/sources/sync` | 增加 `/api` 前缀；抓取为受控动作，仅 `admin` / `researcher` 可触发（服务层校验），支持 `dryRun` 演练；抓取结果只产生 `source_change` 与 `alert`，**不自动**改动方法学状态或规则卡，须经 `POST /api/source-changes/{id}/confirm` 人工确认。另配套 `GET /api/sources`（任意角色）、`POST /api/sources`（`admin` / `researcher`）、`GET /api/source-changes`（支持 `limit`）、`GET/PATCH /api/alerts`（PATCH 限 `admin` / `researcher` / `reviewer`）、`GET/POST /api/subscriptions`（POST 限 `admin` / `researcher` / `analyst` / `reviewer`）。 |
| `/methodologies` | `GET /api/methodologies`（目录）、`GET /api/methodologies/{id}`（版本详情） | 拆为「目录查询 + 版本详情」两个接口：目录按 `document_status` 分正式 / 草案两栏返回，支持 `status` / `domain` / `keyword` 过滤；版本详情额外返回规则卡、公式、因子与计算插件元信息。草案只作观察项，不列为可申报候选。 |
| `/projects` | `GET /api/projects`、`POST /api/projects`、`GET /api/projects/{id}`、`PATCH /api/projects/{id}/registry` | 列表与创建合并到同一路径的不同方法；创建限 `admin` / `researcher` / `analyst`，列表按团队与保密等级裁剪并支持 `stage` 阶段过滤；详情与注册登记链条更新拆为独立子路径，六个登记阶段与三套减排量数字分列更新、不合并状态；注册登记链条更新为写操作，由服务层以 `needManage: true` 授权，只读角色被拒。 |
| `/projects/{id}/facts` | `GET /api/projects/{id}/facts`、`POST /api/projects/{id}/facts`、`POST /api/projects/{id}/evidence` | 事实的读写拆为 GET / POST；证据单独成 `/evidence` 子资源，并在事实写入时做「严格证据字段必须附证据」与「证据归属项目」校验，因此新增了 400 类错误码。读取按项目团队 / 保密等级授权；写入的两个接口由服务层以 `needManage: true` 授权，跨团队返回 403，只读角色返回 403「只读角色不能修改项目数据」。 |
| `/projects/{id}/match` | `POST /api/projects/{id}/match` | 仅提供 POST 触发（追加式保存运行，不覆盖历史）；最近一次结果通过 `GET /api/projects/{id}/runs` 的 `matches` 读取。返回候选 / 观察项 / 排除项三组，并明确 `scoring_note`：分数仅用于排序，不代表申报成功概率。服务层 `engine.runMatch` 以 `needManage: true` 做项目级授权，跨团队与只读角色均返回 403。 |
| `/projects/{id}/eligibility` | `POST /api/projects/{id}/eligibility`（运行）、`GET /api/projects/{id}/eligibility`（读取） | 拆为触发运行与读取结果两个方法；运行侧由 `engine.runEligibility` 以 `needManage: true` 授权（只读角色返回 403），读取侧由路由层的 `requireProjectAccess` 授权。结论固定为四态枚举，规则结果按通用门槛 / 专属条件 / 冲突标记三层分列，冲突项只标记不自动判不合格。 |
| `/projects/{id}/calculate` | `POST /api/projects/{id}/calculate` | 增加三种情景一次性计算（`allScenarios`）与期间重叠校验；校验未通过时以 **422** 明确「拒绝出数」并落库 `rejected` 运行。服务层 `calc.runCalculation` 以 `needManage: true` 做项目级授权。另新增 `GET /api/projects/{id}/calculations`、`GET /api/calculations/{id}`、`GET /api/calculations?a=&b=`（两次运行差异对比与解释：`a`、`b` 须同时存在且属于同一项目，跨项目对比返回 400，均按运行所属项目授权），以满足「历史不静默改写、差异可解释」的要求。 |
| `/projects/{id}/report` | `POST /api/projects/{id}/report`、`GET /api/projects/{id}/reports`、`GET /api/reports/{id}/export` | 生成、版本列表、导出拆为三个接口；生成时以 `needManage: true` 做项目级授权（只读角色被拒），并自动串联条件检查与三情景计算，以 `revision` + `supersedes_id` 保留版本链；导出支持 `markdown` / `html` / `doc`（Word）/ `xls`（Excel）/ `csv` 五种格式并记审计；其中 `doc` 与 `xls` 为带 Office 命名空间的 HTML，Word / Excel / WPS 可直接打开。 |
| `/reviews` | `POST /api/reviews`、`GET /api/reviews/pending` | 提交结论与待审清单拆为两个方法；待审清单限 `admin` / `researcher` / `reviewer`，`POST` 除写入 `review_decision` 外还会回写被审对象的审核状态字段。 |

此外，实现层还提供设计文档 §8 未列出的支撑接口：`GET /api/health`、`GET /api/dashboard`、`GET /api/users`、`GET /api/meta/fact-fields`、`GET /api/meta/standard-codes`、`GET /api/audit`（限 `admin` / `reviewer` / `researcher`）、`GET /api/admin/plugins`（任意身份可读，唯一有意的例外）、`POST /api/admin/gate-mode`（仅 `admin`）。设计文档中的删除类操作未实现任何 `DELETE` 接口。

## 结论可追溯性字段

设计文档要求「所有结论返回 source_ids / rule_version / unknown 原因 与运行时间」。实现层不使用单一的 `source_ids` 字段名，而是按对象类型展开为下列**实际字段**，其语义等价物如下：

| 追溯维度 | 实际字段名 | 出现位置与语义 |
| --- | --- | --- |
| 规则版本 | `rule_version` | 每条规则判断结果（`layers.common` / `layers.specific` / `layers.conflict` 的元素）与报告 `body.condition_checks`、`traceability.rule_versions`；取值为该规则所属的 `methodology_version_id`，通用门槛规则固定为字符串 `common` |
| 判断时间 | `judged_at` | 每条规则结果与报告 `traceability.rule_versions`；ISO 8601 时间戳，标明该条判断的判定时刻 |
| 证据定位 | `evidence` | 每条规则结果与报告 `body.condition_checks`；对象 `{ evidence_id, file_name, doc_type, page, line_ref, excerpt }`，无证据时为 `null`；证据受限时项目事实中表现为 `evidence_blocked: true` |
| 条款引用 | `clause_ref` | 每条规则结果与报告 `body.condition_checks`；规则卡对应的官方文件条款号，未登记时为 `null` |
| 缺失字段 | `missing_fields` | 条件检查 `layers.*[].missing_fields`、`summary.unknown_list[].missing_fields`；导致该条判断为「待核实」的字段键数组 |
| 未核实原因 | `unknown_reasons` | 条件检查 `layers.*[].unknown_reasons`、`summary.unknown_list[].reasons`；`{ field, reason }` 去重列表，逐项说明为何无法判定 |
| 分析基准日 | `analysis_base_date` | 匹配、条件检查、计算、报告四类结果均带；所有判断与测算均绑定该基准日，库更新不静默改写历史结论 |
| 运行时间 | `run_at` | 匹配运行、条件检查运行、计算运行；运行落库时刻（同时报告内有 `generated_at`） |
| 匹配运行 ID | `match_run_id` | `POST /api/projects/{id}/match` 返回体、条件检查结果及其 `match_snapshot.match_run_id`、报告 `snapshot` 与 `traceability.runs`（`match_run` 表主键） |
| 条件检查运行 ID | `eligibility_run_id` | `POST /api/projects/{id}/eligibility` 返回体、报告 `snapshot` 与 `traceability.runs`（`eligibility_run` 表主键） |
| 计算运行 ID | `calculation_run_id`（单个）/ `calculation_run_ids`（数组） | 计算接口 `runs[].calculation_run_id`；报告内聚合为 `snapshot.calculation_run_ids` 与 `traceability.runs.calculation_run_ids` |

配套的可追溯信息还包括：

- **来源分层标注**：报告 `one_page` / `body` 中的每条陈述均为 `{ label, text, ...extra }` 结构，`label` 取值 `官方已确认` / `项目资料记载` / `项目资料记载（业主自述，未经官方核实）` / `分析师推断` / `模型假设` / `模型假设（方法学缺省值待确认）` / `待核实`，等价于「置信度或未核实原因」的表达；条件检查项另有 `fact_source_kind` 与 `fact_source_label`。
- **因子与输入快照**：计算结果带 `factor_snapshot`（`factor_key`、`value`、`unit`、`source_ref`、`source_year`、`value_status`）、`input_origins`、`placeholder_factors`，落库字段为 `inputs_json` / `result_json` / `factor_snapshot_json`，历史运行不因因子库更新被改写。
- **证据索引**：报告 `traceability.evidence_index`（`field_key` → `evidence_id`）与 `traceability.methodology_version_id`。
- **审核留痕**：`calculation_run.audit_status` / `review_status`、`eligibility_run.review_status`、`report.status`，以及 `review_decision` 与 `audit_log` 记录（actor、actor_role、action、object_type、object_id、detail、result、时间）。

## 错误处理

服务在主处理函数外层统一 `try / catch`：任何未被业务层捕获的异常都会记录到服务端标准错误（形如 `[ISO 时间] <METHOD> <path> 处理失败：` 加异常对象），并返回 **500**：

```json
{
  "error": "服务端处理失败",
  "message": "<异常消息>",
  "path": "<请求路径>",
  "trace": ["<堆栈前 4 行>"]
}
```

字段含义：

- `error`：固定文案「服务端处理失败」，便于前端统一识别；
- `message`：异常自身的 `message`，无法取得时退化为 `String(e)`；
- `path`：发生异常的请求路径（不含查询串）；
- `trace`：异常堆栈按换行切分后的前 4 行数组（`String(e.stack).split('\n').slice(0, 4)`），仅保留主调用链，避免泄露完整堆栈。

需要注意的边界（按主处理函数的执行顺序）：

- **回环限制失败**发生在路由匹配之前，返回 **403** `{ error: '本服务默认仅允许回环访问…' }`；
- **路由匹配失败**返回 **404** `{ error, hint }`；
- **请求体解析异常（超 32 MB、非法 JSON）** 在业务 `try` 块**之外**单独捕获，返回 **400** `{ "error": "请求体解析失败", "message": "请求体过大（超过 32 MB）" | "请求体不是合法 JSON" }`，不会进入业务处理，也不会表现为 500；
- **业务错误**不走 500，而是由处理函数返回 `{ error, status }`，经响应规约分支 3 以 `out.status || 400` 输出，因此 403 / 404 / 409 等状态码由授权助手（`requireRole` / `requireProjectAccess`）与各服务函数自行指定；
- **计算拒绝出数**属正常业务结果，走分支 4 固定返回 **422**，携带 `errors`、`warnings`、`gate` 与 `calculation_run_id`，且不提供任何减排量数值；
- 以上三条前置分支（回环、路由、请求体）都发生在业务 `try` 之外，只有**业务处理期间的未捕获异常**才会走上面的 500 通道。

## 附：本轮新增与变更的接口（首轮检查整改）

本节记录首轮检查整改（见 [14-首轮检查整改对照.md](./14-首轮检查整改对照.md)）新增与变更的接口。
前文的接口总表已包含它们；此处补充其业务语义，便于与整改清单对照。

### POST /api/auth/login · POST /api/auth/logout · GET /api/auth/me

身份改为**服务端会话**。令牌由服务端签发，库中只保存 SHA-256 摘要。
`session` 模式下 `x-user-id` 与 `?user=` **一律忽略**——这是对「客户端可自报管理员」漏洞的修复。
`dev` 模式（须显式开启，且与 `CCER_ALLOW_REMOTE=1` 互斥）才保留旧行为，并在启动时打印告警横幅。

### GET /api/admin/sessions · DELETE /api/admin/sessions/:id

会话管理，仅 `admin`。列表**不含** `token_hash`。

### GET /api/admin/demo-channel　（替代原 GET /api/admin/plugins 的门禁字段）

返回门禁状态与每个方法学的业务测算可用性：

- `demo_channel_enabled` / `enabled_by` / `enabled_at`：演示通道状态；
- `calculator_gate_mode`：默认 `strict`；
- `plugins[]`：每个插件的 `calculator_status`、`placeholder_factors[]`、
  `formulas_without_clause[]`、`business_calculation`（可出数 / 禁止出数）、`demo_channel`。

**判据以数据库为准**（`factor_version` / `formula`），不读插件模块里的静态声明——
否则管理后台的审批无法生效，会出现「已审批但仍拒绝出数」的死锁。该缺陷已在整改中修复。

### POST /api/admin/demo-channel　（替代原 POST /api/admin/gate-mode）

**仅 admin**。请求体 `{ enabled: boolean, note?: string }`。
开启后仍不产生可用于投资筛选报告的数字：演示运行标记为 `demo`，不进入报告、不可导出。

### POST /api/admin/methodology/:id/approve

**仅 admin / reviewer**。请求体
`{ target: 'rulecard'|'calculator', decision: 'approved'|'rejected'|'pending_review', comment? }`。

**防呆**：当 `target = 'calculator'` 且 `decision = 'approved'` 时，若该方法学仍有占位系数
或仍有缺条款页码的公式，直接返回 **409**，并在 `detail` 中列出
`placeholder_factors[]` 与 `formulas_without_clause[]`。
也就是说，**无法靠点一下「批准」绕过未确认的系数**。

### POST /api/projects/:id/calculate　（请求体与返回扩展）

请求体新增：

| 字段 | 说明 |
|---|---|
| `channel` | `'business'`（默认）或 `'demo'` |
| `eligibilityRunId` | 业务测算必须绑定同一项目、同一方法学版本、同一分析基准日的条件检查快照 |

新增响应码：

| 码 | 含义 |
|---|---|
| **409** | 业务前置条件未满足（`rejected:true`、`kind:'precondition'`）：审批未通过 / 含占位系数 / 缺条款页码 / 无条件检查快照 / 快照版本或基准日不一致 / 存在硬障碍 |
| **422** | 输入校验未通过（单位错误 / 超范围 / 期间重叠），与整改前一致 |

成功响应新增 `channel` / `demo` / `usable_for_report` / `gate_reason` / `eligibility_snapshot`；
每个 `runs[]` 带 `status`（`ok` / `demo`）与 `usable_for_report`。

|---|---|
