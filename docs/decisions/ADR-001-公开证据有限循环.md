# ADR-001：公开资料采用有界证据补全循环

## 状态

已采用（2026-09-30），先在本地验证，云服务器暂未更新。

## 背景

平台原有每日任务已按政策、方法学、公开项目、交易、研报与动态采集并调用模型核验，但“证据不足”不会自动变成下一轮定向补采。内容检索每天固定截取前 12 个关键词，使后列主题长期得不到覆盖。本地预览还曾使用仅校准模式，未运行完整采集。

## 决策

1. 每日检索先覆盖所有主题，再轮换同义词；保留搜索 API 的单日限额。
2. 每日初轮采集和核对后，最多运行两轮证据补全，每轮默认最多处理 8 个对象。可用 `CCER_EVIDENCE_LOOP_ROUNDS`（上限 3）和 `CCER_EVIDENCE_LOOP_ITEMS`（上限 30）降低资源占用。
3. 补全动作只针对有明确公开来源的缺口：文章原始链接缺全文、政策原件缺归档、官方交易日缺行情，以及初轮失败后可重试的注册登记项目。方法学只在官方原件或编号缺失且初轮确实有进展时续采。
4. 新来源快照、原件归档、正文版本或官方字段确有增加，才重新运行规则和模型核验；没有新证据立即停止。搜索摘要和模型推断不算新证据。
5. 来源仍不足或来源互相冲突时保持“证据不足 / 来源冲突 / 未核实”。循环不自动改写官方数值，不把转载当成独立证实，也不创造人工审核任务。
6. 演示项目不参与公开项目缺口核对。本地原有 6 条项目差异均来自 3 条演示条目，已按此口径结清并保留历史。

## 取舍与限制

- 有界循环降低搜索、抓取和模型费用，也适合当前小规格 ECS；代价是无法保证单日补齐所有历史缺口。
- 政策和方法学的官方前端渲染页、受限接口仍可能无法取得正文；此时必须保留缺口。
- 仅补到原文不代表交叉验证完成。需要第二个独立来源的内容仍标为“证据不足”；下一阶段可引入来源独立性识别与双来源引文校验。
- 每次循环的进展和停止原因写入每日任务明细与审计记录，便于定位配额、抓取或来源问题。

## 验证

`test/28-v2-evidence-loop.test.mjs` 使用独立临时数据库覆盖关键词分配、演示项目排除、全文补采、摘要不得升格、无证据立即停止、轮数上限和每日任务接线。本地真实抓取连接已完成单条文章的全文补采与重新核验；该条因缺第二来源仍保持“证据不足”。
