# ADR-004：信息治理、历史补采、方法学版本与统一检索

日期：2026-10-21。状态：本地已实现并测试；未部署、未访问云端、未推送 GitHub。依据：`docs/74-信息治理与统一检索开发要求.md`；2026-10-21 按 `docs/76-跨资料处理闭环补齐要求.md` 扩展跨资料逐条阶段与每日统一调度，验收见 `docs/77`。

## 背景

平台已有 SQLite、公开内容采集、搜索/抓取连接、摘要、自动核验、政策/方法学/公开项目/CEA/因子/企业名录和管理员维护链路。本轮需要在不引入大型搜索引擎、容器或新依赖、兼容 2 核 2GB 云服务器的前提下，补齐：

1. 采集到核验的五阶段可查询状态、有界重试与每日补处理；
2. 按来源/日期窗口的历史补采，带任务/窗口/页游标与暂停恢复；
3. 方法学版本时间线、差异与有证据的版本关系；
4. 跨政策、方法学、项目、研报、CEA、因子、企业名录的统一检索。

现有 `content_item.updated_at` 同时会被正文更新和核验回写修改，不能用它单独判断摘要/核验是否新鲜；现有 `supersedes_id` 和 `auto_verify_status` 也不能单独构成已确认关系。

## 决策（实际采用）

### 1. 增量 SQLite schema，不新增搜索引擎/队列/运行时

新增 `src/db/schema-governance.sql`，只在 `CCER_ENABLE_V2=1` 时随既有 `migrate()` 幂等执行：

- `processing_stage`：`(object_type, object_id, stage)` 主键，保存状态、输入哈希/版本、来源定位、完成时间、失败原因、尝试次数、下次重试时间；
- `governance_lease`：`lease_key='collection'` 的单实例租约；
- `backfill_task` / `backfill_window`：任务、日期窗口、页游标与累计计数；
- `methodology_version_relation`：候选/确认关系及原文 URL、定位、逐字引文、核验依据；
- `methodology_version_diff`：五个维度的差异与来源定位。

迁移标记为 `schema_version_governance_applied`，`schema_version` 保持 2.7.0（沿用省域地图增量的做法），重复执行安全；不修改任何既有表、列或数据。

### 2. 阶段状态与摘要/核验新鲜度

- 阶段白名单从 `content_item` 扩展到 `policy_document`、`methodology_version`、`cea_document`、`accounting_standard`、`accounting_public_document`、`public_project`；公开项目不适用下载/解析，阶段写 `skipped`，不把结构化项目当 PDF。
- 摘要新鲜度不再看 `generated_at` 与 `updated_at` 的先后，而是调用只读的 `summary-svc.getSummary()`，按**实际输入哈希 + 提示词版本 + 模型键**判断；政策/方法学/项目/CEA 核验按 `objectVerificationInput()` 的当前策略/模型/证据/正文签名与 `verification_result.input_hash` 比对，碳核算两类复用 `accounting-evidence-svc` 的同一正文/著录签名。不使用可变的 `auto_verify_status`，也不因时间戳较新就接受旧正文签名。
- `syncContentStages` 保留为 content 兼容包装；`syncObjectStages` 是跨类型读路径。已有未来重试时间时保留退避与尝试次数；只有当前输入哈希相对该阶段已记录值再次变化，才把摘要/核验重置为 stale 并清零尝试次数，避免“每次刷新都重置退避”。
- 每日任务与后台补处理复用 `summary-svc` / `verification-svc` / `accounting-evidence-svc`，不另写 AI 判断。未配置模型/凭据写 `blocked`（unavailable），绝不写 `verified`；公开项目只有元数据时摘要限定公开字段，核验维持 `insufficient`。

### 2.1 跨类型有界 worker 与每日统一调度

- 后台/每日只通过 `governance-svc.processPending` 处理摘要与核验；类型按轮转取队列，受全局 `limit`、`budget_ms`、`max_attempts` 与退避约束。`sync:false` 仅供测试/受控调用，默认仍先同步真实阶段。
- 摘要批次复用 `summary-svc.runSummaryBatchExclusive` 的全局单并发锁；核验复用既有四态与缓存键。没有适配器的类型写 `blocked`，不把“未支持”写成完成。
- 每日链路调用 `runDailyGovernance`，按自动核验策略 scope 决定哪些类型可核验；不再直接调用 `refreshAfterDaily` / `verifyAllBatch` 旁路无限重试。旧公开 API 保留，供既有调用方使用。
- 后台列表/详情/重试全部显式携带 `object_type+object_id`；上传链接落到既有 `document-upload`（政策/方法学/CEA）或碳核算上传页（标准），编辑链接落到既有覆盖层维护并预选实体。

### 3. 单实例租约

每日任务、后台治理批次、历史补采共用 `governance_lease('collection')`。只有不存在租约或已过期才能获取；默认 TTL 15 分钟，不抢运行中的活任务。进程中断后租约过期，任务从持久化游标恢复。

### 4. 历史补采

- 任务只支持公开内容（研报/动态等）；其它资料类型在界面明确列为不支持统一日期补采。
- 搜索连接必须具备可验证的日期能力：
  - `start_field`/`end_field`（Tavily 等），或
  - `freshness_field` + `freshness_range`（博查 `YYYY-MM-DD..YYYY-MM-DD`）。
- 备用通道除日期能力外，还要求与任务一致的分页语义；不具备同等能力的连接不参与回退，避免把“最近结果”伪装成日期范围结果。
- 结果按真实 `published_at` 二次过滤；未知发布日期保留 NULL 并单列计数，不默认成窗口日期。
- 正文只来自实际抓取或搜索连接直接返回的原文；搜索摘要只作为摘要/元数据。
- 任务与每个窗口的 `cursor_page` 每页结束即落库；失败页不前进，重试从失败页继续；已完成页不重复调用。
- 暂停/继续/取消/失败重试/重启恢复都有持久化状态；“完成”只表示计划窗口已处理。

### 5. 方法学版本

- 时间线由既有正式/草案字段和已确认关系派生，不按编号相邻推断。
- 关系必须同时满足：白名单类型、http(s) 原文 URL（精确 origin+path）、段落/页码定位、逐字引文能在**该 URL 对应的同一版本正文**中定位且包含相应关系语义、该来源版本存在输入签名与**当前**版本字段/正文/策略/模型一致的 `verification_result` verified 记录。否则保持 candidate，界面明确待核实。可变 `auto_verify_status`、时间较新的旧签名、另一版本的引文都不构成确认依据。
- 差异按适用范围、边界、关键参数、计入期、监测要求确定性比较；每条带字段/正文段落定位；取不到证据写“无法比较”。
- 旧 `calculation_run` 的 `methodology_version_id`、`inputs_json`、`factor_snapshot_json` 只读保留，新版本/差异计算不改写旧结果。

### 6. 统一检索

- 使用 SQLite 有界 `LIKE` + JS 相关度/日期稳定排序，不启用 FTS5（中文分词与索引体积/迁移风险不值得在 2 核 2GB 上引入）。
- 七个公开实体白名单：政策、方法学、公开项目、研报动态、CEA 文件、排放因子、企业名录；表名/列名固定，参数化查询；不查询用户、账号、审计、配置、密钥或任务表。
- 类型/来源/日期/地区筛选只作用于支持该字段的类型，不适用时明确说明并保留其它类型；演示、转载副本、来源归档、失败抓取默认排除。公开项目按官方登记编号去重、阶段取并集（复用总览口径），阶段中文化；项目核对日与企业名录截止日分列标注。
- 单类型扫描上限 400，分页 offset 上限 200；总数只声称分页预算内可达的部分，超出用 `truncated/pagination_truncated` 标记，不显示翻不到的页。
- 前端高亮先按关键词切分、再逐段 `esc()`；不把标题/摘要作为 HTML 注入。
- 顶栏提供入口，`#/search` 为独立页；为保持既有 8 个一级模块的验收契约，不新增第 9 个主导航。

## 替代方案与拒绝理由

1. **SQLite FTS5**：中文短词/组合词可用性需要额外分词与索引维护；在 2 核 2GB 上增加索引体积和迁移复杂度，且现有实体字段差异大。选择有界 LIKE + 二次排序。
2. **外部任务队列/容器/搜索引擎**：违反“不新增大型搜索引擎、容器或无必要依赖”的约束。
3. **把五阶段做成 content_item 的 5 组列**：字段爆炸、无法统一尝试/退避/游标；选择独立阶段表。
4. **只用进程内锁**：多入口（每日/后台/补采）和进程重启无法共享；选择 SQLite 租约。
5. **把历史补采做成一次性同步循环**：云端 60 秒超时、重启丢失；选择持久化窗口/页游标 + 后台异步步进。
6. **以 `auto_verify_status`/`supersedes_id` 直接确认关系**：可变状态和旧字段不能证明当前正文；选择证据 + 当前核验。
7. **新增第 9 个一级导航**：会破坏既有 8 模块验收；选择顶栏检索表单 + 独立路由页。

## 后果与限制

- 逐条五阶段已覆盖研报动态、政策、方法学版本、CEA 文件、标准规范、公开资料/问答与公开项目；公开项目的正文获取/解析不适用，阶段为 `skipped`。排放因子、交易行情、企业名录仍是既有确定性/结构化治理，不声明为 PDF 五阶段完成。
- 历史补采只支持公开内容；日期/分页能力完全取决于真实连接声明。没有真实连接或凭据时，预览会显示阻塞，创建被拒绝。
- 未自动调用大模型提取版本关系；提供受保护的候选关系提交接口，确认仍由确定性证据规则完成。
- 版本差异的证据定位是字段/正文段落，不虚构 PDF 页码；只有来源本身提供页码/定位时才可能显示页码。
- 统一检索的总数与分页受扫描/offset 预算约束，超出部分明确截断。
- AI 问答继续复用 `retrieval-svc` 的实体证据（含企业名录）与逐字引文校验；它与统一检索共享实体 ID/来源契约，但不是同一个 HTTP 端点。库内来源查询失败会通过 `source_errors` 暴露，不再静默当成“没有公开信息”。
- DSH 没有使用真实联网、真实模型或真实搜索凭据；Codex 独立做了最小真实 smoke（博查日期区间 1 条结果、已配置 LLM 摘要调用、政策核验 verified/5 条有效引用），详见 `docs/75` 7.4。该 smoke 不等于完整历史补采/全量检索验收。
- 浏览器截图受当前沙箱命名管道限制未由 DSH 生成；Codex 已独立用浏览器检查搜索并发现项目统计/阶段/日期口径问题，本轮已修复。视觉与交互仍需在可控浏览器环境最终复核。
- 未部署、未访问云服务器、未推送 GitHub；未修改 `data` 下现有数据库、账号或服务配置。
