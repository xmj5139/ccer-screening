# ADR-008：第三阶段语义扩展、企业档案与第三方行情候选的轻量实现

日期：2026-10-29。状态：第三阶段本地实现并完成定向隔离测试；未部署、未读取密钥、未调用真实付费模型、未推 Git。依据：`docs/86-公开信息智能化三阶段开发设计.md`；实施记录：`docs/89-公开信息智能化第三阶段实施记录.md`。

## 背景

第二阶段已交付 FTS5 中文索引、用户关注与 PDF 表格 worker，但独立回归暴露：末批清理只看本批 `seen` 会删前批索引；每日从 offset=0 重复扫描导致旧 ID 更新不可见；查询只读缓存 payload，源表/管理覆盖层变化后可能返回旧内容。第三阶段又在同一 Node/SQLite、零 npm 依赖、现有八模块绿色 UI、公开资料和权限边界内增加语义扩展、企业档案与第三方行情候选。约束不变：不读密钥、不真实付费调用、不部署、不推 Git；测试只用临时库。

## 决策

### 1. 用 SQLite 触发器 dirty 队列 + 有界消费，拒绝“查询全库重建”

- 新增 `search_index_dirty(type, entity_id, reason, queued_at)`；政策/方法学/项目/内容/CEA 文件/因子/企业名录源表与 `admin_revision` 的 insert/update/delete 均入队；
- 查询只在索引 ready 时消费最多 25 条 dirty；单实体刷新成功即出队；仍有剩余 dirty 时回退 legacy，并返回 `fallback_reason=index_dirty` 与剩余数；
- 每日批次使用 `cursor:<type>` 旋转游标，不再从 0 重复扫描；后台仍可显式 offset；
- 类型完整处理时以 `sourceIds(type)` 全量合法 ID 集合清理，不再用本批 `seen`；
- 迁移时对既有公开记录入队一次（带 `search_dirty_seeded_v3` 标记），之后完全由触发器维护；
- legacy 回退的 WHERE 同时匹配 active `admin_revision` 公开字段，取回后再合并覆盖层；索引未建/损坏也不显示覆盖前旧标题。

**拒绝**：每次查询全库重建；查询直接返回缓存 payload 并标一个无法验证的“fresh”；只靠每日全量扫描；用 `seen` 做末批删除。

**代价**：批量源数据变更后，检索可能先回退 legacy 数轮；末批全量 ID 清理比单页查询重，但不在每次查询执行。

### 2. 语义扩展用真实聊天模型单次严格 JSON，不冒充 embedding

- 显式 `POST /api/v2/search/semantic` 才调用一次结构化模型；`maxRetries:0`；严格 JSON、最多 4 词、单词 40 字符、查询 100 字符；
- 精确 CCER/方法学/登记编号短路为 keyword，不调用模型、不消耗模型配额；
- 原查询始终保留，FTS MATCH 用 `(原查询) OR (扩展词...)`；类型/地区/年度/来源/日期筛选原样传递；
- 模型失败/超时/无 provider/限流回退原检索，`mode=fallback`；正常 `semantic_expansion`；精确 `keyword`；
- 每用户每分钟 4 次、每日 40 次、平台每日 400 次；配额与查询/扩展词/模型/延迟落库留痕。

**拒绝**：每次列表 GET 自动调用模型；用哈希向量/静态同义词冒充 embedding；用模型覆盖类型/地区/年度筛选；模型失败时返回空结果或伪造扩展词。

**代价**：扩展词仍可能不相关，必须回原文核对；本轮不引入 sqlite-vec/embedding 服务。

### 3. 企业档案用来源明确的身份键，不按名称相似度合并

- 有信用代码：按信用代码跨年度聚合；无代码：按“名称 + 省份 + 城市”聚合；同名跨地区不合并；
- 异常信用代码：标准 `credit_code` 留空，原始值只进 `raw_credit_code`，企业名称照常入名录；
- 多行业/多年度关系存 `cea_entity_membership`，逐来源保留；历史变化存 `cea_entity_revision`；别名存 `cea_entity_alias`，管理员补充需来源并写审计；
- 档案返回年度/行业/地区/来源/修订/正文提及；`emissions` 明确为 null，不推算企业实际排放。

**拒绝**：同名跨地区强合并；异常代码猜测补齐或整条剔除；用名录数量/国际估算推企业排放；把正文提及当官方隶属关系。

### 4. 第三方行情候选独立成表，CEA/CCER 分表核对，官方零改写

- 候选写 `market_candidate_import` / `market_candidate_row`；`cea_trade_daily` 与 `trade_daily` 只读；
- CEA 对 `cea_trade_daily`；CCER 对 `trade_daily` 按 `market='CCER'`、日期汇总交易方式，缺字段保持 NULL 不当 0；
- 其它标的、未来交易日、交易日晚于来源 as-of → unsupported；严格正数/有限数/日期/单位/字节/行数限制；
- 1 吨真实差异使用严格绝对容差保留为 conflict，不用 0.5% 相对容差吞掉；
- `stale` 第三方标志保留；CSV 导出复用公式注入防护；viewer 无诊断/导入权限。

**拒绝**：候选直接 upsert 官方行情；只查 CEA 表导致已有 CCER 被误报 missing；缺字段当 0；用均价补收盘价；相对容差吞小差异。

## 依赖与许可

- 运行时仍为零 npm 依赖；
- 不新增 Python/Node 依赖；沿用 `trafilatura==1.12.2`（Apache-2.0）、`pdfplumber==0.11.9`（MIT）；
- 不安装重模型；真实 DeepSeek 验收由主 Codex 用既有凭据执行，DSH 不读取密钥/不付费调用。

## 后果

- 索引新鲜度由“触发器 + 有界消费 + 旋转游标 + 全量清理”保证；大量变更期间可能短暂回退 legacy；
- 语义扩展是可选显式动作，有配额与留痕，失败不丢原检索；
- 企业档案保留来源与历史，但不提供排放或官方关系判断；
- 第三方候选只做差异报告，官方行情表零改写；
- 真实模型、浏览器、云端迁移/发布由主 Codex 独立验收。
