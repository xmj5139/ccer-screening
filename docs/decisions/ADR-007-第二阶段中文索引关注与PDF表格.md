# ADR-007：第二阶段中文索引、关注订阅与 PDF 表格的轻量实现

日期：2026-10-29。状态：第二阶段本地已实现并完成隔离测试；未部署、未读取密钥、未调用真实付费模型、未推送 GitHub。依据：`docs/86-公开信息智能化三阶段开发设计.md`；实施记录：`docs/88-公开信息智能化第二阶段实施记录.md`。

## 背景

第一阶段已具备正文清洗、版本/附件指纹、字段引句证据与 RSS 候选，但统一检索仍是单类型最多 400 条的 LIKE 扫描，旧记录可能被日期预算遗漏；用户关注只存在内部雷达订阅，没有普通用户级规则/已读；PDF 只有逐页文本/OCR，没有表格行列解析。约束仍是 Node 24 + 内置 SQLite、零 npm 运行时依赖、2 核 2GB、公开资料、现有八模块导航与绿色设计、增量迁移、不得读密钥/部署/真实付费调用。

## 决策

### 1. 用 SQLite FTS5 + 预切分，不引入外部搜索引擎

- `search_index_doc` 保存公开实体 payload、过滤列、来源 hash；`search_index_fts` 是外部内容 FTS5 表，触发器同步；
- 管理覆盖层（`admin_revision`）只读合并进索引 payload，不 UPDATE 业务表；覆盖层变化改变 hash，下次重建更新；
- 中文连续串预切为双字词并在串尾补单字；英文/编号保留 `-_.` 并补 compact；查询 token 加引号，MATCH 参数化；
- 查询只 JOIN 索引表，`COUNT` 为真实总数；分页 offset 上限 10000；
- 索引可重建、按 payload hash 增量；后台有限批次，每日仅在已完整构建时增量 300 条/类型；
- 索引未构建/损坏/查询失败回退 legacy，返回 `mode/fallback_reason`，不把失败当无结果。

**拒绝**：每次查询全库重建；引入 Elasticsearch/Meilisearch（部署/内存/运维不匹配）；用 LIKE 扫描把 400 条预算说成真实总数。

**代价**：content 入库/更新在索引完整后即时单条刷新，其它公开类型仍需每日/后台批次；索引未完整构建时检索回退 legacy。已在状态与文档中如实说明。

### 2. 关注规则用独立用户表，事件组合并不删除来源

- `user_follow_rule` 以 `user_id` 为所有权键；服务层每次保存/更新/删除/按规则读取都校验归属；
- 同规则内字段 AND、同字段多值 OR；地区/行业只是正文或元数据提及；
- 信息流扫描最近 300 条公开内容，事件组（同文不同 URL）合并展示但 `sources` 逐条保留；
- `user_follow_read` 以 `(user_id, content_item_id)` 为主键，保存读取时正文 hash；正文实质变化后自动重新未读。

**拒绝**：把关注规则写入全局 radar 订阅（普通用户越权/无法隔离）；为关注新增一级导航；默认发邮件/第三方消息。

### 3. PDF 表格用本机 pdfplumber 独立进程，不用常驻重模型

- `scripts/pdf-table-worker.py` 由 Node 以无管道方式异步启动，单并发、超时 kill；
- 输出物理页码（1 起）、表序号、行列（0 起）、单元格文本、成功/失败页；
- 文件 ≤20 MB、页数 ≤500、输出 ≤16 MB、表格/单元格上限；realpath 后只允许受限原件根；
- Node 计算 `coverage=pages_processed/pages_total`，区分 `page_limit/page_failures/no_text_layer_or_tables/timeout/...`；
- 扫描/空白页只标 `empty/no_text_layer`，`zero_enterprises_claim_allowed=false`；失败保留原件与既有正文。

**拒绝**：Docling/重模型常驻（云端内存不足）；把扫描空页当“零家企业”；把远程空接口报告为可用解析后端；允许任意路径/../符号链接。

**代价**：不 OCR 扫描页；53 页全量可能较慢，后台请求内同步等待，需页数/超时限制。

### 4. 第一阶段日期/阈值/提及修正作为硬语义门槛

- 发布日期必须有`发布日期/发布时间/生成日期/印发日期/发布于`等明确标签；纯落款、`日期+印发/发布`拒绝；
- 生效日期必须有`施行日期/实施日期/生效日期`或`自……起施行/实施/生效`；
- 阈值必须同时核对数字附近单位与方向；`低于8%` 不支持 `8吨`/`高于8%`；
- 地区/行业字段 `mention_only=true`，页面与模型提示词明确“非官方适用范围”。

**拒绝**：仅凭相同数字接受阈值；把页面标题/文末落款当发布日期；把地区/行业提及当适用范围。

## 依赖与许可

- 运行时零 npm 依赖；
- `trafilatura==1.12.2`（Apache-2.0，第一阶段可选）；
- `pdfplumber==0.11.9`（MIT，第二阶段可选；Codex 已安装，本轮未重装/未联网）；
- 不安装/不调用重型模型；未部署、未读取密钥、未推 Git。

## 后果

- 检索需要一次完整构建后才进入 `mode=fts5`；未构建时按设计回退 legacy；
- 关注信息流是最近 300 条的站内窗口，不是全历史推送；
- PDF 表格结果需要回原件核对，扫描件仍需 OCR/人工；
- 真实联网、真实模型、浏览器/云端验收由 Codex 独立执行。

## 第三阶段修订（2026-10-29，取代本 ADR 第 1 节的部分实现细节）

独立回归证明“每日 offset=0 增量 + 查询只读 payload”不足以保证新鲜度。第三阶段改为：

- `search_index_dirty` 源表/`admin_revision` 触发器入队；查询只做最多 25 条有界消费，剩余 dirty 时如实回退 legacy（`fallback_reason=index_dirty`），不把旧 payload 当最新；
- 每日批次使用 `cursor:<type>` 旋转游标，旧 ID 更新可被轮转刷新；
- 类型完整处理时用全量合法来源 ID 集合清理，不再用本批 `seen` 删除前批索引；
- PDF worker 可用性不再硬编码 `available:true`，改为“未探测/最近一次真实任务”判断；`coverage` 在 UI 明确写“页处理率”，不是正文完整率。

详见 `docs/89` 与 `ADR-008`。
