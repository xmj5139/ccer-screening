# ADR-006：公开信息智能化的轻量实现与可选依赖

日期：2026-10-29。状态：第一阶段本地已实现并完成隔离测试；未部署、未读取密钥、未调用真实付费模型、未推送 GitHub。依据：`docs/86-公开信息智能化三阶段开发设计.md`；实施记录：`docs/87-公开信息智能化第一阶段实施记录.md`。

## 背景

第一阶段要同时解决四类问题：公开正文清洗质量、同 URL 实质变化与附件修订、结构字段的逐字原文证据、RSS 候选发现。现有平台已有统一 `content_item`/`content_version`、摘要/核验失效机制、处理阶段、出站安全、后台权限与每日任务，但：

- 正文获取后没有统一清洗记录，抓取器返回的 Markdown/纯文本与原始 HTML 混用；
- 同 URL 重抓只比较正文哈希，无法区分日期页脚变化、正文变化与附件变化；
- 没有可定位到字符区间的字段证据，模型抽取无法证明“引用了原文”；
- 没有 RSS 来源与候选表。

约束：Node 24 + 内置 SQLite、零 npm 运行时依赖、2 核 2GB、公开资料、现有八模块导航与绿色设计、不得改写既有表/数据、不得调用真实付费 API、不得部署。

## 决策

### 1. 在既有内容主表上做增量，不另建“第二套内容库”

保留 `content_item`/`content_version` 作为业务主表，新增独立从表：

- `content_extraction`：每次实际提取的原始 HTML/文本、清洗文本、提取器/版本/状态/质量/字符数；
- `content_attachment`：附件 URL、类型、已知哈希、指纹与 missing 状态；
- `content_event_group` / `content_event_member`：同文不同 URL 的可解释事件组；
- `field_evidence`：字段值、逐字引句、码点/UTF-16 区间、method/model/版本/状态；
- `rss_source` / `rss_candidate`：RSS 来源与候选。

`content_item`/`content_version` 只做幂等补列（正文指纹、实质指纹、附件指纹、提取器信息、事件组 ID）。既有记录不删除、不重写；迁移可重复执行。

**拒绝**：把原始 HTML 直接塞进 `content_item.body_snapshot`（会混用展示文本与原始响应、难以计算版本）；新建 `content_item_v2`（会造成两套读路径和迁移风险）。

### 2. 确定性清洗永远可用，Trafilatura 只做可选增强

- 规则清洗优先 `<article>/<main>`，再尝试政府 CMS 常见正文 `div`，最后回退 body；保留表格/段落/标题/实体；
- Trafilatura 1.12.2 通过 `scripts/trafilatura-worker.py` 以单进程、单并发、超时/输入/输出上限运行；失败返回真实 reason，调用方回退；
- 提取记录同时保存实际 `extractor` 与 `extractor_version`，绝不把回退结果标成 Trafilatura。

**拒绝**：把 Trafilatura 作为硬依赖（云端内存/安装/许可不确定）；用字符数猜测“是否全文”（正文变长不等于全文）。

### 3. 双指纹与“实质变化”语义

- `body_fingerprint = sha256(归一化清洗正文)`；
- `substantive_fingerprint = sha256(去掉日期页脚/版权/责任编辑/分享行后的正文)`；
- `attachment_fingerprint = sha256(按 URL + 已知哈希排序后的附件清单)`。

同 URL：

- 实质指纹与附件都未变 → `unchanged`；
- 实质指纹变化 → `body_change`，保存版本、失效摘要/核验、旧字段证据 stale；
- 仅附件清单变化 → `attachment_change`，保存版本但不重生成摘要；
- 日期页脚变化 → 只更新提取记录与指纹，不建版本。

**拒绝**：只比较完整正文哈希（页脚日期变化会无意义重生成摘要）；只比较长度（无法区分附件/正文变化）。

### 4. 字段证据必须“可定位”，模型输出先校验后落库

- 确定性字段抽取使用可复现规则，`method=deterministic_rule`；
- 模型抽取复用既有 `callStructuredModel`，只由管理员显式动作触发，`method=model` 并记录实际 model/provider/prompt 版本；
- 每条证据必须在正文中找到逐字连续 quote；码点区间与 UTF-16 区间同时保存；
- 语义校验：
  - 发布/生效日期必须有明确标签，纯落款日期拒绝；
  - 阈值必须核对数字附近的单位与方向；
  - 地区/行业仅表示提及，不声明官方适用范围；
- 无法定位/语义不符写 `invalid`（保留审计），不进入前台；正文变化后旧证据 `stale`。

**拒绝**：让模型自己声明“quote 是原文”而不校验；把定位成功当官方事实；为字段新建一套“人工确认”流程。

### 5. 同文不同 URL 用事件组关联，不合并删除

同一正文哈希命中时，仍插入独立 `content_item` 来源记录，同时写 `content_source_link` 与事件组成员；事件组 `match_basis` 固定记录“正文 SHA-256 完全一致；非标题相似”，成员保留发布/发现/采集时间。相似标题不合并。

**拒绝**：按标题相似度自动合并；删除转载副本；把转载算作独立第二证据。

### 6. RSS 用原生解析与每日有界任务，不部署 RSSHub

- 原生 RSS/Atom 字符串解析，拒绝 DOCTYPE/ENTITY（XXE），不解外部实体；
- 来源/条目 URL 拒绝内网/本机/字面 IP/带凭据/非 http(s)；
- 抓取复用 `fetchText` 的白名单、超时、重定向二次校验、低频与 `maxBytes`；
- 候选只写标题/链接/日期/订阅摘要，`metadata_only`；正文仍走既有抓取/清洗/摘要；
- 每日默认最多 5 来源、每源 20 条、正文抓取 3 条、预算 60 秒；失败写真实游标，不启动常驻 worker。

**拒绝**：把订阅摘要当全文；按 URL 域名猜“官方”；引入 RSSHub/外部队列服务。

### 7. 权限与动作边界

- 普通登录用户只读 `GET /api/v2/content/:id/fields` 与内容详情；
- 重取/重处理/模型字段抽取/RSS 管理全部在 `/api/v2/admin/*`，由既有 admin 守卫 + 服务层二次校验；
- 单条重取/重处理复用 `collection` 租约；抓取失败/列表页/租约忙返回真实 4xx，不写假成功；
- 不新增一级导航；后台只在既有「后台管理」内加页签。

## 后果与限制

- 附件指纹目前基于 URL + 已知哈希；未下载附件时，同一 URL 的文件内容换版无法识别，需要后续附件抓取/哈希补强。
- 确定性清洗对少数老政府 CMS 仍可能保留页脚导航；Trafilatura 可用时优先，但真实 worker 需 Codex 在非沙箱环境验证。
- 字段抽取只做候选证据与语义门槛，不保证穷尽；policy/methodology/project 已有表结构支持，但本轮只接入 content_item 的自动抽取与详情 UI。
- RSS 任务保守有界，来源失效只记录状态，不解释为正式撤回。
- 未部署、未读取真实密钥/环境变量值、未调用真实应用付费 API、未修改在用/审阅库、未启动长期采集/摘要 worker、未推 Git；真实模型、真实 Trafilatura、真实 RSS 与云端验收由 Codex 独立执行。

## 依赖与许可

- 运行时：Node 24 内置模块 + `node:sqlite`，零 npm 依赖；
- 可选：`trafilatura==1.12.2`，Apache License 2.0；固定于 `requirements-intelligence.txt`；由 Codex 安装，不下载重模型；
- 未被采用的候选库（FTS5、pdfplumber、Docling、sqlite-vec 等）不在本轮依赖内，留待第二/第三阶段单独评估。
