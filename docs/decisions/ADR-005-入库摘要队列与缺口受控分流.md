# ADR-005：入库摘要持久队列与缺口受控分流

日期：2026-10-21。状态：本地已实现并完成隔离测试；未部署、未访问云端、未推送 GitHub。依据：`docs/80-入库即时摘要与缺口分流开发要求.md`；验收：`docs/81-入库摘要与缺口分流实施记录.md`。

## 背景

现有摘要是“每日/后台有界批次”模式，新文章入库不会立即生成摘要；缺口台账只有自由文本，无法稳定区分抓取失败、解析失败、摘要失败、需第二来源、原始冲突、非目标页等不同处理路径。CEA 采集还有一类真实问题：搜索/目录发现的页面可能是交易所“基本信息”、招聘或导航页，按行情解析会留下 parse 缺口并被反复重试；同时名录中异常信用代码被置空后，缺少原始值与字段级提示。

约束：2 核 2GB、零第三方运行时依赖、SQLite、单机部署、不得部署/联网读取真实密钥；不能为新功能引入模型/外部队列服务。

## 决策（实际采用）

### 1. 独立持久队列表，不把队列塞进 `summary_task`

新增 `ingest_summary_queue`，一行对应“实体类型 + ID + 当前输入签名 + 提示词版本 + 模型键”的去重任务。`summary_task` 继续表示“一次后台批次”，不承担逐条入库任务的租约/退避/公平性。

- `input_hash` 使用 `summary-svc` 的实际输入哈希（正文/元数据/来源/时间/范围 + 提示词版本），不是 `updated_at`。
- 去重键为 `entity_type|entity_id|input_hash|prompt_version|model_key` 的 SHA-256。
- 新签名出现时旧 queued 任务标 `superseded`；运行中的旧任务在模型返回后重新核对输入，若变化则标 `superseded` 并重新入队，不把旧结果标成新签名成功。

### 2. 入库只入队，worker 独立启动

`upsertContent` 完成原有写库/版本/阶段后只做一次纯数据库入队，不调用模型。worker 由 `startServer()` 启动，与每日 06:30 调度解耦；默认 12 秒周期、单批最多 3 条、单批最多 45 秒；`CCER_INGEST_SUMMARY_WORKER=0` 为环境级停用。

拒绝方案：

- 在 `upsertContent` 同步调用模型：会让采集写路径受外部模型超时/失败影响，且重复抓取会重复付费；
- 只靠每日批次：无法满足“入库即时摘要”，新条目会排到次日；
- 进程内数组/定时器：重启丢任务，多进程无法领取。

### 3. 双层 SQLite 租约与固定锁顺序

- `governance_lease('ingest_summary')`：保证同一数据库只有一个活跃 worker；
- 队列行 `lease_owner/lease_until`：`BEGIN IMMEDIATE` 内条件领取，跨进程原子；
- `governance_lease('summary_model')`：`summary-svc` 的跨进程模型批次锁，防止 worker 与每日/后台摘要重叠。

固定顺序：`ingest_summary` → `summary_model` → 队列行。worker 从不获取 `collection` 租约；每日采集/补采持 `collection` 时也不会等待 `ingest_summary`，因此没有循环等待。忙碌/租约被占/批次到期只延后，不消耗真实失败次数；真实失败才指数退避，默认上限 5 次，达到上限写 `dead`；无模型写 `blocked`，不伪造成功。

### 4. 新内容优先但旧待办有保底名额

每批 3 条中先取 1 条最新入库且未尝试的任务，其余从最久未尝试的旧任务补足；无新内容时按最久未尝试排序。新内容下一 tick 可优先处理，旧待办每批仍有进度，避免永久饥饿。每日兜底扫描使用持久游标分页，超过最新一屏的漏队项会在后续轮次被发现，而不是每次只重扫最新 500 条。

### 5. 缺口分类与动作分离

`gap-triage-svc` 只做确定性分类，不调用模型。分类依据来自台账文本、数据集、真实对象定位、本地附件/快照状态；`processing_stage` 的 blocked/failed/stale 在治理页单独分类。

- 动作只复用 `collectOneCeaDaily`、`repairIncompleteContent`、摘要队列、`ocr-backfill.reparseObject`；没有能力就 unsupported，不显示空动作。
- 抓取成功但解析失败不结清；摘要入队/失败不结清；PDF 只有全部页取得正文才结清，部分页仍是未完成；只有同一来源/日期/对象取得可用结果才结清。
- 每日治理入口执行一次有界缺口校准：同 URL 归档快照证明非目标页、当前摘要已生成等已有证据可确定性结清；累计差异/原始冲突等类别不因相邻证据被顺带关闭。
- 结清追加说明并写审计，旧说明不删除。
- 需第二来源、原始冲突、来源未公开、累计差异、可选字段异常不自动伪造处理。

### 6. CEA 非目标页在行情解析前确定性排除

`detectCeaNonTargetPage` 只看标题/`h1`/主内容；HTML 主内容优先 `<main>/<article>`，否则先移除 nav/header/footer/aside/script/style。只要出现日报语义和数字行情字段，就不判非目标，避免页脚“基本信息”误伤。

命中后写 `cea_page_exclusion`（URL、来源、快照、哈希、标题、规则、证据），同 URL 历史 parse/fetch/nodate 缺口标 `mitigated`、非阻塞、停止重复抓取；不写行情行。空/未知/访问失败不判非目标，保留缺口；标题为空主内容、访问失败/限流页也不据旧标题结清。分类和每日校准可读取同 URL 归档快照，对旧台账改判非目标，但累计差异等类别不受影响。

### 7. 异常信用代码字段级处理

`cea_entity` 保存 `raw_credit_code` 与 `credit_code_valid`。标准代码只写通过 18 位/校验位规则的值；异常时标准代码留空、原始值保留、企业名称继续计入名录，并返回非阻塞 `field_warnings`。不把字段异常变成整条名录缺失，也不猜测补齐。

## 替代方案与拒绝理由

1. **复用 `summary_task` 作为逐条队列**：`summary_task` 是批次审计行，缺少逐条输入签名、租约、退避、旧任务替换语义；混用会把批次数与条目数混淆。
2. **只用进程内锁**：worker 重启/多进程会重复领取；使用 SQLite 双层租约。
3. **worker 共享 `collection` 租约**：会让摘要 worker 与每日采集互相阻塞，且延长采集租约占用；选择独立 `ingest_summary`，用固定锁顺序避免死锁。
4. **所有缺口都提供“重试”按钮**：会制造空动作或错误结清（尤其需第二来源、原始冲突、非目标页）；选择按类别明确支持/unsupported。
5. **用模型判断页面是否非目标/缺口是否关闭**：违反“不凭模型猜关闭”；选择标题/主内容规则与真实对象证据。
6. **把异常信用代码补成某个“看似合法”的代码**：属于捏造；选择原始值保留、标准代码留空、字段级提示。

## 后果与限制

- 自动入队本轮只覆盖 `content_item`；其他实体仍走既有治理/每日摘要批次。
- 缺口动作覆盖有限：CEA 日报 URL、内容补采、摘要入队、CEA 本地 PDF 重解析、非目标页排除；第二来源/冲突/来源未公开/累计差异明确不支持。
- CEA PDF 若不在 OCR 受限根内，重解析会被拒绝；可读部分页也不等于完整文档缺口已结清。
- 非目标规则是确定性的保守规则，访问失败页、空主内容与未知页面保留 gap；需要后续用真实样本补规则。
- 同一数据库只应有一个活跃 worker；崩溃恢复依赖租约过期。
- 未部署云端、未推送 GitHub、未读取真实密钥、未修改现有数据库/账号；全量 42/22 未跑。
