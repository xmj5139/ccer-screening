## 确认存在的实现问题：按语义修正并加回归

1. attachStandardBody 当前按2000字断言full会把截断40/51页标全文、把完整3页更新说明标partial。须传 pagesRead / pagesTotal / extractionComplete 或明确 completeness，按实际页覆盖及错误状态判断，未知完整性partial；实际收齐3页应full。非上传抓取来源不得写“管理员上传”。原文变动应清除旧模型结论、按新内容哈希重新核验。
2. verifyStandardWithModel 仅 `consistent === false` 才冲突，其余JSON缺consistent也走verified；必须**明确一致true、可定位引用且无拒绝引用、正文完整**才可通过。模型说证据不足应insufficient。不可把partial正文的evidence_level固定full_text。核验记录应保留输入内容哈希、精确原文URL及引用定位，单个标题引用不证明所有元数据日期。
3. calculateElectricity source_code-only会默认列表第一条，且factor_id不匹配还能fallback到source_code；必须唯一显式选因子，提供错误ID绝不回落；缺地区/年份/口径的模糊选择拒绝。target_year缺失目前可计算，改为必填有效整数年度（1900—2100），年错配需显式接受。手工因子缺单位不应默认kgCO2/kWh，来源/地区/年/口径显式填写，不默默生成；燃料 carbon_content_unit 需明确tC/TJ，其他单位拒绝。避免依赖隐式数值强转接受数组/布尔。
4. fetchStandardBody 现在只调用原生 pdftotext，扫描件报“需OCR补跑”但不会自动交已配置百度OCR。请真正复用既有pdf-parse/ocr通道，原生无文本时自动尝试，保留页覆盖限制与每日预算。默认 max_pages_per_pdf 可改为60，覆盖实际最长51页，但超预算仍partial且可重试续页，不把第一次partial永久跳过。max_pdfs_per_run=0不应被||8变8。
5. runAccountingCollectTarget 发现errors>0但found=0会标success(empty)，会掩盖全源网络失败；有错误一律failed或partial，只有真正无错误无待处理才empty_scan。任何剩余阶段被deadline跳过需truncated/partial，避免返回success却完全没运行后续采集。
6. 中碳登目前同日存在则一直跳过，无法发现官方修订。每日应至少复核最新日报内容哈希，旧同日缓存有合理期限，变化记revision；不相加、不覆盖CEA收盘价。
7. 标准资料不要只有CETS行业指南：可增加已独立确认的国标**元数据**，不编造全文：GB/T32150-2025，2025-12-31发布，2026-07-01实施，替代2015；GB/T24067-2024，2024-08-23发布，2024-10-01实施，产品碳足迹，官方说明版权不提供全文。真实来源在下一节。状态/生效日期独立保存，不把一般国标自动当全国碳市场履约指南替代。
8. 管理员标准PDF补充界面目前叫“上传”但只有服务器路径输入，用户不能从电脑传文件，云端不可用。请提供真实 file input，复用现有管理员政策附件上传的受控base64/文件流保存方式，再按明确标准ID绑定解析，不允许普通用户上传。原件大小/文件头验证、权限/路径保持现有安全边界；保存后走统一逐页解析与已配置OCR。上传了任意不对应PDF不能伪装官方原件：标记用户补充/来源待模型对照，不覆盖公告官方URL，若与已有sha不同记录差异。
