# 基础 ECS 部署决策与迁移

## 状态与适用范围

已于 2026-09-30 部署到用户提供的 ECS，并开放 `https://60.205.137.86:443/v2` 进行公网试运行。实例为 Ubuntu 24.04.5、2 vCPU、约 1.7 GiB 内存、40 GiB 系统盘、3 Mbps 带宽。应用使用 Node.js 24.14.1、内置 SQLite；运行中调度器在北京时间 06:30 执行每日增量采集。AI、搜索、网页抓取调用外部服务。

## 决策

首期使用一台 ECS 上的单个 Node.js 进程、SQLite 数据库和本地附件目录。服务由 systemd 守护，仅监听 127.0.0.1:8902；Nginx 在公网 443 提供 HTTPS，80 只用于证书验证和跳转。应用端口 8902 不对公网开放。此配置节省内存并沿用现有数据结构。若以后出现持续内存紧张、频繁写锁或多人并发需求，再按实测结果升级服务器与数据库。

部署前检查实例现有服务和端口，不能覆盖其他应用。云盘空间需同时容纳 SQLite、PDF 原件、备份、日志及增长余量。

## 迁移边界

1. 只迁移新版 `data/ccer_v2.db`、`data/official-originals/`、需要的 `data/registry-files/` 以及解密现有服务凭据所需的 `data/keys/master.key`。绝不运行 `npm run seed`，该命令带 `--reset`。旧版 `data/ccer.db` 不作为新版生产库。
2. 运行中的 SQLite 必须用一致性快照（`VACUUM INTO` 或 SQLite backup API）导出，再传输。不能只复制有 WAL 的 `ccer_v2.db` 文件。
3. 迁移后对本地密钥文件设所属服务用户和 `0600` 权限；校验已保存的 DeepSeek、博查和 Firecrawl 凭据仍能解密并真实调用。不得在日志或命令参数中打印密钥。
4. 官方 PDF 在数据库中记录的是 Windows 绝对路径。将文件放入云端数据目录后，先执行 `node scripts/v2-relocate-files.mjs --db=<云端数据库> --data-dir=<云端data目录>` 做只读检查；确认所有附件与 SHA-256 无误后才加 `--apply` 更新路径。
5. 启动命令为 `node scripts/v2-start.mjs`，默认使用独立 `data/ccer_v2.db`。服务保持 `CCER_AUTH_MODE=session`，回环监听，Nginx 负责 HTTPS。系统启动后检查 `/api/health`、登录、七个模块、每日任务与导出。

## 运行与恢复

- `ccer-screening.service` 设置自动重启；采集任务按北京时间 06:30 运行。服务器关机期间不会自动补跑，应在恢复后执行一次增量更新。
- `ccer-screening-backup.timer` 在北京时间 02:30 每天创建数据库一致性快照，打包原始附件和主密钥，写入 SHA-256 校验文件，保留约 30 天；首次备份已完成并通过归档检查。该备份仍位于同一云盘，不能代替云盘快照或异地备份。
- 告警监视磁盘使用率、进程重启、最近同步时间和外部 API 调用失败。
- 试运行后记录应用进程的高峰 RSS、CPU、磁盘增量和每日任务耗时，再决定扩容。

- 从正在运行的本地库执行 `VACUUM INTO`，迁移 `ccer_v2.db`、36 个原始文件及密钥；快照完整性、附件路径和哈希检查通过。旧版 `ccer.db` 未迁移。
- `GET /api/health`、`/v2`、总览、政策、方法学、项目、交易、内容、粗估参数及后台接口均返回 HTTP 200；管理员登录成功，演示口令已轮换为受限保存的强口令。
- DeepSeek、博查、直连 HTTP 抓取与 Firecrawl MCP 的云端真实调用通过。服务器进程启动后未发生自动重启；常态服务内存约 45 MB（以 2026-09-30 观测为准）。
- 官方项目抓取已获取 363 条列表并测试 5 条详情。交易日更新发现官方一条历史公告链接返回 404；该问题在迁移前也存在，保留为来源缺口，不能据此补造交易数据。

- 公网 HTTP 自动跳转 HTTPS；从外部访问健康检查、页面、管理员登录和总览接口均返回 HTTP 200，登录 Cookie 带 `Secure` 属性。IP 证书的 SAN 为 `60.205.137.86`；生产证书和 Certbot 续期演练均成功。`ccer-cert-renew.timer` 每天两次检查续期；IP 证书约六天有效，必须保持自动续期正常。
- 公网启用前已停用四个未设置独立口令的演示账号，生产模式禁用代码中的演示口令回退；管理员使用独立 scrypt 口令。HTTPS 登录后再次验证，管理员可用，演示账号返回 401。

## 后续优化

1. 若将来使用域名，可将其解析至 ECS，再为域名配置 HTTPS；目前公网 IP 已能直接登录。
2. 按实际多人使用情况接入机构统一身份认证，或继续使用经过治理的独立账号。
3. 配置阿里云云盘快照或异地备份，定期演练恢复，并监控同步失败、磁盘与外部 API 配额。
