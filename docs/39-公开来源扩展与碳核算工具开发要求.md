## 功能与结构（必须做成可用功能，不是只加链接）

### 1. 独立公开碳核算资料库

新增独立 schema（建议 schema-accounting.sql），接入 core/db.mjs 仅 V2 增量迁移：

- accounting_source：code、名称、URL、权威主体、允许域名、类型、最近抓取/成功、HTTP 状态、错误、采集数量；门户、直接 HTML、PDF 分别记录。公开 API 不返回凭据。
- emission_factor：稳定身份/来源身份、名称、数值、原始单位、规范单位（若转换）、气体、类别/口径、地区、行业、数据年份、发布/生效时间、版本、适用说明、原文定位（PDF 物理页和打印页）、原 URL、哈希/快照、证据完整程度、模型核验状态、当前/历史版本关系。
- accounting_standard：标准/技术规范编号、标题、发布机构、行业、类型（核算/核查/说明/政策）、正式/草案/历史状态、版本、发布/施行/适用年份、原文 URL/PDF、正文、哈希、来源定位、模型核验状态、替代关系/关联标准。缺原文时 metadata_only，不伪造解读或条款。
- crc_clearing_daily（或等价）：独立存放中碳登日成交量额/其公布均价/累计数据/日期/口径/来源/快照/修订记录。不能覆盖主行情的综合收盘价，不能与上海同日成交量再相加。与 CEA 同日量额做交叉核对，差异保留两方原值。

仅真实读取到的资料/数值可写入；若随代码提供已核实静态数据，必须附公开原件/来源、哈希、页码与明确的验证记录。来源登记和规范元数据可 seed，绝不能 seed 编造的实际抓取成功状态或已通过模型核验。文件使用当前 DB 旁 official-originals/accounting，不能用固定项目 data 导致测试污染。

### 2. 用户界面

保持八个主模块。把现有 measure 主导航名称改成“碳计算与因子”，路由仍 #/measure，默认保留原低浓度瓦斯粗估。新增二级页签：减排粗估、碳排放计算、因子库、标准规范、资料来源。

延续现有绿色/深色文字卡片风格，筛选条件清晰。因子库按地区/数据年/类别或口径/关键词筛选，显示数值、单位、引用位置与可计算性，详情可查看来源和版本；提供 CSV/JSON 导出。标准按行业/正式草案/核算核查筛选，查看原文、PDF、正文、来源与版本。

CEA 市场增加“登记与清结算”页签或在现有行情中给出明确入口，展示中碳登每日数据与同日对照，不把两份来源的相同市场量相加。

后台增加“碳核算资料”页签或同等明确入口，管理员可配置采集预算、触发异步更新并看任务/来源错误，普通用户不能改来源、上传或采集。管理员允许给缺失标准上传 PDF，复用现有受限文件路径和百度 OCR；成功提取后自动交已配置模型核对，不增加人工审核状态。

### 3. 碳排放计算

不保存用户的私有项目或输入。纯函数/无副作用 API，登录普通用户即可调用：

- 外购电力：实际电量 × 用户明确选择的电力 CO2 因子，支持 kWh、MWh、万kWh，输出 tCO2。例：100 万 kWh × 全国 2023 平均 0.5306 kgCO2/kWh = 530.6 tCO2。选择区域/省份时不能默默落回全国；0.6096、0.8273 各有独立口径约束，需显示并由用户明确选择，不推断绿电为零。
- 燃料燃烧参考估算：用户输入燃料消耗(t 或万Nm³)、低位发热量(GJ/t 或 GJ/万Nm³)、单位热值含碳量(tC/TJ)、氧化率(0—1)。E = AD×NCV×CC/1000×OF×44/12，输出 tCO2。单位不同必须拒绝；因子未知就要求输入，不默认编值，不声称正式履约全口径核算。
- 可做多能源分项汇总，但区分直接/间接和气体口径，避免把 CO2 自动标成 CO2e。不得把这里的排放总量当 CCER 预计签发量。
- 校验 finite、非负、数量上限、非法单位、过长输入和 NaN/Infinity；0 活动量可输出 0。缺年份/地区/因子、失效或非数值因子须清楚报错；年度不一致必须明确提示并要求显式接受参考年份，不能把 2023 因子写成 2026。
- 结果要给公式、转换步骤、代入值、因子来源与数据年份、输入假设和限制，支持下载本次结果 JSON（不必保存私有项目）。不能由大模型自由生成数值公式。

### 4. 真实采集、模型核验和每日更新

新增采集服务，复用 collect/web-fetch/search/verification/pdf-parse 的实际能力。官方 HTML/PDF优先，失败可使用已配置搜索/抓取寻找官方镜像；不得把 412/登录页当正文，不能登录未知企业账户/绕过验证码。解析器必须按明确结构取数，不从搜索摘要生成事实。

来源及文件均保留实际 HTTP、URL、哈希与物理页码。中碳登列表按真实 a.href 发现详情，不能仅登记链接而不采集正文或结构化数值。日数据已有则保留修订与来源，不覆盖其他口径。新增因子/标准有正文后复用真实配置大模型作有引用的一致性核验；没有模型/超时就 unavailable，不伪造 verified。单位/日期/因子适用性仍用确定性规则。

默认每日 06:30 全平台任务加入新采集步骤，有共享总预算（单批<=120秒）、单并发、重入合并、每次最多文件/页数、重试游标，来源未变命中缓存。异步触发 POST 202 +任务ID，进度轮询；不得把 accepted 或 0 行解析称成功。无待处理对象属于空扫描而不是失败。
