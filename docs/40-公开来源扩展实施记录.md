### 3. 碳排放计算（docs/39 第 3 条）

`src/services/carbon-calc-svc.mjs`，**纯函数、无副作用**（测试 46 断言调用前后所有表行数不变）：

- **外购电力**：`E = AD × EF ÷ 1000`，单位仅支持 `kWh` / `MWh` / `万kWh`（严格换算，非法单位直接拒绝）。样本：100 万 kWh × 全国 2023 平均 0.5306 kgCO2/kWh = **530.6 tCO2**（测试 46）。
- 选择区域/省份时**不静默落回全国**：取不到就报错并给出可用因子清单（西藏不在清单里，因为原文未列）。
- `0.6096`（不含市场化交易的非化石能源电量）与 `0.8273`（化石能源电力）各有独立口径约束，必须由用户显式选择，结果里再次显示口径并给出警告。
- 年度不一致必须显式 `accept_reference_year` 才继续，并在结果里写明「按 2023 数据年度因子计算，目标年度 2026」。
- **燃料燃烧参考估算**：`E = AD × NCV × CC ÷ 1000 × OF × 44/12`。AD 单位与 NCV 单位严格配对（`t↔GJ/t`、`万Nm³↔GJ/万Nm³`、`Nm³↔GJ/Nm³`），不匹配直接拒绝；有活动量时 NCV/CC/OF 不得为 0，**不提供默认因子**。
- 多能源分项汇总区分 `scope1_direct`（燃料燃烧）与 `scope2_indirect`（外购电力），合计口径仍标 **CO2**，`total_tco2e` 恒为 `null`（不把 CO2 自动标成 CO2e）。
- 校验：`finite`、非负、数量上限、非法单位、超长输入（>64 字符）、`NaN`/`Infinity`、空值；0 活动量输出 0。
- 结果给出公式、换算步骤、代入值、因子来源与数据年份、输入假设与限制；`POST /api/v2/accounting/calculate/result.json` 由服务端用同一套纯函数**复算**后返回 JSON 下载，**不保存任何用户输入**。

### 4. 真实采集、模型核验与每日更新（docs/39 第 4 条）

`src/services/accounting-collect-svc.mjs` + `src/services/accounting-parse.mjs`：

- **复用既有真实能力**：`collect-svc.fetchText`（白名单 + 超时 + 重试 + 低频 + 共享 deadline，HTML/PDF 同一通道）、`web-fetch-svc`、`search-svc`、`pdf-parse-svc`（异步无管道 `pdftotext`/`pdfinfo`，逐页 + 页缓存）、`verification-svc`（`callVerifyModel` + `validateCitations` + `recordVerification`）。
- **412 / 登录页绝不当正文**：`assessFetchedDocument()` 按 HTTP 412、JS 挑战脚本特征（`<body>` 为空 + `$_ts`/`_ts.cd`/挑战 script）与登录页特征判定；即使把状态伪造成 200 也能识别。NCSC 因子库与 CETS 门户按此处理，只登记来源、最近尝试、状态与缺口，不破解校验、不猜 API、不登录企业账户（测试 45）。
- **中碳登列表按真实 `a.href` 发现详情**，分页 URL 只从页面已出现的真实 `?page=N` 链接扩展（不拼猜页码）；详情页解析 Excel 风格表格（含 `rowspan`/`colspan` 展开）+ 两段正文，**表格与正文互为交叉证据**，不一致时两方原值都保留并记录冲突。
- **每日数据保留修订**：同源同日同口径的新值 → 旧行 `is_current=0` 保留为历史，新增 `revision_no+1` 行并写 `revision_of`；数值逐字段一致 → `unchanged`（来源未变命中缓存，不重复抓取）。
- **模型核验**：仅对**已取得正文**的新增/更新规范调用已配置模型，要求给出可定位引用（`validateCitations` 逐条回原文校验）；结论判定是确定性的——有字段冲突→`conflict`，引用为空或全部无法定位→`insufficient`，只有引用可定位且一致才 `verified`；**无模型 / 超时 / 配额耗尽 → `unavailable`**，绝不伪造。
- **有界调度**：单批 `batch_budget_ms` 硬上限 **120000ms**（配置接口拒绝超过 120 秒的值）；单并发（串行跑各子采集器）；重入合并（同目标已有 queued/running → 返回同一 `task_id`）；单次最多文件/页数（`max_pdfs_per_run`、`max_pages_per_pdf`、`max_details_per_source`）；重试游标写 `system_meta.accounting_collect_cursor_v1`。
- **异步触发**：`POST /api/v2/accounting/admin/collect` 立即返回 **202 + task_id**，`GET /api/v2/accounting/admin/jobs?task_id=` 轮询真实进度。**「受理成功」不算成功**；「抓到了却解析 0 行」按失败处理（`summarizeAccountingOutcome`）；「无待处理对象」是空扫描 `success/empty`，不是失败。
- **每日 06:30 全平台任务加入新采集步骤**：`collect-svc.runDailyJob` 内新增 `runAccountingDailyStep`（清结算日报 → 门户探测 → 标准规范），失败只记录、不中断既有 CCER/CEA 采集。

## 五、真实限制与未做的事（不掩饰）

1. **NCSC 因子库与 CETS 门户本机返回 HTTP 412**（JS 校验页、`<body>` 为空）。
   本实现**不破解校验、不猜 API、不登录企业账户**，只登记来源、最近尝试、状态与缺口。
   因此本库当前**没有任何来自 data.ncsc.org.cn 的因子值**；因子值来自同一主管部门（生态环境部）的正式公告附件。
2. **公告称第二版因子库有 576 个因子，但本库只导入 40 行电力 CO2 因子**。
   576 是公告口径的总数，**不是**本应用已导入条数；界面与接口都明确标注这一点，绝不据此生成 576 条记录。
3. **10 项规范目前只有元数据（`body_status='metadata_only'`）**，没有正文。
   原因是本机未下载这些 PDF 原件（真实外部抓取由 Codex 执行）。因此不提供任何条款解读，
   `/api/v2/accounting/status` 的缺口里逐条列出「尚未取得正文」。
4. **规范适用年度只填了能从公告原文确认的一项**（发电 2026）。钢铁/水泥/铝冶炼的适用年度
   未从原文提取到，一律留空并在 `applicability` 说明「不做推断」，没有按编号年份反推。
5. **中碳登列表页分页由前端 JS 渲染**，本次只跟随页面里真实存在的 `?page=N` 链接（不超过 3 页）；
   本机保存的列表页没有分页链接，因此实际只采集第 1 页。深度翻页需要 Codex 在真实网络下复核。
6. **模型核验在本轮全部为 `unavailable`**：因为规范还没有正文，且本机未配置/调用任何模型（也不应调用）。
   代码路径已就绪（带引用核验 + 引用可定位校验 + 四态判定），但**没有任何一条被标成 `verified`**。
7. **每日 06:30 定时任务在本地未启用**（`CCER_DAILY_SYNC=0`）。新增步骤已接入 `runDailyJob`，
   但没有在本机触发真实定时运行，也没有真实外部调用。
8. 未做：全量回归、真实外部调用验收、浏览器验收、云端部署、生产库迁移 —— 按 docs/39 全部由 Codex 执行。

- 发布日期：缺失时显示 **「原站未标注」**（问答页为「原站问答，发布日期未标注」），采集时间单独作为「本平台采集时间」，**不用采集时间顶替发布日期**。
- 详情：`GET /api/v2/accounting/public-documents/:id` → `{document,qa}`，抽屉内展示原文（`pre.body-text`，逐字）与**逐条问答**（问 N / 答复，`ordinal` 缺省时按顺序编号；问答带原站条目链接时额外给「打开原站」）。
- 正文状态取值全部中文化，含后端真实枚举 `index_only → 仅栏目条目（未取正文）`、`list_only → 仅列表信息（未取正文）`、`metadata_only → 仅条目信息（未取得正文）`；原始取值只保留在折叠的接口留痕中。
- 核验口径：页面写明「核验只表示正文与所给原文一致，**不表示**答复已按最新规范更新」；旧版指南答复保留原样并单独提示，不改写成现行文件。
- `index` 条目明确标注「这是栏目 / 导航页，不是全文」，正文区标题写成「栏目页文本（导航内容，不作为全文）」，不把菜单当正文。
- 所有插值经 `esc()`，链接经 `safeHttpHref()`（非 http/https 不生成 `<a>`）。

### 2. 计数与总览

- 界面按 `status.counts` 的 `public_documents`、`public_qa`、`standards_full` 读取（缺失时回落到 `standards_with_body`）；「资料来源」页与后台「资料库状态」卡各增一块政策与问答计数。

### 3. 管理员：采集目标与 PDF 绑定

- 采集目标新增 `{ key: 'cets_public', label: '全国碳市场信息网·政策与问答' }`，说明写明「栏目导航不当正文、宣称条数不当作已入库数、只读公开页不登录企业账户」；仍走既有 202 受理 + `task_id` 2.5 秒轮询，本轮**未实测外部调用**。
- PDF 绑定改为真实 `<input type="file" id="acc-upload-file" accept="application/pdf">`：前端先校验 ≤20 MiB，再以 `FileReader` 读成 base64，`POST /api/v2/accounting/admin/upload-body` `{standard_id, file_name, file_base64}`。

### 4. 计算页契约收紧

- 外购电力：目标年度改为**必填**（`min=1900 max=2100 step=1`），前端先拦缺失/越界（服务端仍会 400），**不提供隐式默认年度**；提示「不提供默认年度」。
