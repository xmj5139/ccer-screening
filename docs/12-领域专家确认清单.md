| EXP-004 | 标准状态定义 | ✅ **已解决**：见 EXP-002。**注意**：全局因子 `rho.ch4.standard = 0.716` 是 0 ℃ 的值，对本方法学不适用 | 16.043 ÷ 24.055 = 0.6669 ≈ 0.67（20 ℃ 摩尔体积 24.055 Nm³/kmol） |

**复算方式**：
```text
常温常压(20℃)摩尔体积 V_m = 22.414 × 293.15 / 273.15 = 24.055 Nm³/kmol
ρ_CH4(20℃) = 16.043 / 24.055 = 0.6669 ≈ 0.67 kg/m³   ← 与原文一致
ρ_CH4(0℃)  = 16.043 / 22.414 = 0.7158 ≈ 0.716 kg/m³  ← 全局因子，本方法学不适用
```

## 十、确认流程建议

1. **分工**：EXP-000 系列与 EXP-400 系列由碳核算方法学专家确认；EXP-100 系列由煤矿瓦斯 / 油气田领域工程师确认；
   EXP-200 系列由合规与法务确认；EXP-300 系列由政策研究员在注册登记系统核对。
2. **确认动作在系统内留痕**：确认后须通过管理后台更新对应因子记录的 `value_status`（`placeholder` → `verified`）、
   `verified_by`、`verified_at`，并将 `verification_note` 替换为确认依据。
   规则卡确认后更新 `methodology_version.rulecard_approved_by` / `rulecard_approved_at`。
3. **确认证据入库**：每条确认须附可核对的原文页码（PDF + 页码）或官方文件链接，写入 `source_document` 与证据表。
4. **回归验证**：系数变更后须重跑 `npm test`，并核对 `src/methodologies/*.mjs` 中 `selfCheckSamples` 的期望值；
   若期望值随系数变化，须由领域人员重新手算签字。
5. **切换严格模式**：全部 EXP 条目确认完毕后，在管理后台将计算门禁切换为 **strict**，此后任何仍含占位系数的插件
   都会被阻止出数。

## 十一、切换严格模式的判定标准

系统在 **strict** 模式下，只要插件仍含任一 `value_status = 'placeholder'` 的因子，即拒绝出数并提示
「暂不支持自动测算」。可由以下检查判断是否具备切换条件：

```bash
# 查看每个插件剩余的占位因子
node -e "import('./src/methodologies/index.mjs').then(m=>{for(const x of m.listMethodologyModules()){const p=x.plugin.factors.filter(f=>f.value_status==='placeholder');console.log(x.meta.methodology_id, p.length? p.map(f=>f.factor_key).join(', ') : '已全部确认')}})"
```

当前状态（本轮整改后）：

| 方法学 | 占位因子 | 缺条款页码的公式 | 业务测算 |
|---|---:|---:|---|
| CCER-10-001 | 1（`CEF_CH4`，原文未定义该参数） | 0 | **被阻止** |
| CCER-10-002 | 待原文对照 | 全部 | **被阻止** |
| CCER-10-003 | 待原文对照 | 全部 | **被阻止** |
| CCER-10-004 | 待原文对照 | 全部 | **被阻止** |

**默认门禁已改为 `strict`**，且业务测算另有三道独立关卡：计算插件审批状态须为 `approved`、
不得含占位系数、不得有缺条款页码的公式。原实现中「代码里有模块就写成 approved」的写法已删除，
种子数据一律写入 `pending_review`，审批人与时间留空，等待领域专家签字。
