# 入库摘要与缺口分流实施记录

日期：2026-10-21。依据：`docs/80-入库即时摘要与缺口分流开发要求.md`；承接 `docs/74`–`docs/79` 与 ADR-004。本文只记录**本轮实际实现、实际跑过的隔离测试与仍然存在的限制**，不把未跑的全量套件、真实外部服务或浏览器验收写成已完成。

## 1. 交付结论

- `content_item` 新增/实质更新后立即写入持久 SQLite 摘要队列，同步写路径不调用外部模型；独立 worker 随 v2 服务启动，默认 12 秒周期、单批最多 3 条、单批最多 45 秒，与每日 06:30 调度完全分离。
- 队列键包含实体类型/ID、实际输入哈希、提示词版本与模型键；相同正文重复抓取不新增付费任务，运行中输入变化时旧任务不会把新签名标成完成。
- 缺口台账与处理阶段增加确定性分类；单条动作只复用现有抓取、正文补采、摘要队列、OCR/PDF 重解析能力，缺失能力明确 unsupported。抓取成功但解析失败、摘要失败都不会被关闭。
- CEA 日报在行情解析前按“标题/主内容”判断非目标页；企业基本信息、招聘、导航等页面记录来源/快照/规则后不写行情行，同 URL 历史 parse 缺口标为 mitigated 并停止重复抓取；真日报即使导航/页脚含“基本信息”也不误伤。
- CEA 名录异常信用代码保留原始值、标准代码留空、企业名称继续计入名录，并给出字段级非阻塞提示；真实解析缺口不被顺带关闭。
- 后台维护页增加入库摘要队列状态/开关/失败原因/有界重试/补入漏队项，以及缺口分类、依据、自动处理方式、实际动作结果和非目标页排除记录；治理页阻塞原因也显示分类。

## 2. A. 持久摘要队列与独立 worker

### 2.1 数据表

新增 `src/db/schema-ingest.sql`，仅在 `CCER_ENABLE_V2=1` 时随既有 `migrate()` 幂等执行：

- `ingest_summary_queue`：实体、输入签名、提示词版本、模型键、状态、优先级、来源、尝试次数/上限、下次重试、租约、错误、结果 JSON、时间戳；
- `cea_page_exclusion`：非目标页 URL、来源代码、快照 ID、原始哈希、标题、规则、证据摘录、时间；
- `data_gap` 幂等补列：`classification`、`classification_basis`、`retryable`、`blocking`、`classified_at`、`last_action*`；
- `cea_entity` 幂等补列：`raw_credit_code`、`credit_code_valid`。

状态：`queued | running | succeeded | failed | blocked | dead | superseded`。`blocked` 专门表示无模型等明确阻塞；`dead` 表示真实尝试达到上限，二者都不等于成功。

### 2.2 入库触发与范围

- `content-svc.upsertContent` 在新增或内容哈希/字段实质变化并完成原有正文、版本、阶段写入后调用 `enqueueContentSummary`；不等待模型。
- 以下不生成摘要任务：演示、转载副本、`record_kind != article` 的来源归档、`failed_fetch`、以及正文与来源摘要都为空的标题-only 记录。
- 仅来源摘要的记录以 `summary_only` 入队；只有元数据的记录不会进入自动摘要队列。
- 搜索采集、种子来源、历史补采、正文修复仍走 `upsertContent`，因此自然覆盖；转载副本路径不新增队列行。
- 每次入队读取 `summary.loadSummaryInput`、`summaryInputHash`、`PROMPT_VERSION`、`currentModelKey`。去重键为四者的 SHA-256；同签名已有任务直接返回，不重复付费。
- 新签名出现时，同一实体的旧 **queued** 任务标 `superseded`；运行中的任务不打断，但完成时会重新比对当前输入/模型键，若已变化则标 `superseded` 并按新签名重新入队。

### 2.3 worker 与锁

入口：`src/services/ingest-summary-svc.mjs`。

- 默认随 `startServer()` 在 v2 可写库启动；`CCER_INGEST_SUMMARY_WORKER=0` 是环境级 kill switch，后台开关不能覆盖。
- 后台开关状态存 `system_meta.ingest_summary_worker_enabled_v1`；可暂停/恢复。
- 使用 `setTimeout(...).unref()`；启动先安排一次近即时 tick，之后按周期排空；`ticking` 防重入，`stop` 清定时器。worker 与 06:30 每日调度无依赖关系。
- 跨进程先取 `governance_lease('ingest_summary')`，再在 `BEGIN IMMEDIATE` 中条件领取队列行并写 `lease_owner/lease_until`。固定锁顺序：
  1. `ingest_summary`（本 worker）；
  2. `summary_model`（`summary-svc` 的跨进程模型批次租约）；
  3. 队列行租约（条件更新）。
  worker 从不获取 `collection` 租约，避免与每日采集/补采交叉等待。
- `summary-svc` 的 `runSummaryBatchExclusive` 与后台摘要任务现在同时使用进程内锁和 `governance_lease('summary_model')`；跨进程重叠时返回 busy，不并发打模型。
- 忙碌、租约被占、批次到期只把任务放回队列并延后，不增加尝试次数；真实模型失败/无模型才按指数退避处理。
- 尝试上限默认 5（硬上限 10）。失败退避默认 60 秒起、指数增长、最多 6 小时；达到上限写 `dead`（无模型写 `blocked` 且停止自动重试）。
- 进程中断遗留的 `running` 在租约过期后回收为 `queued`，尝试次数不变，重启继续。

### 2.4 新旧公平

领取时最多 3 条：

- 先给“入库来源 + 未尝试 + 24 小时内”的最新任务 1 个名额；
- 其余名额从最久未尝试的旧待办中补足；
- 没有新内容时按最久未尝试排序。

因此新内容在下一 tick 可优先处理，同时旧待办每批仍获得名额，不会永久饥饿。

### 2.5 输入变化与完成判定

- 领取后、调用模型前核对一次当前输入哈希/模型键；不一致直接 `superseded` 并重新入队。
- 模型返回后再次核对；若签名已变化，旧任务标 `superseded`，不标成功。
- 只有当前 `entity_summary.status='ok'`、非 stale，且队列签名与当前输入/模型键一致时，队列行才写 `succeeded`。
- 无模型时 `entity_summary` 写 `skipped`，队列写 `blocked`；不伪造摘要。
- 原始 `entity_summary` 的完整/部分/来源摘要范围、提示词版本、模型键语义继续由既有 `summary-svc` 负责；worker 不另写一套摘要内容。

### 2.6 每日/启动兜底与读取

- `runDailyGovernance` 末尾调用 `enqueueMissedContentSummaries({limit:20})`，只补“当前签名应有队列但没有”的有效内容；不进模型。该扫描使用持久游标分页，超过最新一屏的旧漏队项也会在后续轮转中被发现，不会永久饥饿。
- 同一每日入口还执行 `triageGaps({status:'open',persist:true,limit:300})`：只做确定性分类和“已有证据结清”（同 URL 快照证明非目标页、当前摘要已生成），不调模型、不猜关闭。
- `startServer` 启动 worker 时也做一次有界启动补入（最多 20 条）。
- 队列状态 GET 只读 SQLite，不调用模型/外网；新内容列表/详情仍只读既有摘要缓存。
- 后台路由：
  - `GET /api/v2/admin/summaries/queue`
  - `POST /api/v2/admin/summaries/queue/toggle`
  - `POST /api/v2/admin/summaries/queue/retry`（仅失败/阻塞/超限，最多 20 条）
  - `POST /api/v2/admin/summaries/queue/backfill`（最多 20 条）

## 3. B. 缺口分类与受控动作

入口：`src/services/gap-triage-svc.mjs`。

### 3.1 分类

对 `data_gap` 依据台账键、数据集、标题、说明、影响和可定位的真实对象/附件状态做确定性分类；对 `processing_stage` 的 blocked/failed/stale 记录在治理页阻塞原因中同步给出分类。

| 类别 | 含义 | 默认可重试 | 默认阻塞 |
|---|---|---:|---:|
| `access_failed` | 下载/访问失败 | 有单条能力时是 | 是 |
| `dynamic_partial` | 动态页/正文不全/解析失败 | 有单条能力时是 | 是 |
| `pdf_unparsed` | PDF 已下载未解析 | 有单条能力时是 | 是 |
| `ocr_failed` | OCR 失败 | 有单条能力时是 | 是 |
| `summary_pending` | 摘要待办/失败 | 有内容对象时是 | 否 |
| `verification_second_source` | 核验需第二来源 | 否 | 否 |
| `raw_conflict` | 原始事实冲突 | 否 | 是 |
| `source_not_public` | 来源未公开 | 否 | 是 |
| `non_target` | 非目标页 | 否 | 否 |
| `optional_field` | 可选字段异常 | 否 | 否 |
| `missing_trade_date` | 交易日缺失 | 有 CEA URL 时是 | 是 |
| `cumulative_mismatch` | 累计差异 | 否 | 是 |
| `unknown` | 未分类/待补证 | 否 | 是 |

每个分类返回：类别、中文标签、依据数组、自动处理说明、可重试性、是否阻塞、当前支持的受控动作、unsupported 原因。

### 3.2 实际支持的单条动作

| 动作 | 当前支持对象 | 说明 |
|---|---|---|
| `retry_cea_fetch` | 有真实 URL 的 CEA 日报抓取/解析/日期缺口 | 复用 `collectOneCeaDaily`，保留 SSRF/域名/配额/时间预算；抓取成功但解析失败仍 open |
| `retry_content_fetch` | 能定位到唯一 `content_item` 的访问失败/正文不全缺口 | 复用 `repairIncompleteContent` 的目标 ID 模式；只接受实际完整正文 |
| `requeue_summary` | 能定位到唯一 `content_item` 的摘要缺口 | 只入持久队列；未生成成功不结清 |
| `reparse_pdf` | 能定位到 `cea_document` 且本地有受控 PDF 的 PDF/OCR 缺口 | 复用 `ocr-backfill-svc.reparseObject`；只有全部页取得正文才结清，部分页仍 open |
| `record_exclusion` | 有同一 URL 真实快照的 CEA 非目标页缺口 | 重新按确定性规则复核，记录快照/规则/证据；不写行情行 |

以下明确 **unsupported**，界面不显示空动作：

- 核验需第二来源：系统不伪造第二公开来源；保留缺口。
- 原始事实冲突、来源未公开、累计差异：没有安全单条自动消除能力；保留原证据。
- 可选字段异常：字段级提示，不修改原始值、不猜测补齐，不产生动作。
- 无法定位到唯一对象、没有真实快照/本地 PDF、没有已登记来源的缺口。

每次动作只处理 1 条；抓取/重解析受既有 deadline 与域名/受限根约束。角色在路由层和服务层双重校验，普通用户 403。

### 3.3 自动结清与留痕

- 成功抓取并解析入库时，沿用既有 CEA 同 URL 缺口结清。
- 摘要缺口只有在当前输入签名下已有有效摘要时才可结清；仅入队或生成失败不结清。
- 内容补采只有 `improved` 且取得全文才结清；抓取到的仍非全文则保留。
- PDF 只有重解析后全部页都取得可用正文才结清；部分页成功、部分页失败仍 open，结果中保留 `pages_failed`。
- 结清会追加带时间/证据的说明，并写 `audit_log`；旧说明保留，不删除。
- 非目标页把同 URL 历史 parse/fetch/nodate 缺口标为 `mitigated`（不是假装修复了行情），原说明保留并追加排除依据。

### 3.4 CEA 非目标页

`cea-parse.detectCeaNonTargetPage()` 在 `parseCeaDailyReport` 之前执行，规则：

1. 标题（`<title>`/`<h1>`）明确为企业基本信息、招聘、导航/网站地图/联系我们等，且未见 CEA 行情字段 → 非目标；
2. 主内容优先取 `<main>`/`<article>`；无该结构时先移除脚本、样式、nav/header/footer/aside，再看主内容关键词 → 非目标；
3. 只要标题/主内容出现日报语义并同时有数字行情字段，就判为目标页，不因导航或页脚出现“基本信息”误伤；
4. 空正文、只有标题没有主内容、访问失败/限流页（如“访问过于频繁/Access Denied”）不判非目标；仍走原缺口路径。
5. 分类与每日校准还会读取同 URL 的归档快照：旧台账只写“解析失败”，但快照标题/主内容证明是企业基本信息时，可确定性改判 `non_target`；累计差异等其它类别不因同一 URL 被顺带改判。

命中后：

- 写 `cea_page_exclusion`（来源代码、快照 ID、原始哈希、标题、规则、证据摘录）；
- 同 URL 历史 `cea:trade:{fetch|parse|nodate}:URL` 缺口标 `mitigated`、`classification=non_target`、`retryable=0`、`blocking=0`；
- 不建 `cea_trade_daily` 行；
- 再次遇到同 URL 先查排除记录，直接跳过抓取/解析；避免同任务反复重试。

### 3.5 信用代码字段级异常

- `cea_entity` 新增 `raw_credit_code` 保存原始值；`credit_code` 仍只保存通过 18 位/校验位规则的标准代码。
- 异常时标准代码留空，`field_warnings` 返回字段、原始值、非阻塞说明；企业名称继续计入名录/总数。
- 不把字段异常升级成整条名录缺失，也不改写原始值或捏造正式代码。
- 缺口分类另列 `optional_field`；企业级真实 parse 缺口仍保留，不被该提示顺带关闭。

## 6. 实际限制

- 自动入队目前针对 `content_item`（本轮“新文章”范围）；政策、方法学、CEA 文件、标准规范、公开资料、项目仍由既有治理/每日链路生成摘要，未改成逐实体入库触发。
- `reparse_pdf` 只对受限根内本地 PDF 有效。CEA 附件目录不在 OCR 受限根时会被拒绝；即使重解析取得部分页，只要仍有失败页，缺口就保持 open，不宣称已完成。
- 缺口分类是规则/台账驱动，不调用模型判断“是否关闭”；旧台账可结合同 URL 归档快照复核非目标页，但累计差异/原始冲突等其它类别不会被顺带改判。不常见表述可能落到 `unknown` 并明确无动作，需后续按真实样本补规则。
- 非目标页识别只使用标题/主内容确定性规则；未知页面、访问失败页和只有标题的空主内容均保留缺口，不扩大为“统统非目标”。
- worker 是进程内单并发 + SQLite 跨进程租约；同一数据库只应运行一个活跃 worker。进程崩溃后依赖租约过期恢复。
- 未跑全量 42 网络套件、22 Windows ACL 套件；未访问云端、未部署、未推送 GitHub、未读取真实密钥、未修改现有数据库/账号。
- 本会话 GraphFlow MCP 工具不可用，按 docs/80 指定锚点读代码；Impeccable `context` 通过项目内技能脚本加载，未做浏览器端视觉验收。
