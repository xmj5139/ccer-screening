# 公开信息智能化三阶段开发设计

2026-10-29。用户授权：由 Codex 设计、DSH 分三阶段本地实现、独立核验通过后发布云端。

依据：本次 GitHub 调研，仓库能力与许可已查证；本地 Node v24.14.1、Python 3.12.10；云端基础 ECS 约 1.7GiB 内存，当前可用约 1.1GiB。以下是开发目标，不是完成回执。

## 共同约束

- 继续现有 Node/SQLite、八模块导航、绿色专业界面、登录权限、公开证据和每日有界任务。不建立内部项目管理或常规人工审核流程。
- 非管理员不得取得后台配置、凭据、抓取诊断及管理写接口；用户关注订阅只能读写自己的记录，ID 参数也须做所有权验证。
- 任何模型字段、摘要、扩展查询都不是官方确认。存原始快照、字段引句与定位，不能虚构原文、数据和许可证。
- 所有网络访问复用出站校验、白名单、重定向检查、超时与大小限制；RSS/XML 禁止外部实体，拒绝内网、file/data/javascript 等地址。
- 增量 schema，迁移幂等；不删除既有记录、不改变已有密码与API配置。测试只用临时库。DSH 不读密钥、不实际调用付费API、不部署、不推Git。
- 多源同文是转载，不算独立第二证据。相似标题不足以合并；保留每条来源记录和合并依据。
- 数据库读接口不得隐式发起模型或抓取；模型/批量处理使用明确动作、有限批次和时间预算。失败回退需如实标注。
- 不安装完整外部平台。开源代码直接采用时固定版本、保留许可；本次可借鉴功能并用现有服务实现，不强制每个候选库入依赖。

## 第一阶段：正文质量、修订监测、字段证据、RSS候选

### 1. 正文清洗

新增纯函数和可选 Python Trafilatura worker；保留当前规则提取作兜底。优先 `<article>/<main>`，移除script/style/nav/footer等；保留表格、段落、标题和政策正文。禁止仅因文本变长升级 full_text。

接入实际 HTTP 抓取/存量原文重处理路径；存原始正文/HTML、清洗后文本、提取器版本、字符数和状态。worker 单并发、超时、输出上限，失败时回退并报告真实 parser，不伪装 Trafilatura 成功。

### 2. 实质变化与事件聚合

复用 content_version 和旧摘要/核验失效机制，增加正文及附件指纹比较、可解释差异：initial/正文变更/附件变更/无实质变化。内容更新自动保存版本；日期页脚变化不应无意义重生成摘要；同URL换附件要记录。

后台提供按条重取/重处理（复用安全抓取及租约）；普通详情可看内容版本和相关来源。新证据未取得时不把来源失效解释为正式撤回。

同文不同URL保留独立来源记录，事件组列出处和时间；不删除原表、不用相似性猜测事实。匹配证据、理由可解释。

### 3. 结构字段与引句

从正文抽取地区、行业、年度、方法学编号、阈值、发布日期/生效日期等；复用现有模型调用封装与JSON约束。优先提供“模型抽取”后台动作，并保留确定性可定位的基础抽取，显示 method，不冒充模型结果。

每条记录包含 entity_type/id、body_hash、field、value、quote、char_start/end、可选page、method、model、版本和时间。自动验证quote为对应原文真实连续片段，区间精确、字段值与引句可核对。无法定位即拒绝/标invalid，不当作有效证据。正文变化后旧证据stale，前台不沿用。

详情给出字段及原文高亮；HTML必须转义。不得让普通用户点击触发未授权付费调用。

### 4. RSS资料发现

后台管理RSS源（名称、URL、启用、状态、最近成功时间），接入每日有界任务。RSS/Atom提供候选标题、链接、发布日期；订阅摘要不可冒充全文，不凭URL域名猜作官方。按URL幂等发现，再进入既有抓取/摘要流程。先可用简单原生RSS，无需部署RSSHub；未来可将RSSHub路由作为来源。

### 阶段门槛

样本覆盖：正文中含导航词但不是导航、列表页、HTML实体、表格、同URL重复抓取、同URL换PDF、转载、模型伪造引句、中文Unicode定位、失效证据、XXE/SSRF、匿名401/viewer403、抓取超时。至少用真实公开正文取得一次独立清洗与模型抽取验收，不能只有mock结论。

## 第二阶段：中文全文索引、站内关注、PDF表格

### 1. 可重建全文索引

使用SQLite FTS5，覆盖现有统一检索全部公开类型。中文采用字符/双字切分并保留原始英文编号，支持“瓦斯”等两字词和CCER编号精确检索。SQL参数化并转义MATCH语法。保留已有省份、年度、类型、来源和日期过滤及项目去重口径，不因日期扫描预算遗漏400条之外的早期命中。

索引可重建、增量刷新、记录来源hash，过期不作为最新文本。后台重建有限批次，状态可见；查询不得全库每次重建。总数、分页必须真实可达。处理管理覆盖层、来源归档、转载副本及演示数据排除。索引不可用时如实回退既有检索并显示mode，不把失败当无结果。

### 2. 用户关注与信息流

在现有模块内加“我的关注/订阅更新”，不增一级导航。用户可保存关键词、省份、行业、方法学等组合，查看相关新文章及实质修订；普通用户只能操作自己的规则、已读游标。事件转载抑制重复但保留变化。先站内，不默认邮件/第三方消息。

### 3. PDF解析独立进程

实现实际可运行的轻量PDF表格worker（可选pdfplumber），与既有百度OCR/上传治理衔接，输入只接受受限原件路径或已验证上传文件。表格输出包含原文页码、行列、文本、解析器、成功/失败页、覆盖率。失败保持原件与已取正文，不覆盖为全空、不标全文完成。

后台可对难解析原件触发并查看结果。限制文件大小、页数、执行时间、并发和输出；禁止将扫描空页解释成“零家企业”。Docling作为可选worker后端或后续替换，主服务器不常驻重模型；本轮必须交付至少一种真实可用解析后端，而非只有空的远程接口。

### 阶段门槛

检索：至少600条临时公开记录，验证较旧命中、中文短词、编号、特殊符号、筛选组合、翻页、管理覆盖层与索引过期；订阅跨用户ID越权与只读/已读隔离；PDF真实本地样本逐页/表格核对，损坏/扫描/超页/超时回退明确。

## 第三阶段：语义检索、企业档案、历史行情差异

### 1. 语义扩展+全文混合检索

首版复用既有DeepSeek等聊天模型生成有限相关检索词（最多4条、单次模型、严格JSON），合并FTS候选与原关键词结果。精确编号及用户显式地区/年份筛选不得被模型覆盖，结果仍返回库内实体与原文。

显式标记 keyword / semantic_expansion / fallback 和扩展词；模型不可用/超时必须回退关键词并如实显示。禁止把哈希向量或同义词字典冒充训练模型embedding。独立只读查询动作控制频率，不能每次列表自动付费。问答先库内证据原则不变。

sqlite-vec暂不列必装依赖；只有另行验证embedding服务、模型、许可证、内存和Node扩展后再升级为向量召回。首版实际LLM语义扩展必须独立真实测试。

### 2. 企业和地图档案

在现有CEA企业名录和地图链接上加档案详情：规范ID、名称别名、地区、年度行业成员关系、来源、历史变化、关联政策/资料；只使用来源明确的关系。

同名无信用代码跨地区不能强合并；信用代码异常保留名称、代码留空；多行业不覆盖。支持地图/名录进入档案及历史年度，不把名录数当排放量，不从国际估算填补企业实际排放。别名和关系由证据支撑，管理修订可审计。

### 3. 行情历史交叉核对

后台导入/读取第三方CSV/JSON候选（例如china-ets-mcp公开数据），比较已有官方行情的日期、单位、日量/金额/均价及累计口径；生成missing/conflict/match/unsupported差异报告，保留来源及截至日期。

候选必须独立表，不自动写正式行情，不以均价补收盘价或补造开高低收。严格正数/有限数/日期/单位验证、数量与大小限制，CSV导出防公式。管理员查看，普通用户不见内部缺口诊断。

### 阶段门槛

真实模型查询扩展至少覆盖自然语言与精确编号，不相关扩展不得改过滤；模型失败回退；同名跨地区、异常代码、多行业、多个年度档案；第三方无来源/单位/数据陈旧、负数/NaN和冲突保留、正式行情表零改写。

## 实施与发布

1. DSH按第一、第二、第三阶段顺序实现，每阶段提交progress、文件清单、测试命令/结果和已知限制，再由Codex独立复核；不能把“仅配置入口”报告为能力已可用。
2. 文档86为主设计，87/88/89分别阶段实施；新增ADR记录轻量实现和可选依赖选择。后续90记录独立验收，91记录云端发布（按实际占用顺延）。
3. 源码/文档/测试先备份并生成hash清单；本地副本暂停定时任务，真实调用由Codex有限验证，DSH不触碰实际凭据。
4. 所有通过的能力统一打包，云端基线比对、数据库迁移演练、既有表数据指纹比对、停服一致性备份、安装、重启和公网回归。保留旧代码和数据库快照、失败回滚方案；不覆盖云端账号/API/主密钥。
5. 大批次全量采集、外发通知、安装整套RAG/浏览器常驻服务不属于必要动作。每日链路只增加经过验证的有界动作。
