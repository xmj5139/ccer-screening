## 3. A. 采集与核验闭环

### 3.1 实现

- `src/services/processing-stage-svc.mjs`
  - `content_item` 五阶段同步；摘要新鲜度改为调用 `summary-svc.getSummary()`，按**实际输入哈希 + 提示词版本 + 模型键**判断，不再用 `updated_at`/`generated_at` 先后。
  - 读路径保留已有未来退避时间与尝试次数；正文真变化时 `upsertContent` 先失效摘要/核验，再同步为 `stale`。
  - 核验读取 `verification_result`，除时间晚于当前正文外，还要求 `input_hash` 与当前 `contentVerificationInput()` 签名一致；旧正文签名即使时间戳更新也不能算完成。
  - 核验仍以 `verification_result` 为准，不使用可变的 `auto_verify_status`。
- `src/services/content-svc.mjs`
  - 修复 `collectFromSeedSources` 的 `verify` 参数未执行：只核验本次实际写入/更新的正文条目，并记录计数；支持注入 `fetchPage`/`verifyFn` 做离线替身测试。
  - 内容写入后自动同步阶段；正文/可获得性变化后旧摘要/核验失效。
- `src/services/governance-svc.mjs`
  - 阶段漏斗、阻塞原因、最近运行、条目明细、单条重试、有界补处理、配置上限与租约。
  - 默认单批 20 条、最多尝试 3 次、退避 5 分钟起、单批 60 秒；均有硬上限（100 条 / 10 次 / 300 秒）。
  - 未配置模型时摘要写 `blocked`；核验 `unavailable` 写 `blocked`，不写 `verified`。
- `src/services/collect-svc.mjs`
  - 每日任务取得 `collection` 租约；被补采占用时返回 `skipped/lease_busy`，不并行抢占。
  - 每日 `verifyAllBatch` 以 `includeContent:false` 运行，内容核验统一交给治理阶段按 attempts/next_retry 限流；政策/方法学/项目/CEA 仍走原批处理。若管理员关闭 content 核验范围，治理只补摘要。
  - 每日任务在摘要刷新后执行有界治理补处理；证据循环的进度回调也使用同一治理限流，不再直接绕过阶段上限。
  - `syncRecentContent` 优先补齐**完全没有阶段行**的旧记录，再补最近记录；治理候选按阶段创建时间从旧到新轮转，避免旧记录被最近 120 条饿死。
- 后台接口（`src/routes-governance.mjs`）：阶段漏斗、配置、条目明细、同步、补处理、单阶段重试；全部 `/api/v2/admin/*`，普通用户 403。
- 界面：后台新增「信息治理与历史补采」页签；阶段漏斗、覆盖范围、阻塞原因、最近运行、来源/状态筛选、条目明细、重试、补传原件（沿用既有 `/api/v2/admin/document-upload`，适用于政策/方法学/CEA 文件）、编辑纠错入口（链接既有覆盖层维护）。

### 3.2 覆盖范围（docs/76 补齐后）

- **逐条五阶段**：`content_item`、`policy_document`、`methodology_version`、`cea_document`、`accounting_standard`、`accounting_public_document`、`public_project`。阶段主键为 `(object_type, object_id, stage)`，列表/详情/重试都显式携带 `object_type+object_id`。
- **不适用阶段**：公开项目只有结构化登记字段，`fetched` / `parsed` 写 `skipped` 并说明原因；不把结构化项目当 PDF。
- **正文与原件分列**：政策正文快照/PDF 附件、方法学正文/原件哈希、CEA 正文/附件哈希、标准正文/SHA-256、公开资料正文/快照分别取真实表；原件未获取与已归档但解析失败分别为 `blocked` / `failed`，不混写。
- **摘要/核验**：摘要复用 `summary-svc` 的实际输入哈希/提示词/模型键；政策/方法学/项目/CEA 复用 `verification-svc`，碳核算两类复用 `accounting-evidence-svc` 的既有签名与适配器。无模型/凭据写 `blocked`，不写 `verified`；公开项目只有元数据时摘要限定公开字段，核验结论保持 `insufficient`。
- **仍非逐条 PDF 闭环**：排放因子、交易行情、企业名录继续既有确定性/结构化治理，不声明为五阶段已完成；历史补采仍只支持公开内容。

## 4. B. 历史补采

### 4.1 实现

`src/services/history-backfill-svc.mjs`：

- 支持范围：公开内容；政策/方法学/公开项目/交易/因子在界面明确列为不支持统一日期补采。
- 预览：计算日期窗口、检索词、估算调用数、真实连接能力与阻塞原因；不写库、不调用外部搜索。
- 创建：仅管理员；没有可用日期能力时返回 409，不创建假任务。
- 执行：日期窗口、页码游标、命中/新增/更新/重复/窗外/失败/阻塞/未知日期分别计数；每页结束即持久化。
- 暂停/继续/取消/失败重试/重启恢复：任务和窗口状态持久化；失败页游标不前进；已完成页不重复调用。
- 未配置抓取连接时只保留搜索摘要/元数据并计为阻塞，不把摘要当正文。
- 每日任务与补采共享 `collection` 租约；租约未到期不可抢占。
- 日期能力：
  - `start_field`/`end_field`（如 Tavily）；
  - 博查 `freshness` 精确区间 `YYYY-MM-DD..YYYY-MM-DD`（已在既有预设声明 `freshness_range` 并实际构造请求）。
  - 备用通道限制为同等日期能力与相同分页语义；不把“最近结果”伪装成日期范围。
- `src/services/search-svc.mjs` 支持可选的 `page_field`/`page_size_field`；未声明分页的连接不伪造页码。
- HTTP：`/api/v2/admin/backfill/sources|preview|tasks` 及 `tasks/:id/start|pause|resume|cancel|retry`。
- 界面：预览 → 创建 → 任务列表 → 暂停/继续/取消/重试 → 窗口/页游标详情；无真实连接时预览显示阻塞、创建被拒绝。

### 4.2 限制

- 只支持公开内容，不支持政策/项目/行情/因子的全网历史补采。
- 分页依赖连接显式声明的 `page_field`；未声明时只做日期窗口，不宣称覆盖全部分页。
- 本轮 DSH 未使用真实搜索/抓取凭据联网；Bocha 日期区间已用请求构造/能力识别与 Codex 独立 smoke 验证（见 7.4），但没有跑完整历史补采任务，不能称全量历史能力已真实验收。

## 5. C. 方法学版本跟踪

`src/services/methodology-version-svc.mjs`：

- 时间线：正式/草案分列；征求意见、正式发布、修订、替代、废止按结构化日期与**已确认关系**展示；未来生效按当前日期判断；不按编号相邻推断。
- 关系：
  - 白名单：替代/修订/取代/废止/征求意见/补充；
  - 必须有 http(s) 原文 URL（精确 origin+path）、段落/页码定位、至少 8 字逐字引文；
  - 引文必须在**证据 URL 对应的同一版本正文**中定位，并包含替代/修订/废止/征求意见等关系语义；拿另一版本的句子不能证明本来源；
  - 证据来源版本必须存在 `verification_result` verified，且核验的输入签名与**当前**版本字段/正文/策略/模型一致；仅时间较新或 `auto_verify_status` 可变字段不算；
  - 否则保持 candidate，界面标注待核实。
- 差异：适用范围、项目边界、关键参数、计入期、监测要求五维；每条带字段/正文段落定位；取不到证据明确“无法比较”；不编造 PDF 页码。
- 旧测算：只读 `calculation_run.methodology_version_id` / `inputs_json` / `factor_snapshot_json`，差异计算不改写旧结果。
- API：`GET /api/v2/methodology-versions/:id/timeline`、`GET .../diff?compare_to=`、`GET /api/v2/methodology-relations`、`POST /api/v2/methodology-relations`（管理员/研究员）、`POST .../reconcile`（管理员）。
- 界面：方法学详情抽屉新增版本时间线、证据关系、原文/文件哈希、版本对比与差异表；后台治理页可提交候选关系并自动判定。

### 5.1 限制

- 未在无凭据环境自动调用大模型提取关系；提供受保护的候选提交接口，确认仍由确定性证据规则完成，避免伪成功。
- 差异定位是结构化字段/正文段落；PDF 页码只在来源本身提供时使用，目前没有可靠页码数据时不显示页码。

## 6. D. 统一检索

`src/services/unified-search-svc.mjs`：

- 七类公开实体：政策、方法学、公开项目、研报动态、CEA 文件、排放因子、企业名录。
- 搜索字段/表名/列名全部为代码白名单常量；参数化查询；不查询用户、账号、审计、配置、密钥、任务表。
- 排除 demo、转载副本、来源首页/栏目归档、抓取失败条目。
- 公开项目复用总览/省域地图的登记编号去重与阶段并集口径；结果阶段翻译为中文，项目 `last_checked_at` 标为「最近核对日期」，企业 `data_as_of` 标为「名录数据截至」，不统一冒充发布日期。
- 支持关键词、类型、来源/发布机构、来源类别（仅研报动态）、日期、地区（仅适用类型）；不适用筛选会说明并保留其它类型结果。
- 空查询返回最近公开记录；中文单字/组合词使用有界 LIKE；稳定排序（相关度→日期→类型→ID，或日期→相关度→类型→ID）。
- 单类型扫描上限 400、offset 上限 200；总数只声称分页预算内可达部分，超出标记 `truncated/pagination_truncated`。
- 结果带实体类型/ID、标题、片段、真实来源、日期、详情/原文链接、定位；不输出管理员配置/密钥/用户/审计。
- 界面：顶栏统一检索入口 + `#/search` 独立页（不新增第 9 个一级导航，保持既有 8 模块验收）；安全高亮先切分再 `esc()`。
- AI 问答：`retrieval-svc` 新增企业名录来源，并在库内来源查询失败时返回 `source_errors`，避免把查询失败伪装成“没有公开信息”；问答仍返回实体类型/ID、来源和逐字引文校验。

### 6.1 限制

- 没有启用 FTS5；中文检索依赖有界 LIKE + 二次排序，结果总数受扫描/分页预算约束。
- AI 问答沿用其时间敏感与行情证据判断逻辑，与统一检索共享实体/来源契约，但不是同一个 HTTP 端点。
- DSH 未做真实外部搜索/模型联调；Codex 独立最小真实联调见 7.4，但仍未覆盖完整补采、全量搜索与全部版本关系场景。
