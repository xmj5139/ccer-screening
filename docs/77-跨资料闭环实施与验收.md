# 跨资料处理闭环实施与验收

日期：2026-10-21（本地开发，未部署、未访问云服务器、未推送 GitHub）。依据：`docs/76-跨资料处理闭环补齐要求.md`；承接 `docs/74`、`docs/75`、`docs/decisions/ADR-004`。本文件只记录**实际实现与实际跑过的结果**，不把未跑的全量套件、真实外部服务或浏览器验收写成已完成。

## 1. 交付结论

- 逐条五阶段从 `content_item` 扩展到：`policy_document`、`methodology_version`、`cea_document`、`accounting_standard`、`accounting_public_document`、`public_project`。
- 政策、方法学、CEA、标准规范、公开资料/问答、公开项目的正文/原件哈希/来源/时间/摘要/核验均从**各自真实表与附件表**读取；原件未获取与已归档但解析失败分开记录。
- 后台同一治理页支持按资料类型筛选、逐条详情、各阶段失败原因与重试；列表/详情/重试全部携带 `object_type+object_id`，不同类型同名 ID 不串数据。
- 有界 worker 复用既有摘要/核验/归档/OCR/上传服务；单并发、共享 `collection` 租约、尝试上限/退避、输入变化失效、跨类型轮转、全局条数与时间预算。
- 每日链路改为 `runDailyGovernance` 统一调度，不再直接调用旧 `refreshAfterDaily` / `verifyAllBatch` 旁路；旧公开 API 保留，content 兼容包装保留。
- 既有 content 兼容包装（`syncContentStages`、`syncRecentContent`、`getContentStages`、`processPending` 默认 content）未回归；124/140 均通过。

## 2. 七类逐条阶段与真实数据来源

| object_type | 真实数据来源 | 获取阶段 | 解析阶段 | 摘要 | 核验 |
|---|---|---|---|---|---|
| `content_item` | `content_item.body_snapshot`、`content_version` | HTML 正文抓取 | 正文归一化，无 PDF | `summary-svc` | `verification-svc.verifyContentItem` |
| `policy_document` | `policy_document.body_snapshot` + `policy_attachment.local_path/file_hash/parse_quality` | 官方网页正文或附件下载 | HTML/PDF 文本；失败原因原样保留 | `summary-svc` | `verifyObject('policy_document')` |
| `methodology_version` | `methodology_version.body_snapshot` + `original_file_hash/original_file_path` | 正文或官方原件 | PDF/HTML 文本 | `summary-svc` | `verifyObject('methodology_version')` |
| `cea_document` | `cea_document.body_snapshot` + `attachment_hash/attachment_path` | 正文或附件 | HTML/PDF 文本 | `summary-svc` | `verifyObject('cea_document')` |
| `accounting_standard` | `accounting_standard.body_text/body_status/sha256/pages_total/extraction_complete` | 正文或原件 SHA-256 | 按 `body_status` 记录 full/partial/metadata_only | `summary-svc` | `accounting-evidence-svc`（与既有 `verifyStandardWithModel` 同一签名） |
| `accounting_public_document` | `accounting_public_document.body_text/body_status/content_hash/snapshot_path` | 页面正文或快照 | 目录/索引页与详情全文分列 | `summary-svc` | `accounting-evidence-svc`（与既有 `verifyPublicDocument` 同一签名） |
| `public_project` | `public_project` 公开登记字段 | `skipped`：结构化项目，不适用 PDF 下载 | `skipped`：不适用解析/OCR | `summary-svc`，限定公开字段 | `verifyObject('public_project')`，证据不足保持 `insufficient` |

阶段语义：

- `done` 只表示该阶段**执行完成**；核验的 `insufficient/conflict/verified` 在详情中单独展示，`done` 不等于“核验通过”。
- `blocked`：没有模型/抓取能力、原件尚未获取、或该类型没有核验适配器；不会写 `verified`。
- `failed`：已尝试并失败（如原件已归档但正文解析失败、调用异常）。
- `skipped`：结构化项目不适用的下载/解析阶段；原因明确写入 `failure_reason`。
- `stale`：当前输入签名已变化；自动重试前保留可见状态。

输入签名：

- 摘要使用 `summary-svc.getSummary/loadSummaryInput/summaryInputHash`，包含实际正文/公开字段、来源、时间、输入范围、提示词版本和模型键。
- 政策/方法学/项目/CEA 使用 `objectVerificationInput`，要求 `verification_result.input_hash`、哈希方案与当前模型键一致；不认 `auto_verify_status`。
- 碳核算两类使用 `accountingEvidenceFingerprint`，与既有模型核验写入的正文/著录/URL/完整性/策略签名一致；另外比对当前模型键。

## 3. 原件未获取与解析失败分列（实际规则）

- 政策：正文存在 → `fetched/parsed=done`；原件已归档（`local_path+file_hash`）但无正文 → `fetched=done, parsed=failed`；有附件登记但无本地文件/哈希 → `fetched=blocked`，不能进入解析。
- 方法学：有正文或原件哈希 → `fetched=done`；原件已归档但无正文 → `parsed=failed`；没有正文/原件 → `fetched=blocked, parsed=blocked`。
- CEA：有正文或附件哈希 → `fetched=done`；附件已归档但无正文 → `parsed=failed`；仅有官方链接 → `fetched=blocked`。
- 标准规范：有正文或 `sha256` → `fetched=done`；`body_status=metadata_only` 且有原件哈希 → `parsed=failed`；未知/不可用如实记录。
- 公开资料：有正文/快照 → `fetched=done`；`index_only` 可 `parsed=done` 但 detail 明确“目录/索引页不是详情全文”；快照存在但无正文 → `parsed=failed`。
- 公开项目：`fetched/parsed=skipped`，原因写明“结构化登记字段，无 PDF 正文下载/解析阶段”。

## 4. 有界 worker 与每日链路

- 入口：`governance-svc.processPending`、`runGovernanceBatch`、`runDailyGovernance`。
- 默认 `CCER_GOVERNANCE_MAX_BATCH=20`（硬上限 100）、`CCER_GOVERNANCE_MAX_ATTEMPTS=3`（硬上限 10）、`CCER_GOVERNANCE_BUDGET_MS=60000`（硬上限 300000）、退避基数 5 分钟（硬上限 1 小时/最大 7 天）、租约 TTL 15 分钟。
- 单次 action 仍受全局 deadline 控制；扫描/轮转按 `created_at/attempts`，跨类型每类轮流取队首，避免旧资料被新资料饿死。
- 摘要批次通过 `summary-svc.runSummaryBatchExclusive` 取得全局单并发锁；核验沿用既有缓存键与四态。未配置模型写 `blocked` 并记录 attempts/next_retry，不伪造。
- 每日任务在完成采集后调用 `runDailyGovernance`：按自动核验策略的 scope 决定可核验类型；碳核算两类按 accounting 的 `verify_with_model` 配置；摘要仍受同一 worker 与预算约束。旧 `verifyAllBatch`/`refreshAfterDaily` 仅保留公开 API，不再由每日链路旁路调用。
- 失败后下一次重试是否执行由 `next_retry_at` 决定；读路径不会因为旧缓存仍为 stale 就反复清零尝试次数或覆盖未来退避（140 独立用例覆盖）。
- 每日任务、后台批次、历史补采共享 `governance_lease('collection')`；租约未到期时新任务返回 `lease_busy`，不并行抢占。

## 5. 后台页面与实体定位

- 治理页新增资料类型筛选（七类 + 结构化治理说明），列表项同时返回 `object_type` 与 `object_id`。
- 逐条详情展示：真实来源、时间、正文可获得性、正文长度、原件/附件 hash、五阶段完成时间/输入哈希/定位/尝试次数/失败原因/下次重试、当前摘要、最近核验与引文、正文版本、管理员修订。
- 重试按钮携带 `object_type+object_id+stage`；服务端再次校验管理员角色。
- 重试能力：
  - 摘要/核验：清零该阶段尝试后执行一次；无模型/凭据仍 `blocked`。
  - 政策正文/原件：复用 `policy-archive-svc.archivePolicyOriginal`。
  - 方法学/CEA 原件：复用 OCR/PDF `reparseObject`；没有本地原件时明确返回 `blocked` 并给出正确实体上传链接。
  - 标准规范：回到「碳核算资料」页签的既有 PDF 上传/解析入口，并预选标准实体。
  - 公开资料/问答：没有 PDF 补传；明确提示使用碳核算公开资料采集任务。
  - 公开项目：下载/解析不适用，返回 `skipped`。
- 上传链接：
  - 政策/方法学/CEA → `#/admin?tab=governance&upload_type=...&upload_id=...`，治理页将现有 `document-upload` 表单预选到正确实体。
  - 标准规范 → `#/admin?tab=accounting&upload_type=accounting_standard&upload_id=...`，碳核算上传入口预选标准 ID。
  - 公开资料/问答、公开项目、研报动态 → `upload_supported=false`，页面写清没有 PDF 补传入口。
- 编辑纠错 → `#/admin?tab=maintenance&entity_type=...&entity_id=...&action=edit`；维护页预选实体并打开覆盖层表单，不改写原始证据。
- 普通用户：治理列表、详情、同步、批次、重试均服务端 403（路由守卫 + 服务层角色判断）。

## 6. 覆盖范围与真实限制

- **已逐条五阶段**：研报动态、政策、方法学版本、CEA 文件、标准规范、公开资料/问答、公开项目。
- **仍为结构化/确定性治理**：排放因子（数值、年度、单位、原文口径）、交易行情、企业名录；不套用 PDF 下载/解析，不新增对全部企业逐条付费核验，也不声明为五阶段已完成。
- **历史补采**：仍只支持公开内容（研报/动态）；日期/分页依赖真实连接声明。本轮未扩展为政策/项目/全部历史资料补采。
- **公开项目**：只有公开登记字段时摘要可生成，但输入范围明确为 metadata_only；核验最多得到 `insufficient`，不能升级为 `verified`。
- **碳核算模型核验**：只有已有正文且通过既有 accounting-evidence 适配器才能得到模型结论；无模型/正文时 `blocked` 或 `insufficient`，不伪造。
- **未做真实外部联调**：本轮 DSH 未调用真实博查、模型或云服务，未读取/输出密钥，未修改 `data` 下现有数据库；Codex 的真实 smoke 见 docs/75 7.4。浏览器验收由 Codex 独立完成。
- 未运行全套 42/22；`test/22` 的 Windows ACL 限制未通过修改权限校验绕过。
