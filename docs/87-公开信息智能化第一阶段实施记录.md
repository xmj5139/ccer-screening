# 公开信息智能化第一阶段实施记录

日期：2026-10-29。依据：`docs/86-公开信息智能化三阶段开发设计.md` 第一阶段；承接现有统一公开内容、处理阶段、摘要/核验失效、出站安全与后台权限。本文只记录**本轮实际写入的代码、实际跑过的隔离测试与仍然存在的限制**；第二、第三阶段未实现，真实外部模型与云端发布不由本轮完成。

## 1. 交付结论

- 正文清洗已接入实际抓取/存量重处理路径：确定性 HTML/Markdown 清洗始终可用；Trafilatura 1.12.2 为可选 Python worker，未启用、未安装、超时或输出非法时回退规则清洗，并记录真实 parser，不把回退标成 Trafilatura。
- `content_item`/`content_version` 增加正文与附件指纹；同 URL 重抓按 `initial / body_change / attachment_change / none` 处理。日期页脚/版权行变化不新增版本、不重生成摘要；实质正文变化才失效旧摘要/核验并重抽字段。
- 新增附件清单与事件组：同文不同 URL 保留独立来源记录，事件组用“正文 SHA-256 完全一致”作为可解释依据，不按标题相似合并。
- 新增 `field_evidence`：每条有效证据包含 entity、body_hash、field、value、逐字 quote、Unicode 码点区间、UTF-16 区间、method、model、版本与时间；伪造/改写/无法定位的引句写为 invalid，不进入前台。
- 后台提供单条重取、离线重处理、确定性/模型字段抽取；模型抽取复用既有 `callStructuredModel` 出站封装，只由管理员显式触发，普通用户不能触发付费调用。
- 新增 RSS/Atom 来源管理、候选发现与每日有界任务；解析器拒绝 DOCTYPE/ENTITY，地址与条目拒绝内网/本机/字面 IP/非 http(s)；订阅摘要只作为候选摘要，正文仍走既有抓取/清洗/摘要链路。
- 普通内容详情展示字段值与原文高亮、内容版本、附件、事件组/相关来源；后台新增「公开信息智能化」页签。未改八个一级导航和绿色设计系统。

## 3. Schema 与迁移

`schema-intelligence.sql` 只使用 `CREATE TABLE/INDEX IF NOT EXISTS`；列级补充由 `db.mjs` 的 `addColumnIfMissing` 完成：

- `content_item`：`body_fingerprint`、`substantive_fingerprint`、`attachment_fingerprint`、`extractor`、`extractor_version`、`extraction_status`、`extraction_note`、`raw_html_hash`、`cleaned_at`、`event_group_id`；
- `content_version`：两组指纹、`attachment_fingerprint`、`raw_html`、提取器/状态/说明；
- 新表主键/唯一键均可在临时库重复执行；测试 `test/10` 证明重复 `migrate()` 不增加表数量；
- 不删除、不更新既有业务记录；不触碰 `data/ccer.db`。

## 4. 正文清洗

入口：`content-clean-svc.cleanContent()`。

1. 优先选择最大的 `<article>`，其次 `<main>`，再尝试政府 CMS 常见 `TRS_Editor / #zoom / .article-content / .xxgk-content` 等正文 `div`，最后才回退 `<body>`；
2. 移除 `script/style/noscript/iframe/object/embed/nav/footer/aside/form/button/select` 等，保留标题、段落、列表和表格单元格；表格用制表符/换行保留结构；
3. 解码标准 HTML 实体；正文中的“首页/登录”等词只按文本保留，不因词出现就删除；
4. 页面类型判定 `article/list/navigation/empty` 只用于质量说明；包含多个完整段落时优先判文章，避免政府长文因页脚链接多被误判为列表页；
5. 附件链接只接受 http(s) 的 `pdf/doc/docx/xls/xlsx/csv/zip/ofd`，拒绝 `data/file/javascript` 等。

Trafilatura：

- 仅 `CCER_TRAFILATURA=1` 时尝试；Python 可执行文件可用 `CCER_TRAFILATURA_PYTHON` 指定；
- 自动把 `data/runtime/python-packages` 加入 `PYTHONPATH`（若存在），供 Codex 已安装的固定版本使用；
- worker 单进程单并发、15 秒默认超时、输入 1,000,000 字符/输出 200,000 字符上限；失败返回 `not_installed / timeout / worker_failed / output_too_large / bad_worker_output`，调用方回退并记录真实 parser；
- 不安装依赖、不下载重模型；`requirements-intelligence.txt` 只固定 `trafilatura==1.12.2`。

接入路径：

- 搜索发现后的网页抓取；
- 种子来源逐篇抓取；
- `repairIncompleteContent` 定向补采；
- 后台单条重取；
- 后台离线重处理（可切换 Trafilatura，不联网）。

## 5. 实质变化、版本与事件组

- `bodyFingerprints()` 计算完整正文哈希与“去掉日期页脚/版权/责任编辑/分享行”的实质指纹；
- 同 URL：
  - 实质指纹相同且附件未变 → `unchanged`，更新提取记录/指纹，不建版本、不动摘要；
  - 实质正文变化 → `body_change`，保存版本，清空旧核验状态，摘要/核验置 stale，旧字段证据 stale 后重抽；
  - 仅附件清单变化 → `attachment_change`，保存版本，正文指纹不变，不重生成摘要；
  - 列表/栏目/导航页不会覆盖已有文章（重取返回 422）；
- 附件表保留历史行；本次未再发现的附件标 `missing`，不删除；
- 同文不同 URL：保留独立 `content_item` 行与 `content_source_link`，并建 `content_event_group`/`member`；匹配依据固定为“正文 SHA-256 完全一致；非标题相似”，事件组返回每条来源的发布/发现/采集时间。

## 6. 字段证据与模型抽取

- 确定性字段：地区、行业、年度、方法学编号、阈值、发布日期、生效/实施日期；
- 字段值、逐字 quote、Unicode 码点区间（`char_start/end`）与 UTF-16 区间同时保存；前台按码点高亮；
- 语义校验不只看“数字相同”：
  - 发布日期附近必须有“发布/公布/生成日期/印发/发文日期/公开日期”等标签，纯落款日期拒绝；
  - 生效日期附近必须有“施行/实施/生效”等标签；
  - 阈值必须同时核对数字附近的单位与方向；`quote=“低于8%”` 不能支持 `value=“8吨”` 或 `value=“高于8%”`；
  - 地区/行业只表示正文“提及”，不代表官方适用范围；前台与模型提示均明确写出；
- 模型抽取只由 `POST /api/v2/admin/content/:id/extract-fields` 触发，复用 `callStructuredModel`；无模型返回 400 `no_provider`，调用失败返回 502，不写有效字段；
- 模型输出逐条 `validateQuote` + 语义校验；失败记录为 `invalid`（保留审计），有效记录 `method=model` 并写实际 model/provider/prompt 版本；
- 正文变化后旧证据 `stale`；前台只读当前 `body_hash` 的 `valid` 字段；
- 页面披露明确：定位成功/模型抽取只是候选证据，不是官方事实。

## 7. RSS/Atom

- 后台 `GET/POST /api/v2/admin/rss-sources`、`test`、`discover`、`pause`；候选 `GET /api/v2/admin/rss-candidates`；有界每日 `POST /api/v2/admin/rss/run`；
- 原生 RSS/Atom 解析，不部署 RSSHub：
  - 拒绝 `DOCTYPE/ENTITY`（XXE）；
  - 来源 URL 与条目链接校验 http(s)、拒绝带用户名/密码、内网/本机/字面 IP；
  - 抓取复用 `fetchText` 的白名单、超时、重定向二次校验、低频与 2 MB `maxBytes`；
  - 同一订阅内 URL 去重，跨来源按 `content_item.url_hash` 幂等；
- 候选只写标题、链接、发布日期与订阅摘要；`body_availability=metadata_only`，`body_snapshot` 为空，备注明确“订阅摘要不是全文”；
- 每日任务默认最多 5 个来源、每源 20 条、正文抓取 3 条、总预算 60 秒；已接入 `runDailyJob` 的 content 步骤，失败如实写 `dataset_cursor.rss_discovery`，不启动常驻 worker；
- 正文仍通过既有 `repairIncompleteContent` → `cleanContent` → `upsertContent` 链路。

## 10. 已知限制

1. 附件指纹基于附件 URL + 已知文件哈希；未下载附件时，同一 URL 指向的文件内容换版无法单凭页面清单识别，需后续附件抓取/哈希补强。
2. 确定性清洗对部分老政府 CMS 仍可能保留页脚导航；启用 Trafilatura 时优先使用 worker。未安装/不可用时如实回退，不声称清洗完整。
3. 字段抽取是“正文提及/候选证据”，不是官方确认；地区/行业不推断适用范围，日期与阈值只做语义门槛校验，仍可能漏抽。
4. 模型字段抽取目前只覆盖 `content_item` 的后台动作；`field_evidence` 表已支持 policy/methodology/project，但本轮未为这些实体接入自动抽取与详情 UI。
5. RSS 每日任务默认保守限额；来源失效只记录状态，不把“抓不到”解释为撤回。
6. 真实外部模型、真实 Trafilatura、真实 RSS 与云端环境需 Codex 独立验收；本轮不读取密钥、不部署、不推 Git。
