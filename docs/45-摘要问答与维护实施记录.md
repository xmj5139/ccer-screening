## 2. 接口清单（输入 / 输出）

所有接口都在既有的 `/api/*` 会话与守卫体系内：未登录 401；`/api/v2/admin/*` 由
`withAdminAreaGuard` 统一判定为 admin-only（普通用户 403），服务层再做一次 `requireRole` 双保险。

### 2.1 公开（登录即可）

| 方法 | 路径 | 输入 | 输出（要点） |
| --- | --- | --- | --- |
| GET | `/api/v2/summaries` | `entity_type`、`ids`（逗号分隔，≤200） | `{summaries:[{entity_id,status,summary,stale,stale_reason,input_kind,scope_note,empty_reason}]}`；**只读缓存**，未生成时给 `empty_reason` |
| GET | `/api/v2/market-summary` | `dataset=trade\|cea`、`from`、`to`、`trade_method`、`instrument`、`price_regime` | 区间汇总（`actual_range`、`totals`、`disclosure`、`caliber`、`text`、`model_calls:0`） |
| GET | `/api/v2/chat/limits` | — | `{limits, prompt_version, rate, scope_note}` |
| POST | `/api/v2/chat/ask` | `{question, history:[{role,content}]}` | 答复信封：`{refused, answerable, answer:[{text,sources,quotes}], sources, all_sources, mode, notes, reason, disclaimer}`；429 表示限流，400 表示超长/空问题 |

`answer[].sources[]` 每项含：`source_id`、`title`、`url`、`published_at`、`collected_at`、
`origin`(`db`/`web`)、`origin_label`(库内证据/联网检索)、`kind`、`kind_label`
（已获取正文 / 搜索摘要（非全文）/ 来源摘要（非全文）/ 仅元数据）。

## 3. 关键实现口径（与 docs/44、docs/46 的对应）

1. **来源判定（第 2 条）**：唯一规则是 `host === domain` 或 `host.endsWith('.' + domain)`；
   不使用 `includes`、不使用 `.gov.cn` 字符串包含、不读模型输出、不看标题自述。
   `source_category='official'` 只用于提示「该条自称官方但域名未命中」，展示仍按第三方。
2. **摘要（第 3 条 + docs/46 第 3、4、11 条）**：
   - 缓存键 = 实体类型 + ID + `input_hash` + 提示词版本 + 模型键；
     `input_hash` 含**完整来源文本哈希**（截断窗口之外的尾部改动同样失效）。
   - 读路径（列表 / 详情 / `/api/v2/summaries`）**只读缓存**：不调用模型、不发网络请求；
     失效摘要 `text=null` + `stale_reason`，不以旧摘要冒充当前摘要。
   - 写路径只有两个入口：后台有界批次（异步任务）与每日任务尾部有界刷新（两者共用全局单并发锁）。
   - 未配置模型：写 `status='skipped'`，如实显示「未生成：未配置可用模型」，**不写伪造摘要**。
   - 输入范围（正文 / 来源摘要 / 仅元数据）随摘要一起返回；只有元数据时禁止模型声称读过全文。
   - 候选按**持久游标**轮转（`system_meta.summary_cursor_v1`），补完头部后老内容继续被处理；
     演示项目、抓取失败条目、转载副本与来源归档、失效旧因子均在 SQL 层排除。
3. **总览与运行信息（第 4 条）**：总览页与总览接口都不含运行告警/缺口细节；缺口与运行状态只在
   后台「运行与内容维护」，相关接口 admin-only；前端顶栏的「来源冲突 / 未结清差异」徽标与
   `sync.alert` 横幅也只对管理员渲染。
4. **后台治理（第 5 条）**：编辑写 `admin_revision` **覆盖层**，业务表原始值与官方数值不被 `UPDATE`；
   读路径合并并标记「管理员修订」，保留 `original_values`、修订号与操作者，可恢复到任意历史版本；
   字段全部来自硬编码白名单（表名/列名不接受外部输入），URL 仅 `http(s)`，明显脚本载荷直接拒绝；
   所有编辑与恢复都写 `audit_log`。
5. **问答（第 6、7 条）**：库内优先；库内不足才联网，且联网失败原样写入 `notes`；
   引句必须落在**该段声明来源**提供给模型的证据文本中（严格子串，保留小数点和数字）；
   伪造来源、无有效引句、证据中没有的数值、年份/日期不一致、空证据 → 拒答并说明原因；
   含系统提示词/凭据的段落整段拦截；客户端提交的 `assistant`/`system` 历史一律丢弃；
   请求长度、历史轮数、引用数、检索数、模型/网络时长、每用户速率、总并发均有硬上限。
6. **显示清理（第 8 条）**：空值统一「—」；摘要块与对话气泡有明确行高与间距；
   长标题/来源/URL 使用 `overflow-wrap:anywhere`；短操作按钮 `white-space:nowrap`；
   `@media (max-width:420px)` 下限制页面整体横向溢出（覆盖 390px 设备）。

2. **浏览器实机验收未做**：本环境无法启动 Chromium，前端验收通过「读取真实下发资源 + 文本/结构断言」
   完成。桌面端与 390px 移动端的实机截图与交互（对话发送、摘要抽屉、维护页编辑）由 Codex 执行。
3. **摘要质量本身不设阈值**：平台只保证「依据的输入范围可追溯、失效可重算、无模型不伪造」，
   不对摘要文字质量打分；`summary_block` 始终与原文链接并列展示。
4. **问答的数值一致性校验是「证据子串」级别**：段落里的数值必须能在被引用证据中找到，
   但不做算术推导正确性判断（例如「总量 = 分项之和」不由程序复核）；这类推算被系统提示词禁止，
   且不需要推算的问题才可能通过校验。
5. **异步摘要任务为进程内执行**：任务状态持久化在 `summary_task`，进程重启后超时任务会被标记为
   `interrupted` 并可重新发起；但**不自动续跑**中断前的进度（游标已推进，重新发起会从游标处继续）。
6. **限流为单进程内存实现**：多实例部署时每用户速率与总并发是**每进程**口径；
   当前部署形态（2 核 2GB 单实例）下即为全局口径。
7. **`docs/46` 第 11 条中的云端 Nginx 超时未在云端验证**：本地把摘要批次改为 202 + 轮询以消除长请求，
   对话请求仍可能在极慢检索下接近 75 秒上限（代码内硬上限），云端代理超时由 Codex 在发布前实测确认。
8. **未做的可选重构**：没有改动 `admin.js` 既有页签的实现、没有重写既有采集链路、
   没有调整 `data/backups` 与历史文档。

## 8. 定点修复：行情数值问题的联网充分性 + 模型明确「缺事实」时的一次补证

**触发证据**：`data/backups/platform-20261016/real-model-final.log`——
`ask("2024年12月31日全国碳市场CEA收盘价是多少？")` 返回 `mode=db`、`refused=true`，
notes 却写「库内已找到 7 条可用证据，未发起联网检索」。命中的 7 条是 2023/2024 年度配额分配方案、
CCER 均价新闻、方法学通知等：没有任何一条是 2024-12-31 的 CEA 行情，不能充当收盘价依据。

**根因（两个，各自独立）**

1. `retrieval-svc.retrieveEvidence` 的充分性判断只在**已经取到行情类证据**时才校验日期
   （`dateMismatch` 要求 `marketEvidence.length > 0`）。问某一天的收盘价时，若库内该日无行情，
   `marketEvidence` 为空 → 日期校验整条失效；同年度政策/研报只凭标题里的年份就满足
   `strong`（`_score ≥ 6`）→ `weak=false` → 第一步就不联网。
   同时：指定日期时行情来源只按该日做等值取数，其它日期的行情不会进入候选，
   连「日期不匹配」都触发不了。
2. `chat-svc.ask` 只有「库内不足 → 联网」一条路径。库内被判为足够、但模型明确
   `answerable=false`（说库内证据缺所问事实）时直接拒答，没有第二次机会。

**修改（只改两个服务文件；未动 UI / 路由 / 采集 / 服务商配置）**

- `src/services/retrieval-svc.mjs`
  - 新增导出 `needsMarketQuote(question)`：只把**行情数值**问题（收盘/开盘/最高价/最低价/成交价/
    成交均价/均价/成交量/成交额/报价/行情/吨价，或「价格是多少」这类数值意图）纳入强校验；
    泛问「价格机制 / 配额价格如何确定」仍按通用文档检索。
  - 新增导出 `marketScopeOf(question)`：识别问题指向 CEA（全国碳市场）还是 CCER（自愿减排）；
    两个都提到按两个市场算，都没提到则不限定市场。
  - `weak` 增加 `missingQuote`：行情数值问题必须存在**相应市场 + 日期匹配**的行情证据
    （问具体日期就要求当日行情）。政策/研报/方法学不能代替，也不能因为它们同年/标题相关就阻止联网。
  - 给「问题所指日期 + 相应市场」的行情行加排序权重，保证它真的进入给模型的证据列表，
    而不是被同年度政策挤掉。
- `src/services/chat-svc.mjs`
  - 第 5b 步：**库内初检认为足够**（`dbHit.weak===false`，即本轮尚未联网）、且模型**明确**
    `answerable=false`、且没有因伪造来源 / 无据数值被拒时，在**同一个限流槽**与**同一个 deadline**
    内补一次联网检索（复用既有 `webEvidence` 适配器），再基于**新增的真实证据**重试模型一次。
  - 不是递归调用 `ask()`，不再申请并发槽，一个请求最多两次模型调用；
    搜索失败 / 超时 / 剩余时间不足都如实写进 notes 并返回原有结论（不静默、不伪造）。
  - 模型伪造来源或数值导致的拒答**不触发**联网（不去搜索迎合模型的错误结论）。
  - 提示词改为按当前证据重建（`buildPrompt`），补证后的重试使用同一套系统约束与同一套输出校验。

**修复后的行为（本机桩验证）**

| 场景 | 结果 |
| --- | --- |
| 库内只有同年度政策/研报，问某日 CEA 收盘价 | `weak=true`，reason「库内没有 2024-12-31 的 CEA 行情证据（政策、研报不能代替行情数值）」→ 转联网 |
| 库内补上该日 `cea_trade_daily` | `weak=false`，该行情排在证据首位 |
| 泛问配额分配方案（非行情数值） | 仍是通用文档检索，`weak=false`，不联网 |
| 库内够 + 模型明确 `answerable=false` | 联网 1 次 + 模型重试 1 次；重试命中联网证据 → `mode=db+web`、`refused=false` |
| 模型伪造来源并称缺事实 | 不联网、不重试，直接拒答 |
| 本轮已经联网（库内不足）后模型仍说缺事实 | 不二次联网、不额外重试 |
| 模型正常回答 | 不联网，`mode=db` |
