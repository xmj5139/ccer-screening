# 页面原型与信息架构

> 本文档描述 CCER 投资筛选 AI 应用工作台前端的页面原型与信息架构，内容全部来自当前实现：
> `web/index.html`（外壳）、`web/app.js`（1824 行，视图与交互）、`web/styles.css`（230 行，样式）。
> 前端为零构建的单页应用，全部页面在 `#view` 容器内切换，线框图按代码实际渲染的区块、表格列、表单字段与按钮绘制。

### 顶级导航

导航项硬编码在 `app.js` 的 `NAV` 数组，`renderNav()` 逐项渲染为 `<a href="…" data-nav="…">`：

```js
const NAV = [
  ['#/dashboard', '总览看板'],
  ['#/radar', '信息雷达'],
  ['#/methodologies', '方法学库'],
  ['#/projects', '项目档案与筛选'],
  ['#/reviews', '人工审核'],
  ['#/admin', '管理后台'],
  ['#/about', '边界与说明'],
];
```

`route()` 用 `base = '#' + '/' + (r.segs[0] || 'dashboard')` 与 `data-nav` 比对，给当前项加 `.active`；
因此 `#/methodologies/:id` 会点亮「方法学库」，`#/projects/:id?tab=…` 会点亮「项目档案与筛选」。

### 项目详情页的六个子标签

子标签定义在 `ProjectDetailView()` 内的 `tabs` 数组，渲染为 `.subtabs` 中的 `<button data-nav-tab="…" data-project="…">`；
点击由 document 级 click 委托处理：`location.hash = '#/projects/{id}?tab={key}'`，等价于把 `tab` 查询参数写进 hash。

| 子标签 key | 按钮文案 | 渲染函数 |
|---|---|---|
| `overview` | 概览与合规状态 | `OverviewTab(p, d)` |
| `facts` | 事实与证据（N）（N = 已录入事实字段数） | `FactsTab(p, d)` |
| `match` | 候选方法学匹配 | `MatchTab(p)` |
| `eligibility` | 申报条件检查 | `EligibilityTab(p, d)` |
| `calc` | 减排量初算 | `CalcTab(p, d)` |
| `report` | 投资筛选报告 | `ReportTab(p)` |

`tab` 缺省或取值不在上表时回落到 `overview`（`switch` 的 `default` 分支）。

### 哈希路由表

`parseHash()` 把 `location.hash` 去掉 `#/` 前缀后按 `?` 切成路径与查询串，路径按 `/` 过滤空段，
查询串交给 `URLSearchParams`；无 hash 时按 `#/dashboard` 处理。

| 路由 | 页面 | 视图函数 | 说明 |
|---|---|---|---|
| `#/dashboard` | 总览看板 | `DashboardView()` | 缺省路由；无 hash 或 `#/` 时进入 |
| `#/radar` | 信息雷达 | `RadarView()` | 来源、变更、告警、订阅四段 |
| `#/methodologies` | 方法学库（列表） | `MethodologyListView(query)` | 支持 `?keyword=&domain=&status=`，由检索表单写入 hash |
| `#/methodologies/:id` | 方法学详情 | `MethodologyDetailView(id)` | `rest[0]` 为方法学版本 ID |
| `#/projects` | 项目档案与筛选（列表） | `ProjectListView(query)` | 支持 `?teamId=`（代码读取 `query.teamId`） |
| `#/projects/:id?tab=` | 项目详情（六个子页） | `ProjectDetailView(id, query)` | `tab` ∈ overview / facts / match / eligibility / calc / report，缺省 overview |
| `#/reviews` | 人工审核 | `ReviewsView()` | 三块待审列表，需 admin / researcher / reviewer |
| `#/admin` | 管理后台 | `AdminView()` | 门禁模式、插件与系数、标准编码、审计日志 |
| `#/about` | 边界与说明 | `AboutView()` | 纯静态文案，不调用接口 |

未知顶级路径（如 `#/foo`）渲染 `<div class="card">未知页面。</div>`。
路由切换期间 `#view` 先写入 `<div class="card">加载中…</div>` 作为占位。

## 全局框架

### 外壳结构（`web/index.html`）

```
┌ 启动占位  #boot「正在加载工作台…」（boot() 完成后 hidden）
├ 顶栏  header.topbar#topbar（hidden 直到初始化成功；position: sticky; top: 0; z-index: 50）
│  ├ 品牌区 .brand：徽标 [CCER] + 主标题「投资筛选 AI 应用」
│  │  + 副标题「政策与方法学跟踪 · 项目初筛 · 条件检查 · 可追溯减排量初算」
│  ├ 导航区 nav.tabs#nav：总览看板 | 信息雷达 | 方法学库 | 项目档案与筛选 | 人工审核 | 管理后台 | 边界与说明
│  └ 身份区 .userbox：
│     label「当前身份」+ select#user-select（5 个身份）
│     + span.gate#gate-badge（门禁徽标；严格模式时同时挂 class="gate strict"）
├ 使用边界横条  div.disclaimer#disclaimer（常驻，不属于任何页面）
│  「使用边界：本应用是投资筛选与研究辅助工具……情景估算不得称为「预计可签发量」。」
├ 页面容器  main#view.view（全部页面在此渲染；max-width: 1560px; margin: 0 auto）
└ 全局提示  div#toast.toast（hidden；右下角固定定位）
```

### 身份切换（`renderUserSelect()`）

`select#user-select` 的选项与取值：

| value | 显示文案 |
|---|---|
| `user-admin` | 系统管理员（admin） |
| `user-researcher` | 政策研究员（researcher） |
| `user-analyst` | 投资分析师（analyst） |
| `user-reviewer` | 领域复核人（reviewer） |
| `user-other` | 其他团队成员（viewer） |

初始值来自 `localStorage.getItem('ccer.user')`，缺省 `user-analyst`。
`onchange` 处理：

```js
$('#user-select').onchange = async (e) => {
  state.user = e.target.value;
  localStorage.setItem('ccer.user', state.user);   // 身份写入 localStorage，刷新后保留
  state.cache = {};
  await route();                                   // 以新身份重新拉取当前页面全部数据
  toast(`已切换身份：${e.target.selectedOptions[0].textContent}`, 'ok');
};
```

身份通过 `api()` 的请求头 `x-user-id` 传给后端，服务端据此解析角色并做权限判断。

### 门禁徽标（`refreshGate()`）

启动时以及切换门禁模式后调用 `GET /api/admin/plugins`，用返回的 `gate_mode` 刷新徽标：

```js
el.textContent = d.gate_mode === 'strict' ? '严格模式 · 占位系数阻止出数' : '演示模式 · 可出数（标注占位）';
el.className = `gate ${d.gate_mode === 'strict' ? 'strict' : ''}`;
```

请求失败时静默忽略（`catch { /* ignore */ }`），徽标保持空文本。
门禁模式的真实值同时出现在总览看板页头与「管理后台」的门禁卡片中。

### 启动与渲染流程（`boot()` / `route()`）

1. `boot()` 先 `GET /api/meta/fact-fields` 存入 `state.meta`（失败则弹红色 toast「初始化失败：…」，页面仍继续渲染）。
2. `renderNav()`、`renderUserSelect()`，隐藏 `#boot`，显示 `#topbar` 与 `#disclaimer`，再 `refreshGate()`。
3. 绑定 `hashchange` 与首帧 `route()`。
4. `route()` 设置导航高亮 → `#view` 写入「加载中…」→ 按路由调用视图函数（均为 `async`，数据取齐后一次性写入 `innerHTML`）。

### 全局提示（`toast()`）

`#toast` 用 `textContent` 写入文案（不做 HTML 解析），并切换 `toast ok` / `toast err` 样式；
默认 4200 ms 自动隐藏，`err` 为 9000 ms。页面用 `ok` 提示成功、`err` 提示失败，
失败文案统一为 `` `${act} 失败：${e.message}` ``，表单失败时若错误体含 `errors` 数组，会逐条换行追加 `· 消息`。

### 线框图约定（本文档统一使用）

- 左侧 `│` 表示容器边界，缩进表示嵌套层级；
- `[ … ]` 表示按钮、输入框或下拉控件，`( … )` 表示徽标（badge），`|` 表示同一行内的并列元素；
- 表格以「表格 + 列名序列」表示，列名顺序与代码一致；
- `#id` 表示带 id 的容器（供局部更新使用）。

## 页面原型

### 总览看板（`#/dashboard`）

**页面目标**：一屏回答「方法学目录、项目筛选结论、注册登记链条与待处理告警当前各是什么状态」。

**线框图**

```
┌ 页头 .page-head
│  h1 总览看板
│  p.muted 分析基准日：{today} ｜ 计算门禁：(严格模式/演示模式徽标)
│  右侧按钮组： [查看信息雷达]→#/radar   [进入项目筛选]→#/projects
├ 指标区 .grid.c6（六格 .stat，大数字 + 指标名）
│  [teal]  方法学条目（按编号去重）        = methodology.distinct_methodologies
│  [blue]  方法学版本记录                  = methodology.total_versions
│  [green] 正式且可列为候选                = methodology.formal_candidate_eligible
│  [amber] 尚未做条件检查的项目            = project.not_yet_analyzed
│  [red]   待处理告警（警示及以上）        = alert.by_severity.warning + .critical
│  [amber] 被拒绝出数的计算运行            = calculation.rejected_runs
├ .grid.c2
│  ┌ 卡片：方法学目录结构（h2）
│  │  两列表格（行 = 指标，列 = 数量）：
│  │    正式发布（可列为候选） | 正式发布（编号待核实，仅观察）
│  │    修订征求意见稿 / 征求意见稿 | 已获批规则卡 | 已注册计算插件
│  │  条件渲染：catalog_gap 存在时追加 note warn「目录核对：{note}」
│  └ 卡片：项目筛选结论分布（h2）
│     表格：四态结论 | 项目数（结论用 conclusionBadge 渲染）
│     h3 注册登记链条状态（分列统计，不合并）
│      每个状态一行：状态名 + 右侧计数 + .bar 进度条（宽度 = 计数 / 合计）
└ 卡片：待处理告警（h2，alertRow 列表）
   └ 卡片 .card.flat：p.tiny.muted 目录口径说明（catalog_note）
```

`alertRow(al)` 单条告警的结构：

```
.rule（info 无类名 / warning→unknown / critical→fail）
├ .head：(severity 徽标) (kind 徽标) 标题 (status 徽标，非 open 时显示)
├ .body：detail（换行转 <br/>）
├ 可选来源行：来源：<a>source_title</a>　发布日期 {source_publish_date}
└ status === 'open' 时按钮组：[标记已知悉] [关闭]
```

**数据来源**：`GET /api/dashboard`（返回 `today`、`methodology`、`project`、`alert`、`calculation`、`catalog_note`）。

**主要交互**

| 触发 | 行为 |
|---|---|
| `[data-act="alert-set"][data-status="ack"]` | `PATCH /api/alerts/:id` body `{status:'ack'}` → toast「告警状态已更新」→ `route()` |
| `[data-act="alert-set"][data-status="closed"]` | 同上，`{status:'closed'}` |
| `<a href="#/radar">`、`<a href="#/projects">` | 原生锚点跳转（无 `data-act`） |

**空态与异常态**

- 结论分布为空：`<p class="muted">尚无已完成条件检查的项目。</p>`（注册登记链条进度条仍按行渲染，分母取 `totalStage`，为 0 时按 1 处理）。
- 无待处理告警：`<p class="muted">无待处理告警。</p>`。
- 接口报错：`route()` 的 catch 分支渲染 `note danger` + 原始 JSON 卡片（见「关键交互设计」）。

### 信息雷达（`#/radar`）

**页面目标**：展示官方来源基线、抓取产生的变更与告警，并把变更的确认权交给人。

**线框图**

```
┌ 页头：h1 信息雷达
│  p.muted「监测生态环境部、全国 CCER 注册登记系统及信息平台等官方来源；抓取结果只产生变更记录与告警，
│  不自动修改方法学状态或规则卡。」
│  按钮组： [演练比对（不发请求）]  [执行受控抓取]（primary）
├ note info：官方来源采集须走受控出口……
├ h2 一级来源库（{N} 条）+ .scroll-x > table
│  列：状态 | 标题 | 发布机关 | 文号 | 发布日期 | 生效日期 | 最近抓取 | 抓取质量 | 链接
│  「状态」单元格 = 文档状态徽标（formal→pass / draft→draft / 其它→info）+ 分级徽标（tier===1 ? 一级 teal : 二级 gray）
│  「标题」下方可带 parse_note（tiny muted）；「链接」= [打开]（新窗口）或 —
├ h2 来源变更记录（待研究员确认）
│  有数据：.scroll-x > table 列：检测时间 | 来源 | 变更类型 | 摘要 | 确认状态 | 操作
│    「变更类型」徽标：fetch_failed→fail，其余→unknown
│    「确认状态」：pending→(待确认徽标)，否则 (状态徽标)
│    「操作」：pending 时 [确认]，否则 —
│  无数据：卡片 +「尚无变更记录。点击「演练比对」或「执行受控抓取」建立基线。」
├ h2 告警（{N} 条）
│  有数据：alertRow 列表（同总览看板）；无数据：卡片 +「无告警。」
└ h2 订阅 + 卡片 > table
   列：订阅名 | 领域 | 地区 | 项目类型 | 渠道 | 状态
   领域/地区/项目类型为空数组时显示「全部」；状态徽标：启用 pass / 停用 gray
```

**数据来源**：`GET /api/alerts`、`GET /api/sources`、`GET /api/source-changes`、`GET /api/subscriptions`（`Promise.all` 并发）。

**主要交互**

| 触发 | 行为 |
|---|---|
| `[data-act="sync-dry"]` / `[data-act="sync-live"]` | 按钮禁用并改文案「执行中…」，`POST /api/sources/sync` body `{dryRun, timeoutMs: 15000}`；toast 汇总「共 N 条；内容变化 N；失败 N；新编号 N」（有失败用 err），随后 `route()`，`finally` 恢复按钮 |
| `[data-act="change-confirm"][data-id]` | `POST /api/source-changes/:id/confirm` body `{review_status:'confirmed'}` → toast「变更已确认」→ `route()` |

**空态与异常态**

- 来源库无记录时表格表体为空（代码未渲染空态文案），仅表头保留。
- 变更记录、告警、订阅三块各自有显式空态（见上；订阅块无空态文案，表体为空）。
- 抓取失败不会抛错中断页面：失败被记为 `source_change.change_kind = 'fetch_failed'` 并派生告警。
- 同步接口报错：toast 红色提示，页面不重渲染（按钮状态由 `finally` 恢复）。

### 方法学库（列表）（`#/methodologies`）

**页面目标**：按名称、编号、领域、状态检索方法学版本，并区分「正式发布」「草案与征求意见稿」。

**线框图**

```
┌ 页头：h1 方法学库 + p.muted「按名称、编号、领域、版本、状态检索。正式发布与征求意见分栏；每条记录可打开官方原文。」
```

| `[data-act="gate-mode"][data-mode="strict\|demo"]` | `POST /api/admin/gate-mode` → `refreshGate()` 刷新顶栏徽标 → toast「已切换为严格模式 / 演示模式」→ `route()` |

**空态与异常态**

- 审计日志：接口 403（非 admin 角色）时被 `catch { /* 权限不足 */ }` 吞掉，页面显示「无审计记录。」而非权限提示——只有响应体带 `error` 字段时才显示 `note warn`。这是当前实现的已知粗糙点。

- 插件返回空数组时「已注册计算插件」整段为空。

## 关键交互设计

### 三态判断的视觉编码（`.rule.pass` / `.rule.fail` / `.rule.unknown` 与 `stateBadge()`）

规则判断只有三种状态，「通过 / 不通过 / 待核实」必须一眼可辨且不可混淆。实现上用**左侧 4px 色条 + 徽标文字**双重编码：

```css
.rule { border: 1px solid var(--line); border-left: 4px solid var(--line); border-radius: 8px;
        padding: 10px 12px; margin-bottom: 9px; background: #fff; }
.rule.pass    { border-left-color: var(--green); }        /* #15803d */
.rule.fail    { border-left-color: var(--red);   background: #fffbfb; }   /* #b91c1c */
.rule.unknown { border-left-color: var(--amber); background: #fffdf8; }   /* #b45309 */
```

```js
const STATE_BADGE = { pass: ['pass', '通过'], fail: ['fail', '不通过'], unknown: ['unknown', '待核实'] };
function stateBadge(s) {
  const [cls, label] = STATE_BADGE[s] || ['gray', s];   // 未登记状态退化为 gray + 原值
  return `<span class="badge ${cls}">${label}</span>`;
}
```

`ruleHtml(r)` 把状态写在容器类上（`<div class="rule ${r.state}">`），把 `stateBadge(r.state)` 放在 `.head` 首位，
因此「左侧色条给整体判断定调，徽标给出确定文字」。同一条规则若为严格证据字段，还会追加 `(严格证据 unknown)` 徽标：
严格证据字段在来源仅为业主自述时不返回「通过」，只会落到「待核实」。

「待核实」使用琥珀色而非灰色，是要让**信息缺口看起来像一种需要处理的状态**，而不是「无数据」的安静态。

### 来源分层标注的视觉编码（`sourceTag()` 与 `.tag.*`）

每个事实、证据与结论都带来源分层，避免把业主自述当成官方口径：

```js
const SOURCE_KIND_LABEL = {
  official: '官方文件', project_doc: '项目资料', owner_claim: '业主自述',
  analyst: '分析师录入', assumption: '模型假设',
};
function sourceTag(kind) {
  if (!kind) return '';
  return `<span class="tag ${h(kind)}">${h(SOURCE_KIND_LABEL[kind] || kind)}</span>`;
}
```

配色按「可信度递减 + 语义分组」设计：

| 类名 | 来源 | 底色 / 文字色 | 语义 |
|---|---|---|---|
| `.tag.official` | official 官方文件 | `--teal-soft` / `#0b5d56` | 与顶栏、方法学主题同色系，最高可信 |
| `.tag.project_doc` | project_doc 项目资料 | `--blue-soft` / `#1e40af` | 项目侧书面材料 |
| `.tag.analyst` | analyst 分析师录入 | `#f5f3ff` / `#5b21b6` | 系统内人工录入 |
| `.tag.assumption` | assumption 模型假设 | `--amber-soft` / `--amber` | 与「待核实」同色，提示不确定性 |
| `.tag.owner_claim` | owner_claim 业主自述 | `#fef9c3` / `#854d0e` | 黄色，最低可信度 |
| `.tag.unknown` | 未知来源 | `--gray-soft` / `--ink-3` | 兜底 |

计算结果的输入来源也复用同一套编码：`input_origins` 中 `factor_default` 与 `plugin_default` 会被归并为 `assumption` 渲染，
即「方法学缺省值/插件缺省值 = 假设」，不会伪装成项目事实。

### 四态结论徽标（`conclusionBadge()` 与 `CONCLUSION_BADGE` 映射）

条件检查的最终结论有四种取值，映射到四种徽标色：

```js
const CONCLUSION_BADGE = {
  '可继续尽调': 'pass',
  '存在明确障碍': 'fail',
  '资料不足暂无法判断': 'unknown',
  '无已发布适用方法学': 'gray',
};
function conclusionBadge(c) {
  return `<span class="badge ${CONCLUSION_BADGE[c] || 'gray'}">${h(c)}</span>`;
}
```

- 前三种沿用三态语义（绿 / 红 / 琥珀），保证「结论色」与「规则色」一致；
- 第四种「无已发布适用方法学」是**流程之外的排除态**，用中性灰，避免被读成「待核实」或「障碍」；
- 未知取值兜底为 `gray` 并原样输出文本（`h(c)` 转义），不会静默丢弃。
- 徽标在上述位置复用：总览看板结论分布表、条件检查历史表、筛选结论大字、报告一页结论、待复核条件检查列表。

### 计算被拒绝（HTTP 422）不作为异常抛出

输入校验未通过时后端返回 422 + `{rejected: true, errors, warnings, message}`。
前端把它当作**正常业务结果**而不是错误：

```js
// 422 = 校验未通过而拒绝出数。这是系统的正常业务结果，不作为异常抛出。
if (res.status === 422) return { ...data, rejected: true };
if (!res.ok) { /* 其它非 2xx 才抛 Error（带 status / data） */ }
```

于是 `POST /api/projects/:id/calculate` 的返回值直接进入 `calcResultHtml()`，命中第一分支：

```js
function calcResultHtml(out) {
  if (out.rejected) {
    return `<div class="card">
      <h2 style="margin-top:0">已拒绝出数</h2>
      <div class="note danger"><strong>${h(out.message)}</strong></div>
      <table><thead><tr><th>字段</th><th>类型</th><th>说明</th></tr></thead>
        <tbody>${out.errors.map((e) => `<tr>
          <td class="mono tiny">${h(e.field || '—')}</td>
          <td><span class="badge fail">${h(e.kind || 'error')}</span></td>
          <td>${h(e.message)}</td></tr>`).join('')}</tbody></table>
      ${out.warnings?.length ? `<h3>提示</h3>${out.warnings.map((w) => `<div class="note warn">${h(w.message)}</div>`).join('')}` : ''}
    </div>`;
  }
  /* …正常出数渲染… */
}
```

设计意图：拒绝出数必须**渲染成一张正式的结果卡片**（含字段级原因表），而不是一条一闪而过的错误提示——
用户要能截图、能对照字段去补数据。历史运行里被拒绝的运行同样以 `{rejected: true, …}` 重放（`view-calc` 分支），
运行历史表对应行的年度结果与计入期合计显示 `—`，状态列为 `(拒绝出数 fail)` 加拒绝原因。

### 占位系数的可视化

未获领域专家确认的系数在界面上有四处显式标注，任一处都不允许悄悄出数：

1. 逐式明细：某一步绑定了占位系数时，结果行追加 `<span class="badge unknown">占位系数</span>`
   （`s.factor_status === 'placeholder'`），已核实则显示 `(已核实 pass)`。
2. 情景结果卡底部：`r.placeholder_factors` 非空时给出 `note warn`
   「本结果含 N 项未经领域专家确认的占位系数：」并逐项列出 `factor_key = value unit —— verification_note`。
3. 因子快照表（本次运行绑定，历史报告不受库更新影响）：状态列按 `f.value_status`
   渲染 —— `verified` → pass，其余（含 `placeholder`）→ unknown。
4. 管理后台：每个插件卡片显示 `(占位因子 N unknown)` 徽标与「占位因子（须领域专家确认后方可用于正式报告）」明细表；
   顶栏门禁徽标在严格模式下显示「严格模式 · 占位系数阻止出数」，与 `POST /api/admin/gate-mode` 联动。

方法学详情的因子版本表也用同一套三值映射：`verified → 已核实`、`placeholder → 占位待确认`、`deprecated → 已弃用`。

### 注册登记链条六个独立复选框

设计约束是「项目公示 / 审定 / 项目登记 / 减排量公示 / 核查 / 减排量登记」六个状态**分列存储、不合并**。
界面上就是六个独立复选框，不提供「一键全部达成」：

```js
const stage = [
  ['registry_project_public', '项目公示'],
  ['registry_validated', '审定'],
  ['registry_project_registered', '项目登记'],
  ['registry_reduction_public', '减排量公示'],
  ['registry_verified', '核查'],
  ['registry_reduction_registered', '减排量登记'],
];
// 渲染：<td>{label}</td><td><input type="checkbox" name="{k}" {p[k] ? 'checked' : ''} style="width:auto" /></td>
```

提交时按白名单逐项读取 `checked`（未勾选即 `false`，而不是「不变」），其余四个数字/地址字段空串转 `null`：

```js
case 'registry-update': {
  const body = {};
  for (const k of ['registry_project_public', 'registry_validated', 'registry_project_registered',
    'registry_reduction_public', 'registry_verified', 'registry_reduction_registered']) {
    body[k] = form.elements[k]?.checked || false;
  }
  for (const k of ['owner_announced_estimate', 'verified_amount', 'registered_amount', 'registry_public_url']) {
    body[k] = fd[k] === '' || fd[k] === undefined ? null : fd[k];
  }
  await api(`/api/projects/${projectId}/registry`, { method: 'PATCH', body });

```

三套数字（业主公示预计减排量 / 核查报告确定的量 / 登记量）在同一张卡片里**分开三个输入框**，
列表页也分三行显示，任何位置都不做求和——把「预计」和「登记」混为一谈是本领域的典型误用。

### 报告导出：五种格式按钮 + 打印

报告结果的按钮组与历史报告行都提供五种格式，报告结果卡额外提供打印：

```js
// reportResultHtml 中的按钮组
<button class="primary" data-act="export-report" data-id="…" data-format="markdown">导出 Markdown</button>
<button data-act="export-report" data-id="…" data-format="html">导出 HTML（可打印为 PDF）</button>
<button data-act="export-report" data-id="…" data-format="doc">导出 Word（.doc）</button>
<button data-act="export-report" data-id="…" data-format="xls">导出 Excel（.xls）</button>
<button data-act="export-report" data-id="…" data-format="csv">导出 CSV</button>
<button data-act="print">打印 / 存 PDF</button>
```

`doc` 与 `xls` 两种格式由服务端 `report-svc.mjs` 的 `toWordHtml()` / `toExcelHtml()` 生成
带 Office 命名空间的 HTML，Word / Excel / WPS 均可直接打开并保留标题层级、表格与列表；
Excel 版本按「报告信息 / 一页结论 / 项目事实 / 条件检查 / 计算明细 / 因子快照 / 情景 / 敏感性 /
冲突与权属 / 可追溯索引」分成 10 个 table 区块。

导出走独立于 `api()` 的下载通道，文件名来自响应头 `Content-Disposition`：

```js
async function apiDownload(path) {
  const res = await fetch(path, { headers: { 'x-user-id': state.user } });   // 仍带身份
  if (!res.ok) { /* 尽量解析 { error } 作为提示文案后抛出 */ }
  const blob = await res.blob();
  const cd = res.headers.get('content-disposition') || '';
  const m = cd.match(/filename\*=UTF-8''([^;]+)/);        // 优先解析 RFC 5987 形式
  const name = m ? decodeURIComponent(m[1]) : 'export.txt';
  const url = URL.createObjectURL(blob);
  const a = document.createElement('a'); a.href = url; a.download = name;
  document.body.appendChild(a); a.click(); a.remove();
  URL.revokeObjectURL(url);
  toast(`已导出：${name}`, 'ok');
}
```

服务端写入的头部是 `attachment; filename*=UTF-8''${encodeURIComponent(out.file_name)}`，
因此中文报告名能被正确还原；解析不到时退回 `export.txt`。
打印按钮只调用 `window.print()`，版式完全交给 `@media print`（见下节）。
未生成二进制 `.docx` / `.pdf`，固定版式的正路是「导出 HTML → 浏览器打印为 PDF」，这一点在「边界与说明」页明示。

### 审计与权限反馈（403 时页面显示什么）

`api()` 对非 2xx 一律抛 `Error`，并挂上 `err.status` 与 `err.data`（后端返回的 `{error, status}`）。
`route()` 的 catch 分支把它渲染成「红色提示条 + 原始 JSON 卡片」：

```js
} catch (e) {
  view.innerHTML = `<div class="note danger"><strong>加载失败：</strong>${h(e.message)}</div>
    <div class="card"><pre class="mono">${h(JSON.stringify(e.data || {}, null, 2))}</pre></div>`;
}
```

以 viewer 身份打开「人工审核」为例：`GET /api/reviews/pending` 返回 403，
后端 `requireRole()` 生成的消息形如
「当前角色「其他团队成员」无权限查看待审列表（需要：系统管理员 / 政策研究员 / 领域复核人）」，
页面因此显示该文案的 `note danger` 条，下方附上原始 JSON（`{"error":"…","status":403}`）。

设计取向是**暴露原始错误体而不是美化它**：原型阶段需要让复核人能直接把 JSON 贴给开发定位问题。
写操作（`data-act` / 表单）出错则走 `toast(..., 'err')`，页面**保持原样不重渲染**，
避免一次失败把已填表单冲掉；表单错误若带 `errors` 数组，会逐条追加到 toast 文案里。

对审计日志这类「非关键但可能无权限」的数据，`AdminView()` 采取了更弱的策略：
`try { audit = await api('/api/audit?limit=60'); } catch { /* 权限不足 */ }`，
失败时页面显示「无审计记录。」而不是权限提示——这是已知的可改进点（见「可访问性与本地化」一节的限制清单）。

### 栅格断点

布局只用一套自适应栅格 `.grid`，配合 `auto-fit` + `minmax`，**没有媒体查询断点**：

```css
.grid { display: grid; gap: 14px; }
.grid.c2 { grid-template-columns: repeat(auto-fit, minmax(420px, 1fr)); }
.grid.c3 { grid-template-columns: repeat(auto-fit, minmax(280px, 1fr)); }
.grid.c4 { grid-template-columns: repeat(auto-fit, minmax(210px, 1fr)); }
.grid.c6 { grid-template-columns: repeat(auto-fit, minmax(150px, 1fr)); }
```

| 类 | 单列最小宽度 | 页面用法 |
|---|---|---|
| `c2` | 420px | 总览看板的目录结构 / 结论分布；方法学详情适用范围 / 审计信息；事实与证据主分栏；匹配页缺口两块 |
| `c3` | 280px | 方法学库的三个统计格 |
| `c4` | 210px | 预留（当前页面未使用） |
| `c6` | 150px | 总览看板 KPI 六格；条件检查结论六格；报告结果三格 |

容器与溢出控制：

- `.view { padding: 20px 22px 60px; max-width: 1560px; margin: 0 auto; }` —— 超宽屏不无限拉伸；
- 宽表格外包 `.scroll-x { overflow-x: auto; }`，窄屏横向滚动而不挤压列（项目列表、条件检查规则表、审计日志等）；
- 顶栏导航 `.tabs { flex-wrap: wrap }`、子标签 `.subtabs { flex-wrap: wrap }`，窗口变窄时折行；
- 表单网格 `.inline-form { grid-template-columns: repeat(auto-fit, minmax(180px, 1fr)); }`，字段自动换行；
- 窗口小于卡片最小宽度时 `auto-fit` 自动降为单列，因此移动端可用但未做专门优化（顶栏在窄屏会折成多行、`.brand { min-width: 300px }` 会造成额外换行）。

### 打印规则

```css
@media print {
  .topbar, .tabs, .disclaimer, .btn-row, button { display: none !important; }
  .card { box-shadow: none; break-inside: avoid; }
}
```

打印路径与效果：

1. 入口是报告页的「打印 / 存 PDF」按钮（`data-act="print"` → `window.print()`），因此打印对象通常是**已生成的报告页**；
2. 顶栏（含身份选择与门禁徽标）、导航、常驻的使用边界横条、所有 `.btn-row` 与 `<button>` 都不进入打印稿，
   删除按钮是为了避免导出材料上出现「点击这里」的无效控件；
3. `.disclaimer` 在打印时被隐藏，所以**报告正文自身必须携带免责声明**——`reportResultHtml` 在一页结论与正文中分别渲染
   `c.disclaimer` 与 `r.disclaimer`（`note info`），保证纸质/PDF 输出不丢失边界说明；
4. `break-inside: avoid` 作用在 `.card` 上，单张卡片尽量不跨页断开；`box-shadow: none` 去掉阴影以省墨水并避免灰底；
5. 已知限制：`.step`、`.rule` 与表格行没有 `break-inside` 约束，长规则卡与长表格仍可能在分页处断开；
   页面没有 `@page` 规则，页边距完全由浏览器默认；
   子标签栏 `.subtabs` 的按钮因为是 `<button>` 被 `button { display: none !important }` 一并隐藏，
   但容器本身与其 2px 下边框仍在，打印稿上会留下一条空分隔线；
   `.scroll-x { overflow-x: auto }` 容器在打印时可能裁掉超出可视宽度的列。

## 可访问性与本地化

### 语言与文案

- `web/index.html` 声明 `<html lang="zh-CN">`、`<meta charset="utf-8">`、`<meta name="viewport" content="width=device-width, initial-scale=1">`，
  标题为「CCER 投资筛选 AI 应用 · 工作台」。
- 界面文案**全部为简体中文**，且关键枚举在代码里都有中文标签映射，而不是直接暴露英文枚举：
  - `STATUS_LABEL`：formal 正式发布 / draft 征求意见 / revised_draft 修订征求意见稿 / repealed 已废止；
  - `STATE_BADGE`：通过 / 不通过 / 待核实；
  - `SOURCE_KIND_LABEL`：官方文件 / 项目资料 / 业主自述 / 分析师录入 / 模型假设；
  - `CONCLUSION_BADGE`：可继续尽调 / 存在明确障碍 / 资料不足暂无法判断 / 无已发布适用方法学；
  - 域内固定枚举（规则层级、严重度、因子状态、保密等级、变更类型）均在渲染处内联中文映射。
- 少量下拉选项刻意采用「英文枚举值 + 中文说明」并列（如 `internal（团队内可见）`、`project_doc 项目资料`），
  目的是让原型阶段的排查者能直接看到入库值。
- 字体栈以中文字体优先：`"Microsoft YaHei", "PingFang SC", "Hiragino Sans GB", system-ui, sans-serif`。

### 日期与数字格式

| 类型 | 处理 | 结果 |
|---|---|---|
| 日期 | `(x || '').slice(0, 10)` | `YYYY-MM-DD`（发布日、生效日、基准日、证据上传日） |
| 时间戳 | `x.slice(0, 19).replace('T', ' ')` | `YYYY-MM-DD HH:mm:ss`（抓取时间、运行时间、判断时间、报告生成时间、审计时间） |
| 数字 | `num(v, digits)` → `Number(v).toLocaleString('zh-CN', { maximumFractionDigits: digits })` | 千分位分隔；`null` / `undefined` / 空串 → `—`；非数字原值经 `h()` 转义后原样输出 |
| 金额/系数精度 | 调用处指定 | 因子与逐式结果 6 位、减排量 2 位、计数 0 位 |

### 已知限制（如实列出）

- **无 ARIA 语义**：`#view` 没有 `role="main"`，导航没有 `role="navigation"`，子标签栏没有 `role="tablist"` / `aria-selected`，
  当前导航项只用 `.active` 类表示，没有 `aria-current="page"`；`#toast` 没有 `aria-live`，屏幕阅读器不会主动播报提示；
  无图标按钮均无 `aria-label`（好在按钮文案本身就是动词短语）。
- **无键盘焦点管理**：`route()` 直接替换 `#view.innerHTML`，切换页面/子标签后焦点回到 `document.body`，不做焦点归位；
  子标签是 `<button>`，可用 Tab 聚焦并用 Enter 触发，但没有方向键切换；没有「跳到主内容」的跳转链接。
- **颜色是主要状态载体**：三态的左色条只有颜色差异，色觉障碍用户需要依赖徽标文字；徽标文字本身是中文词，因此仍有文本补偿。
- **表单无障碍细节不完整**：`<label class="field"><span>…</span><input/></label>` 是隐式关联（可用），
  但没有 `id` / `for` 配对，也没有 `aria-describedby`；表格有 `<th>` 但无 `<caption>` 与 `scope`；必填只用 HTML `required`（仅项目名称与字段/文件名）。
- **无 i18n 机制**：中文文案硬编码在 `app.js` 与 `index.html` 中，没有语言包或运行时切换语言的入口；
  `lang="zh-CN"` 是固定值。
- **无前端表单校验反馈层**：除 `required`、`type="number"` 与 `min="1"` 外不做校验，非法输入交给后端返回错误再由 toast 呈现。

## 前端技术约定

### 零构建、ES 模块

- 没有打包器、转译器与 npm 运行时依赖；`index.html` 以 `<script src="/app.js" type="module"></script>` 直接加载单个 ES 模块，
  由 `src/server.mjs` 静态托管 `web/` 目录。
- `app.js` 是一个模块：顶部是工具函数与常量，中间是各视图函数，底部注册两个 document 级事件监听并调用 `boot()`。
- 样式单文件 `styles.css`，用 `:root` 自定义属性集中定义色板（`--teal` / `--amber` / `--red` / `--green` / `--blue` 及对应 soft 底色），
  组件类按「顶栏 / 通用 / 表格 / 徽标 / 标签 / 按钮与表单 / 标签页 / 规则条 / 公式步骤 / 提示 / 打印」分区注释。

### `api()` 包装器：统一注入身份

```js
async function api(path, opts = {}) {
  const res = await fetch(path, {
    method: opts.method || 'GET',
    headers: { 'content-type': 'application/json', 'x-user-id': state.user },
    body: opts.body ? JSON.stringify(opts.body) : undefined,
  });
  const text = await res.text();
  let data;
  try { data = text ? JSON.parse(text) : {}; } catch { data = { raw: text }; }
  if (res.status === 422) return { ...data, rejected: true };      // 拒绝出数 = 业务结果
  if (!res.ok) { const err = new Error(data.error || data.message || `HTTP ${res.status}`);
                 err.status = res.status; err.data = data; throw err; }
  return data;
}
```

约定：**所有**页面数据都经 `api()`，因此身份（`x-user-id`）与错误语义在单一入口统一处理；
唯一的例外是文件下载 `apiDownload()`（同样带 `x-user-id`，但读的是 blob 与 `Content-Disposition`）。

### `toast()` 反馈

所有写操作无论成功失败都必须给出反馈：成功 `toast(msg, 'ok')`，失败 `toast(`${act} 失败：${e.message}`, 'err')`。
文案里保留动作名（`act`）便于定位；`err` 停留 9 秒（默认 4.2 秒），因为错误信息通常更长、需要抄录。

### `h()` 转义：所有插值都过一遍

```js
function h(s) {
  return String(s === null || s === undefined ? '' : s)
    .replace(/&/g, '&amp;').replace(/</g, '&lt;').replace(/>/g, '&gt;')
    .replace(/"/g, '&quot;').replace(/'/g, '&#39;');
}
function nl2br(s) { return h(s).replace(/\n/g, '<br/>'); }
```

- 视图函数返回的是 HTML 字符串，因此**每一个来自接口或用户输入的插值都包在 `h()` 里**，包括文本节点、
  属性值（`data-id`、`href`、`value`、`name`、`title`）与 `<pre>` 错误体；
- 多行文本用 `nl2br()`（先转义再换行转 `<br/>`）；
- 数字统一走 `num(v, digits)`，其内部在遇到非数字时回退到 `h(v)`，日期/时间在 `slice()` 之后仍过一次 `h()`；
- 唯一不做转义的地方是有意的：`route()` 中拼装的固定 HTML 模板字符串本身（不含插值），以及 `<a class="btn" href="#/…">` 这类常量链接。

### 变更后重新渲染的规则

约定是「**写操作完成后，页面必须反映新的服务端状态**」，分两种粒度：

| 粒度 | 实现 | 适用动作 |
|---|---|---|
| 整页重渲染 | 调用 `route()`（重新解析 hash、重新请求接口、重建 `#view`） | `alert-set`、`change-confirm`、`review`、`gate-mode`、`registry-update`、`fact-upsert`、`evidence-add` |
| 局部结果替换 | 把结果 HTML 写入指定容器后 `scrollIntoView({behavior:'smooth'})` | `run-match` → `#match-result`；`run-elig` → `#elig-result`；`run-calc` → `#calc-result`；`gen-report` → `#report-result`；`view-calc`、`compare-calc` 同理 |

局部更新用于「结果本身就很大、且用户需要停下来读」的场景（匹配、条件检查、计算、报告），避免整页重绘丢失阅读位置；
写库类动作则统一 `route()`，保证列表/徽标/计数与服务端一致（例如保存注册登记状态后，项目列表里的链条徽标立即更新）。

其它约定：

- **事件委托**：只在 `document` 上注册一次 `click` 与 `submit` 监听，通过 `[data-nav-tab]` 与 `[data-act]` 分发；
  未登记的动作/表单会以红色 toast 明确报错（「未实现的操作：X」「未实现的表单：X」），不静默失败。
- **表单提交统一 `ev.preventDefault()`**，字段用 `new FormData(form)` 一次性收集，再按动作裁剪/转换类型。
- **会话状态**：`state.user` 持久化到 `localStorage('ccer.user')`，其余（`meta`、`hash`、`cache`）仅存内存；
  `state.meta`（事实字段清单与分组顺序 `group_order`）在启动时拉取一次，供项目列表的项目类型下拉与事实录入表单使用；
  `state.cache` 目前只在身份切换时被清空，视图函数每次都重新请求接口，尚未实现请求级缓存。
- **按钮忙碌态**：耗时动作（同步抓取、匹配、条件检查、生成报告）在请求期间 `btn.disabled = true`，
  长动作还会把文案临时改为「执行中…」，避免重复提交。
